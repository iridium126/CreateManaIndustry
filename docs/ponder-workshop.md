# 魔法工坊 Ponder：实现与游戏内验收

## 实现范围

31 段教程，155 段中英文正文；入口仍为 `CMIPonderPlugin`。每段使用独立的 `ponder/workshop/<id>.nbt`，木地台、铜或紫水晶点缀和后排低矮陈设保持一致。机器通过 Java 指令分步搭建，主要说明附带关键帧。

`Workshop` 负责场景内搭建、传动、液量、交互提示和雾效；`AssemblyWorkshop` 负责机械手、注液器、冲压机的传送带流程。物品加工结果使用实际物品和联动数据转移方法。Ponder 的雾元素独立于真实世界雾场及 Veil，每次回放重新创建。

分类包括魔法工坊、雾场入门、魔法自动化，并关联 Create 的动力、流体、机械臂和显示链接分类。可选场景在模组和必要注册项存在时才注册，齿轮链场景同时要求 Trickster 和 Bits ’n’ Bobs。

未修改配方、机器规则、配置平衡或网络协议。

## 已执行验证

- `python scripts/ponder/resources.py --check`：检查场景 ID、故事板方法、NBT 内容、双语标题及正文顺序、可选依赖条件，以及教学示例对应的配方用量和热量条件。
- `gradlew.bat compileJava processResources --offline --console=plain`：Java 编译与资源处理。
- `git diff --check`：补丁空白检查。

这些检查不能证明场景的运行时视觉效果、缺少联动时的类加载行为或装置可实际运行。按用户安排，以下游戏内验收交由用户执行。此前本地开发客户端尝试在 Sodium 加载阶段失败，未进入场景；临时探针与启动配置已移除。

## 每段共同验收

1. 正常播放一遍；确认方块、物品、液面、旋转、机器动作和产物都出现，且说明指向正确位置。
2. 每个关键帧暂停，再前进和后退；最后从头重播两次。检查物品没有重复、雾范围没有继承上一遍、机器没有卡在加工中途。
3. 在雾出现、机械臂移动、唱片插入三个阶段分别退出。确认主世界无新增雾源或遗留声音。
4. 简体中文和英文各检查一次；GUI 缩放 2、3、4 或窗口允许的最大值。检查文字是否覆盖主要连接、机器是否被裁切、半透明雾是否遮住液面。
5. 检查分类索引能找到入口；八种冷凝管和八种镀层板各抽查入口，未完成晶结与施法物品共享对应流程。

唱片场景设置唱片物品状态，不启动世界级唱片音频。雾的显示半径与液量变化按教学节奏编排，不是生产速率基准。配置相关产量与速率以服务器实际配置为准。

## 可选依赖组合

分别在基础依赖、增加 Trickster、增加 Trickster＋Bits ’n’ Bobs、增加 Hexcasting、全部安装的环境中打开 Ponder。基础环境应只有 23 段本模组教程；Trickster 增加 4 段，齿轮链额外增加 1 段，Hexcasting 增加 3 段。其他模组自带教程不计入此数量。缺少可选模组时，不应出现对应入口或类加载异常。

## 实际世界复现

- 燃烧室供热冲压紫水晶、机械臂自动添料、泵供媒质。
- 冷却液沿冷凝管贯通，下方分液池回收灵魂液；装满或移除分液池后停止回收。
- 关闭框架玻璃活板门，在媒质雾中沉积铁板；玫瑰石英镀层另需热源。
- 魔力雾驱动齿轮与磨石，换媒质雾验证反转。
- 绿宝石＋玻璃部署、重复注魔、获得完整晶结；冲压验证开裂。
- Hexcasting 写入图案、注液、冲压，比较前后数据；媒质之瓶取液后再灌注。

记录问题时附上场景 ID、语言、GUI 缩放、模组组合、配置是否修改、具体关键帧以及实际观察，便于复现。

## 后续维护

编辑 Java 场景中的英文及中文字符串，然后运行 `python scripts/ponder/resources.py --write`，再运行 `--check`。不要单独手改生成的 Ponder 翻译或 NBT。脚本不需要第三方 Python 包。配方校验失败时先核实教学步骤是否需要同步更新，不能仅放宽断言。
