# 悦灵风暴美术方案：天穹灵潮

状态：📐 正式美术设计／待实施。原设计日期：2026-10-25。顺序1～2的视觉帧与光影接入已另行实现，详见[通用集成说明](shaderpack-integration.md)；旧风暴／维度视觉已由用户验收，新接入的八包矩阵待客户端验收。本文其余美术类、参数、数量、时间和预算仍为提案，现有行为以源码为准。

设计扩展：[天幕裂口与悦灵维度入口](allay-storm-sky-rift-plan.md)规定主世界风暴成长到16,384后，风眼上方裂口显露悦灵维度天空，并提供高空传送。该阶段的裂口内景取代本方案中的主世界风眼天光；裂口以外继续保留原来的主世界天空与云冠。

## 1. 视觉目标

**让玩家看到一场由无数悦灵组成、正在改写天色的空中天灾。**

远处先看见遮住半边天空的旋转云冠；靠近后辨出六条青蓝星河正围绕中空风眼流动；仰视时，悦灵、细碎星尘与纵向极光分出不同距离。攻击从这片星海中抽离、集结、贯入地面，随后重新汇入主体。悦灵本身仍然轻盈、灵动，群体规模与运动秩序构成压迫感。

风格关键词：青蓝、星海、流线、薄纱、巨构、合唱。造型取自现有六臂台风、悦灵翅膀、钻石剑及三种攻击的几何。六臂是台风结构，不追加无来源的六芒星或 Hex 法阵。远景云冠可以壮阔，近景悦灵保留原版轮廓和动作。

推荐画面明暗面积：约60%低亮深蓝空间，30%青蓝流动层，10%青白高光。比例是构图目标，需要随昼夜和光影包曝光调整。必须保留风眼、旋臂间隙和山体剪影，让“巨大”有参照物。

| 色彩 | 建议 sRGB 色值 | 用途 |
| --- | --- | --- |
| 靛蓝 | `#101B39` | 云冠背光、风暴内部暗部 |
| 深海蓝 | `#164C7A` | 主体阴影、远景大块面 |
| 悦灵青 | `#56D9EF` | 主旋臂、普通光流 |
| 冰白 | `#D8FAFF` | 剑锋、触地、短促攻击高光 |
| 淡紫 | `#A693E8` | 云冠边缘和少量干涉色，总量低于青色 |

上述是美术取色值，着色器中应转换到适用的线性颜色空间；发光强度独立于基础颜色。强光保留青色层次，避免整片饱和成白色。

## 2. 项目现状与必须遵守的边界

| 已核查的现状 | 对方案的约束 |
| --- | --- |
| Minecraft 1.21.1、NeoForge 21.1.236；GPU 粒子以 OpenGL 计算、压紧、剔除和间接绘制为基础 | 沿用现有 GPU 生命周期与能力探测，新增视觉效果独立检查资源能力 |
| 风暴默认增长上限65,536，硬上限131,072；成员是有稳定身份的 MODEL | 百万规模安排为装饰粒子，成员身份、HP、碰撞和攻击资格保持现有规则 |
| 主体是六臂拖曳对数螺旋，带风眼和升降环流；`R = clamp(sqrt(max(1,count)) / 8, 2, 64)` | 用现有旋转／环流积分相位驱动视觉，不能用“当前角速度×总时间”重建相位 |
| 65,536名时 R=32格，131,072名时 R约45.25格，成员外缘可达1.15R | 巨大天空演出需要外延云冠；将外延明确表现为大气／灵光，不能误作实际成员或攻击范围 |
| 共享粒子池默认200万、可配置最高400万；通用粒子64字节，MODEL动画槽最多262,144 | 池容量不等于风暴可独占容量，也不等于可以绘制百万完整悦灵模型 |
| 普通粒子距离淡出默认96格；MODEL与非MODEL走不同光影路径 | 远景云冠与天穹需要独立距离策略；普通 additive 粒子不会因开启 MODEL 光影集成自动进入光影 HDR 流程 |
| 当前普通风暴追踪首次激活距离196格，退出距离260格，并有附近Dome／已锁定Helix的额外覆盖 | 提高天空绘制距离并不会让更远玩家自动获得风暴数据；更远的天灾预览需要轻量视觉订阅 |
| Veil 已用于体积雾、燃料棒辉光；`IrisWorldEffects` 在透明世界之后、光影最终合成之前调度 | 可复用入口设计与资源管理，但现有顺序不能直接解决全部粒子／雾／水透明层关系 |
| 开发目录有 `ComplementaryUnbound_r5.8.1.zip` 与 `photon_v1.3b.zip` | 优先以这两个确切版本为适配对象；文件存在不代表当前启用或已经兼容新效果 |
| 悦灵维度目前使用 `minecraft:overworld` 的 effects | 第一阶段做风暴局部天象，暂不更换整个维度的全天候天空规则 |

现有基准不能作为新效果的帧率承诺。例如2026-10-25报告中65,536风暴成员GPU p95约2.77ms，仅覆盖指定计算区间，不含完整游戏、地形和绘制。默认200万池在已分配动画后，报告中的核心缓冲约396.94MiB，仍不含完整风暴和光影额外资源。需要先测实机剩余预算，再确定默认画质。

现有契约：[攻击行为](allay-storm-ai.md)、[身份与同步](allay-storm-sync.md)、[粒子引擎](particle-engine-dev.md)、[动画与显存测量](benchmarks/allay-animation-2026-10-25.md)。

## 3. 六层视觉构成

### A. 天穹：旋转云冠与天河

视觉：风暴上空出现一个有厚度的倾斜云冠，中心对准实际风眼。六条宽阔暗蓝云臂内嵌细亮的青色脉络，边缘升起断续极光帘。云冠不是一个均匀发亮的圆盘：内缘锐、外缘碎，亮带与大片阴影交替。风眼初期露出原来的天空，形成最强的形状识别点；主世界达到16,384名后按扩展方案撕开天幕，裂口内显露悦灵维度天空。

尺度：成熟风暴的近层云冠半径建议为主体R的2～3倍；更远的天河／极光外延到约4～6R，属于低密度大气投影。随人数从小规模薄环过渡到完整云冠，不能让几十名悦灵也产生百格天灾。外延不是硬边圆柱，靠低频密度、透射与距离渐隐消失。

实现：以风暴中心为世界锚点，使用解析环带／扁椭球包络、螺旋密度场和预烘焙平铺噪声。远天穹用天空方向采样，近云冠用有实际交点与深度截断的体积层。无光影时新增天空层入口；光影时按具体光影包的天空／云流程适配。仅换一张天空盒贴图难以提供视差、遮挡和招式响应，因此天空盒素材只承担远底色与纹理细节。

### B. 主体：六条由悦灵组成的星河

视觉：每条旋臂有“暗色厚体—青色星流—少量冰白亮点”三层。真实悦灵在近处逐只可辨，外围星尘拉出流动方向；风眼壁出现向上的薄光瀑，外缘回落为碎光。光瀑留出缺口，避免把主体封成一个实心灯罩。

实现：主体悦灵继续使用当前模型、动画、持物与阴影。装饰粒子读取同一风暴中心、半径、种子、旋转相位和环流相位，沿相近流场运动，不给成员额外施力。随成员实际离开、死亡和攻击预留降低对应视觉贡献，避免正在抽空的区域被装饰层永久填满。

对真实成员的贴身光尾必须读取已提交的实际位置／速度，受阻或转向后随之变化。远层分析式星尘只表示灵流，不逐只假装跟踪成员。主体周围至少留一层可见的模型轮廓，避免Bloom吞掉翅膀和剑。

### C. 空间填充：百万星尘与稀疏光丝

视觉：细星尘占数量、亮度低；少量较大的六边形光屑给出中景尺度；更少的长光丝串起旋臂与攻击。镜头前0～2格装饰层柔和淡出，保持移动、瞄准与近战视野。不能用百万张大面积半透明片覆盖全屏。

实现：优先使用无状态、由实例ID和共享相位确定的GPU粒子；需要实际惯性或短期历史的部分使用独立紧凑状态。光丝是有截面和长度上限的带状几何，按重要性采样真实成员，绑定稳定身份，不按压紧后的池槽索引持久跟踪。

### D. 空气：青色散射、轮廓光与阴影

视觉：风暴背后的天空略压暗，前方空气有微弱青色散射。几束宽、柔、断续的光从风眼和旋臂缝隙洒下，让山脊、吊桥和建筑出现体积参照。主体仍有暗面；不追求全身自发光。

实现：半分辨率或四分之一分辨率体积积分，先求包络交点，再对有限区间采样。用少量宏观光源／发光体近似整场风暴，不为百万粒子分别创建动态灯。光柱先做遮挡可靠的透射效果，地形青色受光另作为光影包增强项。现有彩光adapter主要解决方块发光，不等于已经支持移动风暴的动态照明。

遮挡：实心建筑截断光雾；透明玻璃、水面和水下视角要单独验证。洞内可以从洞口看到外面被染色的天穹，局部空气与全局色调则按可见天空、深度和视角所在介质衰减。单纯判断玩家是否露天不足以决定每个像素是否应显示天空。

### E. 地面：招式预警与触地花纹

视觉：地面效果集中在确实存在的攻击落点。保留现有Starfall半径4格空心六边形粒子圈；集合为浅青，接近地面逐渐明亮，实际触地出现青白星花。外围装饰余波更暗、更高、更快淡出，不能长得像另一层伤害圈。

实现：首期复用当前预警圈，不额外假定整个4格区域平坦。坡地上的附加纹理若要贴地，需要独立有界地表采样／深度重建；仅有中心地面信息时，优先做离地薄雾和空间光屑。地面光纹不创建方块、不触发区块重建。

### F. 镜头：受控辉光与事件脉冲

视觉：只让星流核心、剑锋和触地点产生柔Bloom。Helix发射或Dome贯心时，局部空气有短促波纹和细小星芒；强度在0.15～0.35秒的装饰脉冲内回落。普通巡航用慢呼吸，攻击高光才有尖峰。

默认无持续镜头抖动、全屏径向模糊、景深或色差。可选演出模式加入很轻的短脉冲，保留独立开关；HUD、准星和手持物不被扭曲。折射只偏移效果区域，并检查偏移前后的场景深度，避免采到墙背后。

## 4. 玩家视角分镜

| 情境 | 画面应呈现什么 | 演出约束 |
| --- | --- | --- |
| 远处初见 | 山体上方出现缓慢旋转的靛蓝云冠，青色天河先勾出六臂，中心仍透天光 | 视觉可见距离由专用天穹层决定；远处看见不等于进入攻击范围 |
| 进入约3R范围 | 前后两层极光发生视差，风眼壁向上流动，近景开始辨认悦灵 | 相机距离只控制视觉权重，不触发新攻击 |
| 主体下方 | 六条星河横贯视野；头顶有层次，地平线与地面保持可读 | 看向地面时主动减少近屏装饰；天空本身可保留强烈压迫感 |
| 集结大招 | 一部分星河被抽出，连续光流汇入真实集合形状，主体局部稍暗 | 明确区分“正在集结”和“已经锁定／攻击” |
| 攻击发动 | 队形高光、局部云冠脉冲、真实路径上的短尾迹同时出现 | 以已有LOCK／实际阶段为准，不自行编造发射时刻 |
| 受阻或中止 | 相关攻击光丝断为暗星尘，已退出成员的尾迹随真实归队方向弯回 | 不补播命中、贯心或触地爆发 |
| 风暴停止 | 真实成员按现有停止规则结束，装饰云冠与余辉建议2～4秒衰减 | 尾效仅本地视觉；换维度和身份失效立即清理，不拖带旧世界数据 |

人数控制的是宏观成熟度：低人数只开近体薄环；达到大招资格的规模后逐渐展开云冠；65,536附近形成完整视觉。建议以存活比例调节密度／亮度，但主体半径仍取当前协议定义，不自行按存活人数改变物理半径。死亡越多，星海越稀，不用保持满亮来掩盖削弱。

## 5. 三种攻击的专属美术

### Starfall：四缕垂天，触地开花

保留每柱64名、四股各16名的现状。集合时四股细光丝围绕柱轴盘绕，光丝之间留空；下降时真实成员前方有细锐光头，后方短尾变长，整体像一束缓慢落下的星瀑。

每名成员**实际触地并进入展开**时，其方向亮出一瓣青白光；64个方向陆续形成空心星花，尺度对应当前最大半径4格、外缘高1格。触地脉冲由实际阶段跃迁导出GPU视觉事件，按柱合并亮度。不能仅按预计到地时间触发整柱爆炸，也不能在未知碰撞数据下伪造触地。

0.5秒短回流开始时立即收掉攻击亮头，星花残光可淡出但不再呈现持剑／伤害姿态。多人最多64柱时，预警圈全量保留，光丝、花瓣余辉和屏幕脉冲按距离与像素贡献限额；不同柱不把全屏曝光不断叠高。

### Helix：双股星锥，破云而出

保留4096名、双臂各2048名、64格轴向长度、尾部32格外包络及0.75圈模板。集合时两股对向光流像一支由星群组成的巨锥；光从后方宽尾向尖端流动，真实编队边缘是主轮廓。

集结期间轮廓以低亮青色展示跟踪方向；收到LOCK才将已冻结轴线画成冰白短脉冲，双股外缘同时出现窄亮带，背景云冠沿相同方向让出一道明暗裂隙。裂隙是天象，不暗示破坏地形。

发射时保留当前轴向12格／秒和真实轨迹，只通过短尾拉长、局部粒子方向性和有限折射增强速度感。不能把它画成瞬时激光。装饰亮边不能填满整个宽锥体形成实心光弹；成员穿出终止面／受阻退出即关闭该成员攻击尾光，再跟随普通归队。

### Dome：穹顶织星，十二重贯心

保留12288名、16～32格上半球集合厚壳、66条三维闭合流线和12组攻击。集合时像在玩家周围逐渐织起的半透明星穹：66条流线以不同明暗和粗细穿插，顶部有小范围亮冠，地面侧保持明显开口。

部分流线受阻暂停时，相应装饰也停在当前相位，低亮悬持；实际退出者的细尾回到主体，不强行补齐一个完美半球。就绪程度可以影响织网完整度，但不能按时间强制“充满”并假装即将发动。Dome集结预算可能较长，设计持续可看的慢流动，而不是长时间高频闪烁。

LOCK以后，十二组在**现有轨迹时序**中显出十二重不同角度的星幕；真实经过近心区的成员各带细亮尾，中心形成小而清晰的冰白核，外围仍能读出方向。概念上的“十二重”不要求修改攻击顺序，不额外添加十二次伤害或人为延迟。

中心高光不能淹没玩家和近身剑。强闪只集中在近心可见像素；低亮余丝保留穿出3格后的空间层次，攻击资格结束当帧去掉危险亮头。整体观感是“无数星流从穹顶交错掠过”，不是一个持续遮挡视线的白球。

## 6. 百万级粒子如何分配

推荐高画质上限为**1,048,576个装饰粒子候选实例**，另加现有真实成员。它是某一帧可参与剔除／绘制的粒子规模，不是每秒生成数量，也不把Bloom像素或体积采样点算成粒子。视锥、遮挡与画质预算会降低实际绘制数，不承诺百万实例同时落在屏幕上。

| 装饰类别 | 高画质候选上限 | 主要职责 | 优先实现 |
| --- | ---: | --- | --- |
| 云冠／远层星尘 | 655,360 | 形成大片星海，提供不同距离的细密颗粒 | 实例ID确定位置的无状态GPU粒子，低像素覆盖 |
| 六臂／风眼细星流 | 262,144 | 让主体的旋转与升降方向清晰 | 分析式流场为主，少量实际成员位置采样 |
| 攻击／消散／短尾节点 | 131,072 | 花瓣、亮点、归队余辉、受击碎光 | 独立紧凑状态、事件限额；尾迹段也占明确预算 |
| 合计 | 1,048,576 | 多效果共享上限，未使用部分可不绘制 | 不为每个攻击槽重复分配一整套上限 |

首选新增独立的风暴装饰后端，接入项目GPU调度和发布机制；共用GPU基础设施，装饰数据不混入风暴成员身份、HP、碰撞和动画列表。无状态部分不保存百万条64字节运动记录；需要状态的最多131,072条建议控制在32字节／条，双bank约8MiB。候选索引、间接命令、尾迹历史、噪声与离屏纹理另列清单。

如果复用现有共享粒子池做早期样机，应先做配额／优先级，保护真实成员、攻击预警和其他玩法效果；缺额只减少装饰。不能看到200万容量就固定占用100万，忽略其他特效的活跃记录。

粒子以小面积加法为主，避开百万透明片排序；加法仍有过绘制和饱和成本。按屏幕投影大小限制片元开销，远层用1～数像素小点，中景少量短线，近景只留稀疏光屑。微粒聚成低频云后，可渐变由密度层承接亮度，避免远距闪烁。

## 7. 渲染落地路线

### 7.1 共用视觉状态

建议新增 `client/allaystorm/visual/`，含以下职责，名称均为提案：

| 模块 | 职责 |
| --- | --- |
| `StormVisualState` | 捕获当前dimension／epoch、中心、R、种子、已积分相位、存活比例、攻击阶段，生成只读视觉帧 |
| `StormVisualGpu` | 生成／剔除装饰、管理事件与短尾历史，提交独立视觉generation |
| `StormSkyRenderer` | 无光影天空方向层和近层云冠 |
| `StormAtmospherePass` | 低分辨率体积积分、深度感知上采样、透射与发光输出 |
| `StormVisualIrisBridge` | 按光影包桥接uniform／sampler、提交阶段和目标buffer，仲裁基础与增强路径 |
| `StormVisualQuality` | 全局装饰额度、片元覆盖预算、计时与带滞回降档 |

GLSL建议放入独立 `shaders/storm_visual/`，Veil程序／pipeline放在现有 `pinwheel/` 资源体系。共享数学只引用必要部分；不把噪声、体积、事件和后处理塞进已有重型 `update.comp`。现有冷编译报告已有分钟级链接案例，新增视觉程序应独立编译、缓存源码、失败保留工作集，首编未完成时先显示现有风暴与预警。

视觉只读**成功发布的一代**。有状态装饰若依赖成员运动提交，须与其提交／回滚对应；无状态云冠可由已提交共享时钟重建。暂停不推进特效，低帧率不补发成堆爆闪；迟入场观察者重建持续效果，历史触地／发射脉冲不补播。身份切换、热重载和停止清理事件去重与尾迹缓存。

现有网络足够驱动主体与攻击的大部分演出。逐成员触地、离队等本地视觉事件优先在GPU生成紧凑、有界事件表，不新增百万粒子的网络同步、CPU逐粒子更新或每帧整池读回。GPU视觉事件不作为战斗判定输入。

**远景数据是独立工作项。** 仅用当前追踪范围时，初次尚未激活的远处玩家看不到天穹，不应声称只改天空就能千格可见。推荐后续加入约512格内、每秒至多一次的低频“远景风暴摘要”：dimension／epoch、时间戳、中心、R、种子、积分相位与视觉强度；停止及时失效。该订阅只绘制低成本云冠轮廓，不分配真实成员、不参加authority选举、不启动攻击和位置同步。进入现有活动范围后与完整视觉渐变衔接，退出范围则退回摘要模式，不能双绘制。512格是待测提案；ALLVR与其他远景地形的遮挡能力还需分别核对。若本批不实施摘要，就把远景验收限制在当前有效追踪内。

### 7.2 无光影模式

建议顺序：

1. 天空阶段绘制远天穹；正常地形与实体保留自身深度。
2. 由真实场景深度截断近层云冠和光雾，输出低分辨率透射／发光纹理。
3. 绘制真实悦灵与装饰；装饰片元按其深度采样适用的雾透射，避免所有星尘浮在雾的前面。
4. 有界折射／触地脉冲合成，再由独立发光遮罩产生小规模Bloom，与世界颜色合成。
5. 进入手持物和HUD前完成世界演出；具体挂钩位置实施时核查，不能仅凭现有mist的阶段推定所有层次正确。

优先形成“没有光影也完整”的基线。主目标可能是LDR，独立浮点发光层只能改善本特效的辉光范围，不能宣称把整个原版管线升级成HDR。色调压缩只处理新增发光，保留世界原有明暗，不强行给全世界重新做一遍ACES。

透明水、玻璃、雾与模型透明翅膀的顺序是专门验收项。第一阶段不承诺任意透明材质下严格体积合成；可采用深度感知柔化与适度减弱，在不具备正确层深时避免强遮盖。

### 7.3 Iris与光影包模式

沿现有 `IrisWorldEffects` 和源码转换机制设计适配，但新增专门的风暴adapter职责，不把天空演出混入“燃料罐方块彩光”接口。基础路径与光影增强路径每帧只能有一个负责同一效果，避免云层或Bloom重复绘制。

**需要显式Java桥接风暴参数。** 新增GLSL的 `uniform cmiStorm...` 或修改 `shaders.properties` 不会自动获得模组的epoch、中心与攻击状态。桥接须覆盖目标program构建、绑定、重载、纹理单元预留和世界切换；先验证最小“参数驱动一条亮带”闭环，再扩充全部天空。

| 目标包 | 本轮本地检查 | 计划改造位置／限制 |
| --- | --- | --- |
| Complementary Unbound（r5.8.1为最初设计样本） | 存在 `lib/atmospherics/sky.glsl`、`lib/atmospherics/clouds/mainClouds.glsl`，`world0/gbuffers_skybasic.fsh`转入共享program | 核查天空颜色、原生云层密度与阴影、合成HDR位置；将风暴密度接入云／天色，世界特效层负责近景和攻击 |
| Photon（v1.3b为最初设计样本） | `world0/gbuffers_skybasic.fsh`仅执行discard；另有 `program/d0_sky_map.fsh`、`d1_clouds.fsh`、`d2_clouds_upscaling.fsh`、`d4a_generate_sky_sh.csh` | 不能只补sky-basic；需分别追踪天空贴图、云层、上采样及SH环境光更新。优先做可见天空／云层，环境照明与反射属后续增强 |
| 其他／未知版本 | 现有mist为不同包族区分scene／translucent／HDR／raw layer；这只是已有雾路径的经验 | 先识别真实buffer语义与提交时点，不按包名直接假定colortex0就是最终HDR。结构不匹配则停用该增强适配并回退可验证的世界效果 |

光影模式尽量让新增发光进入包自己的曝光、Bloom与色调映射，关闭同一部分的Veil重复后处理。风暴亮度要有区域限幅／曝光测试，防止云冠导致整片地面被自动曝光压黑。普通自绘additive粒子需要新增显式合成桥接，不能照搬MODEL已支持的结论。

源码修改优先做加载期内存补丁，以路径、版本及结构特征验证，全组成功再启用。现有接口只给简单文件名；新适配若涉及同名文件，需要扩展到完整路径识别。仅换包名不应误命中。保留原始zip；如后续选择独立定制光影包，则另存新包并注明基底版本。

不占用“看似闲置”的colortex而不检查包的全部program。新增离屏颜色／发光／折射输入使用不同读写纹理或明确合法的拷贝／乒乓流程，避免直接采样当前写入附件。光影管线允许多个合成阶段，但每个包的数据语义需要分别核实，见[Iris合成阶段说明](https://github.com/IrisShaders/ShaderDoc/blob/master/passes/composite.md)、[自定义uniform说明](https://shaders.properties/current/reference/shadersproperties/custom_uniforms/)及[OpenGL帧缓冲纹理反馈约束](https://wikis.khronos.org/opengl/Framebuffer_Objects)。这些参考说明一般机制，不代表本方案已经完成兼容。

### 7.4 深度、时序与光照

统一使用相机相对坐标及适用的逆投影重建；普通／Iris的深度、天空值和抖动矩阵分别核对，不把一种路径的深度公式硬套到另一种。宽屏、FOV、第三人称、远坐标和ALLVR垂直坐标映射均纳入检查。

基础云层优先稳定抖动加深度感知上采样；高档可加有限历史重投影。场景深度、身份、投影、分辨率或相机跳变时拒绝历史，风暴密度使用自身流动修正，避免快速转头时拖出一整片青色残影。光影已做TAA的路径先不另叠第二套全屏TAA。

风暴对地面的青色照明分三档：基础为深度截断的空气散射／局部屏幕染色；已适配包可做少量宏观发光体对表面法线的近似受光；真正进入包的体素光传播、天空环境光／反射预计算属于单独任务。屏幕染色不得称为真实动态照明，屏幕空间水面倒影也不得承诺能反射屏幕外风暴。

## 8. 画质与性能预算

以下是建议调优目标，全部待实机验证。新增视觉GPU预算不含现有风暴模拟、真实成员绘制、地形或光影包本身；1080p为预算参考，不承诺具体GPU型号达到目标。

| 档位 | 装饰候选上限 | 云冠／体积 | 新增视觉GPU p95目标 | 新增资源目标 |
| --- | ---: | --- | ---: | ---: |
| 精简 | 65,536 | 天穹薄层＋少量带状光，无体积历史 | ≤1.5ms | ≤16MiB |
| 标准，建议首期默认 | 262,144 | 四分之一宽高，12～16次有界采样 | ≤3ms | ≤32MiB |
| 华丽 | 1,048,576 | 二分之一宽高，16～24次有界采样，有限历史 | ≤5ms | ≤64MiB |
| 演出 | 最高2,097,152，后置实验项 | 更长尾迹／更细云层，非默认 | 单独报告 | 单独报告 |

资源目标包括新增状态、索引、历史、噪声和特效离屏纹理，不包含项目现有资源。提高分辨率时按像素数评估；无法满足预算就降低中间纹理尺寸／档位，不能把64MiB目标自动外推到4K。内部采样数是起点，应先用预烘焙噪声和解析密度降低成本。

降档顺序：减少近屏大光屑与宽光晕 → 减少装饰尾迹 → 降低体积分辨率／采样 → 降低细星尘密度。保留六臂轮廓、风眼、真实攻击成员和现有预警圈。让百万级密度成为华丽档的明确特色，标准档仍然能读到同一套美术。

节流采用异步GPU时间查询和连续窗口，带降档／恢复滞回，避免粒子数量逐帧跳动。分别记录生成、剔除、粒子绘制、体积、合成的时间，也记录实际可见实例数和片元覆盖估计；只看粒子数量无法定位过绘制。现有 `particles.frameBudgetMs=15` 是旧共享系统配置，不直接当作新增效果预算。

百万实例不进行成员分离、地形碰撞、局部寻路、动画或战斗反馈。真实成员远景LOD可在后续研究，属于绘制层优化；不得删除其模拟、死亡或攻击状态。近身交互、持剑及预警优先保持真实模型辨识，主体聚合显示需要额外评估点击一致性。

## 10. 实施批次与可检查的结果

下表保留美术功能分组；加入高空裂口后，实际执行以[统一开发顺序](allay-storm-visual-development-order.md)为准：提前高空摘要、共用天空与Iris接入探针，先完成裂口／传送样机，再推进三招和百万扩量。

| 批次 | 工作 | 完成判据 |
| --- | --- | --- |
| P0：构图样机 | 固定主体下／山脊远望／Dome内部三机位；无光影先做六臂云冠、风眼和少量星尘 | 三个机位均能读出规模、纵深和地面，不靠白屏发光；只用低密度也成立 |
| P1：招式与数据闭环 | 三招完整阶段着色、实际位置尾迹、触地GPU事件、停止／恢复／中止 | 美术随真实阶段运行，受阻不出现假命中；观察者进入不补播爆发 |
| P2：密度与体积 | 独立视觉后端、百万候选、低分辨率体积、Bloom与自适应预算 | 获得可复现的计时／显存表；从精简到华丽保持同一轮廓 |
| P2a：远景订阅，推荐扩展 | 低频云冠摘要、约512格预览、与完整风暴渐变切换 | 远处只显示云冠，不启动成员模拟和authority；停止／换维度无残影，实测额外带宽与遮挡 |
| P3：Complementary适配 | 指定r5.8.1的天空／云与发光合成；动态参数桥接 | 已开启／关闭云层、Bloom、自动曝光的组合均可解释；无重复演出 |
| P4：Photon适配 | 指定v1.3b的sky-map／云层／上采样，后续评估环境光／反射 | 不是只改sky-basic；天空和世界特效色彩一致，无历史污染 |
| P5：整合验收 | 真实客户端场景、玩家与多招并发、可访问性设置 | 提供对比截图／短录屏、整帧p50／p95／p99及兼容状态；结论标明机器与配置 |

宏观构图验收图建议为“山脊与建筑形成暗色前景，巨大的六臂青蓝星海横跨天空”；16,384名前保留风眼天光，达到阈值后展示高空异界裂口。低密度构图成立后再以百万粒子补足尺度和细节；光影先验证最小接入，完整增强在公共效果稳定后完成。

## 11. 后续验证矩阵

本轮未运行构建、GPU回归或游戏测试，因为没有运行实现变更。实施后至少覆盖：

- **人数与并发**：小风暴、16,384、65,536、131,072；64星柱、4大招槽及其他项目特效共存。确认装饰额度全局共享，未知／中止／退出不出现假攻击。
- **视角与场景**：主体下、侧面、远眺、风眼内；昼夜、雨天、坡地、建筑遮挡、水面／水下、玻璃、ALLVR高低坐标；FOV与第三人称、近战看剑、快速转头和传送。
- **生命周期**：暂停恢复、迟入场、重复快照、死亡、归队、STOP后同tick重建、换维度、F3+T、光影开关、编译失败保留旧效果。
- **渲染路径**：无Iris、Iris无光影及八款验证样本；有无iris-veil-compat；无法确认的能力明确降级。无重复Bloom、无阴影pass内误绘制天穹、无sampler／FBO状态泄漏。
- **性能与资源**：相同存档／种子／机位／分辨率，关闭自适应采固定档基线，再单测自适应；预热后三轮，记录完整游戏帧与各GPU区间、显存清单、上传字节与读回等待，区别冷编译和稳态。1080p与1440p分别测，4K单独决定支持档位。
- **可读性**：星花4格预警和真实危险亮头清楚；准星周围不被近屏粒子遮住；降低闪光／关闭折射仍保留所有战斗信息。视觉尾效与伤害关闭严格区分。

## 12. 推荐决策

采用“**现有真实悦灵主体＋独立百万装饰粒子＋世界锚定云冠／极光＋局部体积与受控辉光**”的组合。华丽来自六臂结构、巨大的暗亮块面、前后分层和三招各自的运动语言；数量用于让细节在靠近后仍成立。

首期标准档默认，华丽档提供百万级实例上限。完整的无光影版本先成立，Complementary与Photon作为明确版本的增强路径。暂不改变人数硬上限、攻击轨迹、伤害规则、维度天空定义或世界地形。真正动态地形受光、环境反射与更高粒子规模在测得收益和资源余量后单独推进。
