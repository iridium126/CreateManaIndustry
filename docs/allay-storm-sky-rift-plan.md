# 悦灵风暴：天幕裂口与悦灵维度入口设计

状态：📐 裂口与入口设计／待实施。原设计日期：2026-10-25。前置视觉帧与光影探针已另行实现，详见[通用集成说明](shaderpack-integration.md)，本轮没有实施正式天空、裂口或传送。本文扩展[“天穹灵潮”美术方案](allay-storm-art-direction-plan.md)；涉及人数阈值、天空裂口与传送的设计以本文为准，现有行为仍以源码为准。

## 1. 确定的方向

**主世界的悦灵风暴成长到16,384名后，撕开头顶天幕，裂口内显露悦灵维度的天空；玩家飞到风暴正上方的高空区域，自动进入悦灵维度。**

主世界环境保留昼夜、天气、地形和正常天空。异界天空只在裂口范围内出现。悦灵维度未来采用独立天空效果时，维度本体与裂口内景共用同一天空定义，避免两者成为外观不一致的两套素材。

## 2. 服务端规则与边界

| 项目 | 本方案定义 |
| --- | --- |
| 活动维度 | 只在 `minecraft:overworld` 的活动风暴上启用该入口；不把本规则自动推广到其他维度 |
| 开启阈值 | `AllayStormData.count >= 16384`；表示已生成总成员数，包含死亡成员，符合“成长到”语义 |
| 稳定性 | 同一风暴epoch达到阈值后，不因死亡或攻击临时抽离而反复开关；风暴停止／替换／世界卸载使该入口失效 |
| 目标维度 | `AllvrDimensions.ALLAY_LEVEL`，即 `createmanaindustry:allay_dimension` |
| 水平范围 | 以服务端连续中心 `chaseX/chaseZ` 为圆心，`dx² + dz² < 4096`；64格是中心距离，不是距最外层成员的距离 |
| 高度基准 | 来源主世界运行时的 `getMaxBuildHeight()`，记为H，采用建筑范围的上边界，不采用最高合法方块Y |
| 高度条件 | 玩家脚点 `player.getY() > H + 64`，保持严格大于；不使用眼睛、头顶或包围盒上缘 |
| 标准主世界 | `minY=-64`、高度384，所以H=320，入口条件为脚点 **Y>384**；Y=384不触发，最高合法方块Y=319不作为公式基准 |
| 判断来源 | 服务端世界／风暴／玩家状态，按游戏tick检查；不依赖客户端GPU反馈、看向裂口或客户端请求传送 |
| 其他行为 | 不增加按键、停留读条、向上速度、视线命中、额外几何遮罩命中或“必须从下方穿越”的要求 |

核心条件的设计表达式：

```text
sourceDimension == minecraft:overworld
AND storm.active
AND storm.count >= 16384
AND player.isAlive
AND (player.x - serverStormCenter.x)^2
  + (player.z - serverStormCenter.z)^2 < 64^2
AND player.feetY > sourceLevel.maxBuildHeight + 64
```

目标维度、合法落点和标准跨维度流程必须可用才能完成传送。它们是执行准备条件，不是新增的玩法门槛。生存、创造、旁观的已连接活玩家均按此几何规则处理；不擅自给某种模式另加豁免。达到条件时已身处高空、从侧面飞入、下降进入或风暴移到玩家下方，也应触发。

阈值依据服务端整数count，不用客户端插值人数提前开启。直接以16,384或更多成员创建风暴，同样具备入口；存档恢复时仍具备入口。主世界建筑高度被数据包改变时使用实际H，不把384写死。Helix／Dome的现有就绪、人数及调度规则不变。

## 3. 裂口的空间形态与美术

### 3.1 世界锚定的天幕

视觉上是“天空被撕开”，实现上建议使用**位于世界高空的有限裂口面／解析曲面**，而不是把裂纹画在跟随相机的固定cubemap像素上。

- 中心XZ始终对应同一服务端风暴中心流；平滑显示可沿用中心快照插值，但传送取服务端当前中心。
- 入口基面位于Y=H+64。玩家从地面仰望、在风暴内部和高空侧看时，裂口具有一致的方位、大小和视差。
- 成熟视觉外包络建议约192×160格的横向破口，边缘分叉、略倾斜起伏；是美术起点，待实机调整。
- 破口内有效天空区域至少覆盖圆心半径64格的投影圆，边缘再向外撕裂。美术边界只能在64格之外变化，避免玩家看到脚下封闭天空却触发传送。
- 固定的64格传送圆柱与更大的破口外形不完全重合；接近入口时，用内层青色薄环／空间微粒明确引导到可穿越的中心区域。外围撕裂边不伪装成另一圈传送边界。

裂口没有实体碰撞，不创建高空方块，不使建筑上限变高。192×160格是可见破口包络，不是新增的传送范围。

### 3.2 从星海到异界的阶段变化

人数不足16,384时，继续呈现六臂星海、云冠和中空风眼；风眼中是主世界天光。达到阈值后，风眼上方出现细长冰白裂纹，向两侧抽开，露出另一个世界的天空。

撕裂动势以“拉扯”与“翻卷”为主：边缘分出两层亮线，中间是低亮深蓝断面；细碎青色光屑沿裂口边缘滑动，偶尔逸散回风暴。六臂星流的上升分支将视线引向裂口，但不把真实成员的运动路线改成飞入入口。

开启演出建议2～4秒，只控制边缘扩展、亮度和碎屑。**不能把演出时长变成额外的传送等待时间。** 满足条件的高空玩家仍立即进入标准传送流程；首帧即可显露中心入口，外侧分叉继续演出。迟入场与重进世界直接看到当前稳定状态，不反复播放初次撕裂。

当未来悦灵维度天空拥有特殊天体、星云、极光或不同昼夜时，裂口内直接呈现该天空在目标上下文下的样子；主世界太阳／月亮不能再透过裂口内部重复出现。裂口外侧仍遵守主世界天气；位于裂口前方的主世界云和实心山体仍可遮挡它。

风暴停止后，服务端入口立即失效，视觉边缘可在约1秒内收拢消散。入口指示先关闭，余光不再显示为可进入的稳定孔洞。换维度立即清理主世界裂口，不把它带入悦灵维度。

## 4. 裂口内景与未来天空的共用接口

### 4.1 当前能力

当前悦灵维度类型JSON的 `effects` 是 `minecraft:overworld`，尚无本项目独立的悦灵天空资源／渲染器。因此“裂口中看见显著不同的悦灵天空”不是现成能力，需要新增共享天空层。不能把“已存在悦灵维度”当作已经有可直接抓取的异界天空画面。

本轮不提前锁定未来悦灵天空的最终美术。实施时可使用可替换的测试天空验证遮罩和方向，但正式效果应与悦灵维度本体一并接入同一profile，不能只在裂口里画漂亮星云，实际进入后仍是另一套天色。

### 4.2 共享天空描述，而非再造一个客户端世界

建议新增以下职责，名称均为提案：

| 接口／数据 | 职责 |
| --- | --- |
| `AllaySkyProfile` | 天空资源版本、底色、天体／星云参数、可选远云与视觉种子 |
| `AllaySkyContext` | 目标天空时钟、方向基、天气／环境参数及需要时的目标观察点高度 |
| `AllaySkyProvider` | 从方向与context求天空辐射；被悦灵维度本体与裂口内景共同消费 |
| `StormRiftVisualState` | 来源dimension／epoch、中心、高度、开放状态／开始时间、目标sky profile／context |
| `StormRiftRenderer` | 裂口有限面交点、边缘形状、深度遮挡、内景采样与合成 |

主世界客户端不必构造第二个 `ClientLevel`，不订阅悦灵维度区块，也不渲染远端实体／地形。首期窗口只展示天空：星云、天体和方向层远云均由profile决定。若未来要通过裂口看到世界树、浮岛和其他玩家，应视为真正的跨维度场景渲染项目，另行设计。

天空内景由有限裂口处的视线变换到目标天空方向后采样，使用稳定的方向基；不能把一张未经方向转换的截图贴在面上。目标天空时间与环境取悦灵维度上下文，不直接复用当前主世界的 `Minecraft.level`、太阳角度和天气。

在客户端尚未进入目标维度时，服务端向视觉订阅者发送最小天空上下文；首次订阅提供时间锚点，之后低频更新天气／profile等变化。视觉种子采用独立美术种子或派生标识，不为天空预览下发完整世界生成seed。未来天空若有特殊空间依赖，再显式扩展context。

### 4.3 可选天空缓存

若未来天空计算复杂，可先将provider烘焙为低频更新的HDR cubemap。256²、RGBA16F、6面约3MiB，含完整mip约4MiB，双缓冲约8MiB；这是纹理理论载荷，不含驱动及额外缓存。简单天空可直接按可见裂口像素计算，无需cubemap。

cubemap只缓存天空，不缓存玩家相机、裂口边缘或地形遮挡。更新过程先完成一致的目标context，再原子发布，避免6面来自不同天象时刻。换profile／维度／分辨率时按资源生命周期重建。

悦灵维度本体未来可通过NeoForge `RegisterDimensionSpecialEffectsEvent`注册专属effects并接入该provider；主世界裂口直接消费provider。仅修改维度JSON的effects id不会自动让所有Iris光影包使用自定义天空，仍需对应光影路径。

## 5. 无光影与Iris渲染路线

### 5.1 基础路径

无光影模式在天空／世界合成适当阶段计算视线与裂口面的交点，求稳定的形状遮罩：

```text
天空输出 = 主世界天空 × (1 - 裂口遮罩)
         + 悦灵天空 × 裂口遮罩
         + 有界的裂口边缘发光
```

该式仅表达天空层替换，不能直接覆盖整个最终画面。实心世界深度截断裂口；太阳、月亮和星星需纳入天空替换顺序，避免后绘制的原版天体穿出异界。前景云层／透明物体与裂口的先后应按实际距离及管线处理，不能用“全部云层一律擦除”的遮罩。

裂口边缘单独提供发光遮罩，以柔Bloom突出破口，不靠全屏曝光闪白。云冠、极光、百万星尘继续沿原美术方案工作，裂口只新增一个宏观焦点，不要求再分配一套百万粒子。贴边碎屑从风暴装饰总额度中取用。

### 5.2 指定光影包

- **Complementary Unbound（r5.8.1为最初设计样本）**：沿前轮核查的 `lib/atmospherics/sky.glsl`、云流程及对应program追踪天空合成点。把异界遮罩接入实际天空辐射／天体输出，边缘发光进入可验证的HDR阶段；前方主世界云保留。
- **Photon（v1.3b为最初设计样本）**：`gbuffers_skybasic`直接discard，不能仅修改该入口。纯方向天空缓存与有限位置裂口必须分层：AllaySkyProvider可产出目标天空，裂口面遮罩在具备当前主相机视线／位置的屏幕天空合成阶段计算，不能把相机相关的裂口图形永久写进环境sky-map／SH缓存。
- **未知包**：优先保留可验证的深度感知裂口世界效果；不能因全局天空替换失败就禁用服务端传送。渲染状态明确标记为增强不可用，最少仍提供可辨识的入口边缘与中心引导。

首期主世界的环境照明、地形颜色和反射不因裂口自动变成悦灵维度的环境；裂口展示的是可见窗口。若后续希望它照亮云、地面或出现在屏幕外水面反射中，需要单独修改光照／反射采样，不能由屏幕上出现一块异界天空推定已经支持。

官方机制参考：[Iris天空gbuffers职责](https://shaders.properties/current/reference/programs/gbuffers/)、[Iris程序分类](https://shaders.properties/current/reference/programs/overview/)。实际包仍以本地指定版本源码和后续实机输出为准。

## 6. 高空视觉订阅与服务端入口必须解耦

当前风暴以三维距离控制客户端完整模拟：普通首次激活196格、退出260格。中心默认Y=128；当玩家脚点接近Y=384，竖直距离已约256格，水平距离较大时会在穿越前退出260格范围。高空初次进入者也不会自动获得196格内的ACTIVATE。

所以不能把“客户端风暴active”作为裂口显示或传送资格。建议：

1. 保留现有真实成员模拟／authority追踪；不为高空裂口无限扩大整场风暴的三维模拟范围。
2. 将前轮提议的远景摘要扩展为裂口视觉订阅：按XZ水平范围订阅，建议进入512格、离开576格，且不因超过主世界建筑高度而自动退订。这些是视觉距离提案，不改变64格入口规则。
3. 摘要携带来源dimension／epoch、连续中心／时间戳、入口面高度、count阈值状态／开放时间、目标天空上下文。中心低频更新并平滑显示，传送始终使用服务端未延迟坐标。
4. 同时处于完整模拟与摘要范围时合并到一份视觉状态，只绘制一次裂口；失去完整模拟后由摘要维持天空。开关／STOP／替换事件及时发送，不等待下一次普通人数快照。
5. 服务端入口检查遍历本维度玩家和当前风暴，不依赖现有rt.tracks的active或客户端authority。即使玩家从未运行过成员GPU模拟，也可进入入口。

客户端预测的淡入、动画和内圈提示不参与服务端资格。边界采用double坐标计算，不用客户端落后一秒的平滑中心判传送；显示边缘柔化可减轻约2格中心滞后，但不能暗改64格阈值。

## 7. 传送事务、落点与到达演出

### 7.1 服务端执行

建议新增独立 `StormRiftTransferService`，由主世界风暴的服务端tick在增长／中心更新后调用。只管理玩家进入悦灵维度，复用项目所用Minecraft 1.21.1的标准跨维度流程，不绕开现有模组事件、同步和 `PartitionDimensionTeleportMixin`。

项目本地源码已有 `DimensionTransition`及 `ServerPlayer.changeDimension`，后续按该版本实际调用链接入。官方版本说明也确认1.21跨维度使用DimensionTransition，见[NeoForge 1.21迁移说明](https://docs.neoforged.net/primer/docs/1.21/)。不能照搬其他版本传送签名。

每位玩家只保留一个在途请求，绑定玩家UUID、来源dimension与风暴epoch。先验证目标，再调用标准传送；成功才提交到达／来源记录。被事件取消、目标不可用或返回失败时，不能将玩家标记为已成功进入，也不能每tick堆积并行请求。失败重试限频只针对执行失败，不是正常传送的玩法冷却。

目标加载异步／分预算推进，不能在渲染或服务端tick同步扫描大量地形。准备结束时重新核查玩家仍在来源主世界、仍满足条件且风暴身份有效；离开范围、风暴STOP或断线即撤销。未准备好就保持玩家在原维度，不先发成功动画后再撤销位置。

悦灵维度JSON受 `hexcasting` 加载条件控制，因此必须通过服务端实际维度查找确认存在，不能仅因ResourceKey常量存在就认为目的地可达。缺失时入口显示不稳定／不可用提示，限频记录原因，不踢出玩家或落到其他维度。

### 7.2 推荐落点

用户尚未指定具体到达坐标，首期建议固定进入**悦灵原点中央平台的安全到达区**，避免主世界XZ原样映射到任意浮岛、空洞或高Y Cube。

当前中央平台半径90格、地表Y=95。建议在原点水平半径48～72格的候选环中，寻找真实已加载、脚下有有效支撑、无危险流体、玩家完整身体可容纳的点，通常脚点约Y=96。这个高度只是生成模型的候选，不直接相信它永远为空；世界树、玩家建筑和存档差异以实际方块／碰撞为准。

- 候选搜索有界，并为多人分配不同落点，建议间隔至少2格；不每次扫描整个维度。
- 目标位于中央原版高度带 `[-128,384)`，优先使用已有原版区块加载／碰撞；暂不把超高Y Cube到达同步当作本入口的前置要求。
- 达到16,384后可按预算预热小范围到达区，完成后释放临时预热票据；有真实在途请求时才续期，不永久强加载整片维度。
- 没有已验证落点就保留在主世界并重试，不为传送自动清理世界树、覆盖玩家建筑或生成新平台。
- 成功到达后清零速度和fallDistance，保留玩家朝向，避免把高空下降／鞘翅高速运动带成到达伤害；不自动授予创造飞行。
- 本规则传送玩家本人；乘坐时通过标准流程处理下车。首期不自动跨维度搬运载具、乘客组或Create运动结构。

这是一种推荐默认落点策略，可在后续独立配置成其他指定入口。其验证工作不能用“目标维度天空可渲染”替代。

### 7.3 到达演出与返回范围

靠近入口内圈时，边缘光沿视野外围收束，异界天空在裂口内保持稳定方向。服务端确认传送后，短暂青白过渡覆盖正常世界切换；目的地天空就绪后退去遮罩。加载期间保留普通加载界面／可恢复的过渡，不以动画掩盖尚未完成的传送。

首次进入后从原点平台仰望，看到与刚才裂口同一profile的完整天空。首期不承诺无缝跨维度相机连续、互见玩家或远端地形预览。

该规则只定义“主世界→悦灵维度”。不增加自动反向入口、返回钥匙或死亡回程逻辑；可记录来源维度、位置和风暴epoch作为未来返回功能的数据，但记录不等于已经有返回机制。

## 8. 生命周期、保存与开关

可由 `count>=16384`推导稳定开放资格，避免维护与count冲突的独立布尔值。若需跨重启保留撕裂动画相位，新增服务端 `riftOpenedAtGameTime` 并持久化；客户端仅接收有界视觉年龄，避免大float世界时钟精度问题。旧存档已达阈值且没有该字段时按稳定开放态恢复，不补演世界首次撕裂。

风暴epoch变化清理旧视觉摘要、传送请求、事件去重及缓存。玩家离开主世界时清理来源裂口状态；其进入悦灵维度不应使其他主世界玩家的裂口关闭。世界卸载／服务器停止释放目标预热票据；在途事务不以半完成状态跨存档重放。

画质开关可以降低边缘碎屑、Bloom、折射和天空缓存分辨率；关闭粒子或光影不能改变传送判定。保持最小入口提示，让不支持增强天空的客户端仍能找到入口。服务端功能开关如以后提供，必须同时控制入口有效性和同步，不制造“看起来开放、实际永不传送”的长期状态。

## 9. 分批实施与验收

下表是入口功能分组；与风暴美术合并开发时，以[统一开发顺序](allay-storm-visual-development-order.md)为准。规则／目标加载可先验证；共用天空、摘要与可见裂口具备后再对玩家默认开放传送，Iris先做小规模接入探针。

| 批次 | 内容 | 完成判据 |
| --- | --- | --- |
| R0：规则闭环 | 服务端阈值／水平距离／高度、实际维度查找、中央到达区与标准传送 | 无光影与粒子关闭时，16384／64／384边界全部正确，失败不会误提交成功 |
| R1：高空视觉持续性 | 独立摘要订阅、有限裂口面、可替换测试天空、STOP／迟入场恢复 | 从地面飞到Y>384不丢失裂口；未收到完整ACTIVATE的高空玩家仍可显示与传送 |
| R2：共享正式天空 | AllaySkyProvider同时接入目标维度本体和裂口 | profile、方向与目标天象一致；未来换天空素材不重写入口规则 |
| R3：美术整合 | 六臂云冠、撕裂边缘、星屑、到达过渡和可读内圈 | 大气层次清楚，地形／前景云遮挡正确，不靠全屏白闪遮住所有细节 |
| R4：光影适配 | 八款验证样本的实际天空／合成阶段、未确认能力降级 | 无主世界天体穿帮、重复Bloom或环境sky-map污染，功能与渲染支持程度解耦 |

关键测试场景：

- **阈值与严格边界**：count=16,383／16,384；水平距离63.999／64／64.001；Y=383.999／384／384.001；改变主世界高度后重测实际H。
- **成员与存档**：死亡使存活数低于16,384、攻击成员离队、直接大人数创建、旧存档恢复、同tick STOP并重建。资格使用生成count与正确epoch。
- **进入方式**：正常升空、鞘翅、创造、旁观、侧入、下降、命令先到高空、风暴移动到玩家下方。没有额外视线／速度／按键门槛。
- **追踪边界**：玩家首次在Y>384附近上线、三维196／260格追踪退出、XZ摘要进入／离开、多观察者且唯一authority进入目标维度。其他玩家的风暴和入口继续正常运行。
- **目标准备**：维度缺失、区块加载慢、候选落点被建满／有流体、多人同时到达、事件取消、骑乘、准备期间断线／离开范围／风暴结束。
- **天空一致性**：两维度昼夜不同、天气不同、未来profile升级、从下方／侧面观察、建筑／云层遮挡、FOV／第三人称／高分辨率、重载／光影切换和编译失败。
- **资源与性能**：与前轮标准／华丽档一起测新增裂口GPU区间、天空缓存显存、摘要流量和服务端到达准备耗时；不将远端全世界渲染计入首期方案。

本轮仅做设计与文档检查，不运行构建／GPU／游戏测试。后续实现须提供上述实际结果，不把方案中的机制和预算描述成已完成能力。
