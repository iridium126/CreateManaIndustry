# 固定 tick 粒子引擎

状态：单次计算计划的基础修复候选，完整迁移尚未完成；见[实现状态与剩余工作](rt-single-step-status.md)。默认 `gl`；`auto` 当前也选择 GL。保留悦灵、携物、动画、Iris 和独立模型阴影接口。安装见 [安装与回退](particle-engine-install.md)，证据范围见 [性能验证](particle-engine-performance.md)。

## 调度与状态

`ParticleSimulationClock` 使用世界游戏 tick，步长 0.05 秒。显示帧最多提交两个有序补偿步，剩余 tick 保留；暂停不推进。首次进入世界从当前 tick 开始，不重放进入前的历史。生命周期和攻击事件在模拟路径处理，接触按攻击/目标去重；迟到读回按其原采样时间核对攻击窗口。

`ClientGpuScene` 将输入、模拟、接触审核、发布和显示整理分开。普通粒子及外部生产者仍通过通用池导入、压缩和发布；这些工作只在模拟 tick 执行。Storm 另有两个按稳定成员索引寻址的运动状态数组，通用池重排不会改变运动身份；当前实现以通用池作为玩法适配边界，每 tick 将接触及地形修正后的精确状态写回稳定数组。容量固定为 131,072，未按显示 FPS 重建模拟。

玩法状态与显示状态分开。三个 `ModelRenderPublication` 槽冻结发射器、姿态、动画和携物输入，输出插值模型池和绘制索引。模拟压缩生成当前槽位到前态的映射，显示不再重建身份哈希。出生、死亡切换及显式传送使用当前状态，连续字段由类型声明；尺寸、亮度、帧和攻击标记不参与身份匹配。显示池不会写回模拟池。主绘制与阴影使用同一显示池、代次、动画和插值时钟，但分别生成相机和光源可见列表。显示槽只在退休 fence 完成后重用；无空槽使用当前完整 GL 发布，不等待。

模型动画和 Dome 姿态分别绑定纹理单元 15、14；合并 MODEL 预留 9–15，物流独立绘制仍使用自己的 10–12。最终模型材质、携物几何与光影包绘制继续走光栅接口。

## 空间查询

默认每成员两条探针，预测范围 0.10 秒；前向一条、随 tick 轮转的 25° 锥面一条。`cmi.particle.wideBudget=true` 使用四探针、64 项访问、最近 8 项；默认局部预算为 32/4。修正一次，位移不超过 0.03 格，并复核当前地形和速度限制。预算耗尽、覆盖未知和残留重叠分别标记，不增加就绪人数、不缩小集结分母、不证明无接触。

已进入有效 Dome 编队路径的成员按时钟求值，不叠加普通避让。Dome 保留生产 contact/control/apply/audit、地形和就绪审核，查询故障不会进入全池参考枚举。跨 tick 攻击接触检查整个运动段，并裁剪到原攻击窗口；身份、存活状态、攻击 ID、传送包络和发送时期限再次核验。

GL 使用 GPU Morton 排序、Karras LBVH 和有界栈遍历，输出最近距离和方向。每射线最多 256 节点，预算耗尽返回未知，不转全池枚举。

RT 使用静态闭合三角盒 GAS 与每次提交重新构建的 IAS，实例整理限于成员范围和实际地形数量；opaque、内置三角形求交、运动射线背面剔除、无 any-hit。光追仅生成运动偏好，当前步 GL 局部修正和玩法审核独立运行。仍须测量 IAS、普通 CUDA 计算、同步和整理的完整成本。

三个原生快照槽与模拟和显示槽完全独立，按提交顺序完成、消费，再等待 GL 栅栏退休。迟到、错误和已销毁身份的结果也消费一次；仅当前身份的有效输出可发布。环满停止快照导出，RT 错误停止新提交并报告状态，不自动执行 GL LBVH 查询。只有明确切换后端后才使用 GL。连续切换时等待旧资源退休。地形缓存修订不再改变整场景身份。

地形按区块修订维护，每 tick 增量整理一节；碰撞和可靠遮挡分别标记。未知或非完整遮挡体不作为可靠遮挡。中心射线仅选择可靠 opaque 遮挡物，之后证明整个包围体均处于同一个凸遮挡体的阴影体中；覆盖未知保持可见，运动代理不能作遮挡物。此查询尚未接入在线组剔除。此模块未进入 `auto`。

## 原生边界与维护

ABI 12 候选和能力回执共同校验：128 字节帧头、64 字节输入和输出、两种探针预算、0.10 秒预测范围、预编译模块。普通 Gradle 构建不调用 CUDA、OptiX 或 NVRTC。可选模块为 `CmiParticleRt.dll`、`spatial.fatbin`、`spatial.optixir`，客户端不编译设备源码、不分发 SDK 头文件。

NVENC/NVDEC 不接入在线模拟。历史原型与 R6–R9、分页、融合力、COPY 和 Tensor 路线保存在冻结归档中，不再参与当前构建。活动 Hex、物流、光影和地形验证保留；统一 GPU 入口按需编译测试夹具依赖，兼容 Gradle 任务仅作为业务内部入口。

## 其他生产者与材质

`ParticleTypes` 注册类型与 shader hook；`EmitterSpec` 描述发射器，`ParticleAppendTarget` 是外部生产者导入边界。发射请求、脏 header 和 kill 输入在成功提交后消费，失败会重试。生产粒子记录仍为四个 vec4，不改变网络协议。Hexcasting、持续图案、Shared Fate 和物流保留各自业务实现，不依赖原生 RT。

材质继续分为 OPAQUE、ALPHA、ADDITIVE、MODEL、HEX_PATTERN 和 PACKAGE。OPAQUE 写深度，ALPHA 与 MODEL 使用现有深度分区排序，ADDITIVE 最后绘制；Hex 图案和物流使用各自的几何与发布接口。模型人口索引独立于相机剔除，离屏成员继续参与玩法、阴影和反馈。不得用主相机可见性替代碰撞或攻击候选集合。

资源重载由 `ParticlePrograms` 原子发布完整 GL 程序集；未发布的源码不会混入活动程序。`GpuFrameCoordinator` 管理模拟发布代次，GL 状态边界恢复外部程序、SSBO、图像及纹理绑定。玩法检查使用当前提交池，模型绘制使用 `particleDrawBufferId()`、冻结 header 和动画输入。
