# Allay Storm：同步与资源契约

当前核心协议 **17**、Dome模板 **v4**、Helix模板 **v1**。两端同步升级并重启，拒绝旧协议混连；F3+T不更新Java类。本次Helix v1只重生成0.75圈资源内容，二进制布局、存档和Dome v4格式不变。[攻击与配置](allay-storm-ai.md)和[验证入口](allay-storm-validation.md)分别维护，不保留历史协议逐版说明。

## 数据所有权与身份

服务端 `AllayStormData`／`AllayStormManager` 拥有风暴定义、增长、成员HP／死亡、预留、攻击计划和最终战斗结算。GPU负责位置、速度、触地、接触候选及姿态，服务端不模拟成员位置。普通位置不逐帧上传；指定authority按配置发送稀疏校正，服务端转发，其他客户端平滑应用。authority失效重新选择，旧玩家不能继续提交。

风暴身份为 `dimension + epoch`。ACTIVATE只接受客户端当前维度；UPDATE／DEACTIVATE／STOP必须匹配活动身份。换维度立即清理本地状态，旧维度服务端track只移除，不向已离开的玩家补发清理。STOP先捕获身份再清理广播；同tick重建也具有不同epoch。

攻击另有稳定ID和名单rank，槽位可复用但不构成身份。旧完成／中止反馈不能释放新攻击成员。稳定成员身份贯穿普通运动、参战、死亡和归队，未参战导航输出保留普通盘旋目标，防止主体漂向原点。

Iris合并时，CMI自身的注入源码先用Iris内嵌Jcpp解析条件分支，明确选择`CMI_STARFALL_TBO`、禁用`CMI_DOME_RUNTIME_FLOW`，再进入AST。光影包的原始源码不重复预处理，后续既有转换流程保留。主渲染／阴影／受伤覆盖共用入口，两个覆盖变体分别缓存，资源重载统一失效。计算着色器继续读取运行时流线状态，所有绘制端读取已提交TBO／姿态。

Dome的32格异常退出只在本地成员阶段字复用`0x10000000`标志，记录同一攻击内是否进入过球体；阶段4且身份匹配时保留，新归属／退出／清理时重置。正常穿出、球外兜底和受阻退出共用计算阶段的终止写入：阶段6、清除持剑标记、清理阶段临时字段并写入现有完成位图。没有新增协议或服务端位置模拟。

Dome普通归队交接仅复用成员阶段字及阶段互斥的临时计时字段；没有新增网络消息、逐成员轨迹、位置上传或服务端模拟。Dome v4及其配置／存档格式不变。

## 消息

| 方向 | 消息类（`content/allaystorm/network/`） | 当前内容与作用 |
| --- | --- | --- |
| S→C | `ClientboundStormStatePacket` | 生命周期、dimension／epoch、定义、增长、死亡与稀疏状态 |
| S→C | `ClientboundStormCenterPacket` | dimension／epoch、追击中心与速度、人数、采样时间 |
| S→C | `ClientboundStormDamagePacket` | 权威成员伤害／死亡、有限float伤害与击退、绝对double命中坐标及战斗反馈 |
| 双向各一类 | `ServerboundStormPositionsPacket`／`ClientboundStormPositionsPacket` | dimension／epoch、采样时间、authority稀疏校正及转发 |
| S→C | `ClientboundStormWavePacket` | Helix／Dome的START、UPDATE、LOCK、ABORT；开始／观察者快照含名单，阶段更新为紧凑参数 |
| S→C | `ClientboundStormColumnPacket` | 独立星柱身份、种子、冻结落点与集合参数、阶段时间、精确64名名单；中止紧凑发送 |
| S→C | `ClientboundStormColumnSnapshotRequest` | 柱身份、请求令牌和指定采集来源；同批观察者合并请求 |
| 双向 | `StormColumnSnapshotPacket` | 同身份与令牌、来源、采样时间及固定64名实际阶段／运动初值；仅按需采集与转发 |
| C→S | `StormAttackGatheredPacket` | dimension／epoch／攻击ID、ready与eligible两张rank位图，及Dome流线暂停状态，空位图用于只发布暂停变化 |
| 双向 | `StormAttackCompletedPacket` | 同身份及完成rank位图；指定客户端每game tick合并反馈，服务端幂等释放／确认 |
| C→S | `ServerboundStormHitPacket` | 风暴身份、成员、递增attackSeq、绝对double接触点；不携带战斗值 |
| C→S | `ServerboundStormWaveContactPacket` | 风暴／攻击身份、成员、采样秒数及绝对接触点；采样时间仅诊断 |

包处理在所属主线程执行，数组和资源有界。就绪／完成位图每张最多192个long，支持12288名；未到达GPU池的名单成员不能凭缺失获得就绪。服务端验证 `ready ⊆ eligible` 和非空分母；Helix保持`ready×100 ≥ eligible×95`，Dome使用固定START预算D tick与已过e tick的整数规则`10D×ready ≥ (10D−e)×eligible`，GPU反馈筛选、客户端发送和服务端验收保持一致，冻结参战集合；LOCK与观察者START原子携带completedRanks（含未参战成员）。反馈丢失按同步最晚截止时间回收，本地归队不等待网络确认。

当前authority也可在Dome集结阶段提交既有完成rank位图，服务端按维度／epoch／攻击ID验证、幂等释放预留并广播确认；Helix仍需已LOCK。确认后的rank保存在completedRanks中，观察者接入／authority交接不得复活，旧完成不能释放已接管成员。全员完成时提前回收槽位，未就绪者不增加截止宽限。消息布局和协议17不变。

Dome动态门槛复用START／assemble时间字段，D按绝对时间各自转换为tick后相减，e按当前游戏tick与START tick作环绕差；避免大float时钟相减让截止下一tick被误当作截止tick。GPU、客户端、服务端共用同一整数不等式，乘积有界。最终身体接触后的位图统一重新计数；连续帧历史只从已提交bank继承，候选回滚不累计，冻结参考相位变化重新计数。没有新增消息、快照字段或稳态上传。

Dome启动资格额外排除集合上半球与当前主体保守包络相交的目标。该服务端常数时间检查发生在选员和预留之前，直接START入口重复守卫；不请求实际位置快照，不新建网络消息。拒绝后按原调度处理下一机会，已启动攻击不因该检查追溯中止。

Helix同步模板版本、主体相对锚点、独立单位轴向量、阶段时间和冻结终止平面，避免远坐标相减丢精度。Dome每条流线记录相对START的暂停时刻（最多66条，版本为已暂停流线数），本轮只增不减；变化与就绪通过同一异步快照每game tick至多反馈一次。服务端保存并随UPDATE／LOCK／观察者START广播；旧维度、epoch、攻击ID及过期反馈不得修改状态。LOCK原子冻结暂停状态和参战名单，复用START／LOCK时钟及暂停时刻恢复流线相位，原始rank身份与循环映射通道分离。经历过集结的客户端捕获本地实际相位连续交接；新观察者按同步时钟平滑接入。重复快照不重置交接，身份失效或槽位回收清理缓存。

## 战斗信任边界

拾取显示和点击使用同一份最新已完成GPU快照保存的射线、身份和命中距离，不用新镜头重构旧命中点。保留一次本地遮挡检查、身份失效清理和单次消费。预测挥手不发送额外原版挥手包，避免提前重置服务端冷却。

服务端近战仅检查活动身份、活成员、有限数、递增序号和有界处理（每tick一次、滚动20tick最多12次）；不维护眼位历史，不重复距离、时效或方块射线检查。按玩家／维度延迟复用Allay代理，调用实际版本的武器、附魔、攻击强度、暴击、击退和事件钩子；结算后统一重置冷却并广播挥手。耐久、后置效果、统计和饥饿只执行一次，伤害反馈由权威结果驱动。

区域接触信任GPU实际阶段与触地候选，服务端检查维度／epoch、攻击ID、名单／存活、有限数、未中止／释放和按玩家／成员／攻击去重，不重复历史位置、轨迹包络或地形扫描。仅Starfall实际触地展开、Helix／Dome攻击阶段允许候选；后两者距有效玩家身体中心小于6格才持剑并允许接触。调用原版hurt，保留护甲、盾牌、吸收、图腾及无敌帧；128粒子完整性只影响视觉。

## GPU发布与专用碰撞

槽0–3为大招、4–67为星柱，使用独立标记和足够位宽，不以32位活动掩码或两位槽号寻址星柱。接触按成员归属直接查询，去重按稳定成员与攻击ID存储。大招完成位图每槽384个uint、星柱每槽2个uint，总1664words。

参数、身份阶段与运动状态双bank提交，准备失败不发布新代；compute／原生MODEL用SSBO，Iris读取同backing的只读TBO。Dome姿态按稳定成员身份存储两个32位字，双bank按需分配最多2MiB；Iris单元15读取同代姿态，主渲染与阴影边界保存／恢复10–15单元及原纹理目标。归队保持朝向连续，剑资格不受姿态平滑延迟影响。

Helix受阻观察窗按大招槽／rank保存经过时间、地形裁剪时间、预期与实际轴向推进四个float，与成员身份阶段同bank提交。四槽共256KiB／bank（双bank增量512KiB），位于可选Dome扩展之前，不强制分配完整Dome存储；旧攻击／旧阶段窗口不可继承，失败提交不前进。受阻退出复用既有完成位及反馈，客户端当帧收剑、关闭接触并独立归队；服务端幂等释放预留。初始计划、瞄准更新和LOCK统一发布理论尾部通过后1秒的故障截止。

Dome局部搜索位于最终身体接触之后的独立compute阶段，以最终实际位置建网格，下次成功提交帧消费结果；普通更新只登记／跟随，不嵌入BFS。最多128项在途任务，每项每帧最多64节点、合计8192节点，保留队列和前沿，四槽轮转分配。每rank十二个32位字缓存身份、请求时间、冻结相位及压缩路径，128项搜索各保存512节点父指针和队列。全部新增持久状态双bank提交／回滚，仅Dome按需分配；四槽增量5,804,300字节（约5.54MiB，含完全重建的12字节临时间接参数）。Helix／Starfall不强制分配此扩展。

排队、搜索中、路径可用、完整局部无路、未知覆盖及转折点容量不足分别编码。任务同时校验当前名单中的槽／rank归属，不凭滞留的GPU阶段保留已死亡或完成成员的搜索。碰撞页发布变化使旧搜索／无路结论失效，缓存跟随重新检查身体通道，未知不当空气。空队列且无在途任务时跳过搜索；间接参数使用独立小缓冲，避免把同一大状态缓冲同时作为SSBO写入和间接派发输入。路径、节点和位置不通过网络上传，服务端不搜索地形，只处理原有就绪／完成反馈。

协议17的Helix计划解码仅接受轴向12、合速度上限32格／秒，位置及解析前馈按模板螺距旋进。碰撞和接触扫掠使用32预算；Dome集结使用8预算，LOCK交接预算沿原0.5秒曲线回落至6。GPU参数头复用保留word3保存跨攻击邻居速度上界：默认8，遇Helix后保守保持32直到身份重置，覆盖高速归队成员；邻域查询仍保留原768节点访问边界，无服务端扫描或逐帧CPU成员遍历。该速度预算本身不增加成员状态，仅参数变更时每bank多上传4字节；Dome局部寻路额外存储见上段。无新增网络消息及稳态位置上传。

Dome v4共享五次Hermite曲线、闭合流线与离线逆弧长表；稳态不上传成员位置，不在帧内积分／Newton反解。资源后台准备、分帧上传，完整后发布；资源未就绪不得伤害。同攻击内部正常分离已烘焙，运行时只保留异常／跨攻击的一次预测接触裁剪和地形处理。

主体、尸体、三种攻击和普通归队统一使用独立风暴碰撞域，不占通用粒子8槽。16³区块段位图每段512字节，空气／实心共享标记；整数纹理＋TBO页表，按需扩容，不淘汰活动需求。重叠只采集一次，范围移动增删边界，世界变更仅更新相关段；只读已加载数据，未知不能作为空气。

客户端所属线程采集，后台只处理不可变数字快照；默认每帧采集1ms、上传0.5ms且≤128KiB软预算。完整上传后发布页表，旧版本保留至引用帧结束。Dome覆盖中心下20格至上40格及穿出／归队；Helix包含32格尾部及扫掠，已释放成员由独立本地归队覆盖记录接管。报告请求／覆盖／未知段、显存、上传量、采集耗时及超预算，不静默回退8槽。

## 存档与槽位

每维度attachment保存active、anchor、count、seed、创建时间、冻结增长定义、死亡集合和稀疏HP，不保存GPU位置。`CreationRadius`按半径恢复；长满仍保留原半径、增长率、最终规模与创建时间，确保同tick相位连续。缺失／非法增长字段以当前规模建立零增长、加载时重建相位起点，保留成员、死亡和HP，不产生NaN。

槽位先回收过期、再用空槽，满槽按编号复用ABORT淡出槽，不驱逐有效攻击。替换完整清理名单、圆环、声音、碰撞就绪和反馈身份；有容量保留0.25秒淡出，旧圆环由资源代令牌隔离。

## 快照与观察者恢复

Center与双向Positions统一携带dimension／epoch；异步位置读回保留采集身份，身份变化后丢弃。两端按身份拒绝倒退时间戳，服务端仅接收当前authority的位置上传，广播排除已换维度的track。速度上下行共用signed short编解码，精度1/16格／秒、分量边界±32格／秒，保持最多256名，满包约4KiB。

新增`ClientboundStormColumnSnapshotRequest`及双向`StormColumnSnapshotPacket`。服务端按柱合并等待观察者，令牌绑定指定来源；1秒未完成即重选，旧身份、旧令牌、非指定来源及已结束柱的响应无效。单柱64名固定30-float语义记录，成员数据7680字节，常规身份头合计低于8KiB；包含实际位置／速度、阶段、集结初值、下降曲线初值／进度、展开与回流参数，不传弧长表。位置相对冻结落点，时刻复用共享时钟。

仅有请求时从已提交GPU代异步采集，每帧最多4柱；同批观察者共享结果。接收端等待完整快照，使用候选bank原子恢复并一次重建所需弧长表；每帧最多4个0.1秒碰撞子步追赶，恢复帧不持剑、不产生接触。追赶计算使用独立更新变体，普通帧不编入恢复分支。安装确认复用既有异步反馈，重复快照不重置进度，未进入本地GPU池的成员继续等待。没有新增稳态逐帧上传，服务端不模拟或长期保存成员位置。

最后一个有效模拟来源离开时中止现存星柱并释放成员，新观察者回来后正常调度新柱。authority交接优先复用已持有实际状态的客户端；尚在恢复的来源不能提供未完成的快照。

Starfall的3格／秒集结切向匹配只在首次正常下降初始化执行；恢复保存的曲线初值和方向，不重新判断是否就位。集结追赶预算8，其余阶段6。阶段编号、30-float记录、采集预算及切换时刻均未改变。
