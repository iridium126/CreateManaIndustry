# 200 tick/s 实机日志后的客户端采集修复

验证日期：2026-10-03。输入日志为用户提供的 `run/logs/debug.log`，最后写入时间 13:57:27；日志作为诊断数据处理。此前 200 tick/s 理想输入回归通过，但真实客户端采集频率没有同步提高，这次修复覆盖该遗漏。

## 日志证据与根因

13:55:07.798 服务器目标速率切换为 200；13:55:08.950、13:55:15.478 客户端因 `Package input history expired` 全局撤销。13:55:18.936 调回 20 后，13:55:21.550 开始拒绝机器环境事件，随后增量 `INVALID`；13:55:29.800 出现 `Package transition queue exhausted`。之后仍周期性历史过期，直到退出世界。相关原始行保存在[证据目录](benchmarks/package-client-cadence-2026-10-03/reproduction-excerpt.log)。

项目实际 Minecraft 1.21.1 源码中的 `Minecraft.getTickTargetMillis` 返回 `max(50ms, tickRateManager.millisecondsPerTick())`，因此服务器设为 200 时，客户端世界依然最多每秒二十次 tick。`ClientPacketListener.handleSetTime` 则直接设置客户端 `gameTime`。旧历史按这个同步时间编号，时间包的跳跃留下没有采集过的输入编号；GPU 无法越过第一个缺口，最终重新撤销所有权威。原回归每 5ms 提供完整世界输入，无法检出这个条件。

## 输入序列与有界补算

新增 `PackageClientInputs` / `PackageInputTimeline`，在客户端 Post tick 的最高优先级生成包裹专用的单调采集区间，不受时间包回拨、快进影响。碰撞和力源随后按同一区间保存历史；力源捕获位于最低优先级，确保碰撞和结构姿态先完成采集。

200 tick/s 时每次 20 Hz 采集提供十个游戏步。静态几何版本和不可变力源共享该次实际客户端观测；移动结构的平移、旋转、尺度在已捕获的前后姿态之间插值，每个游戏步获得独立的前后区间和一次性编号。不会重复扫掠整个姿态对，也不会借用之后的历史改写之前的输入。这是基于客户端离散观测重建的子步，不声称恢复了客户端未收到的服务器中间姿态。

GPU 每游戏步仍积分 50ms 游戏时间，200 tick/s 的墙钟周期为 5ms，速度维持十倍。时钟预留最多一个尚待采集的区间；采集之间不会丢失已过去的时间。真实缺失和过期仍暂停、重新取得基线，不假装完成缺失步。

首次启动从第一个可用采集区间开始积分，留出一个采集区间的显示延迟，随后按 5ms 节奏消费。不能在收到十步输入后立刻全部算完，再冻结到下一次采集。200 FPS 回归要求首批就绪后每帧持续推进一步；低帧率的待消费量限于一个观察帧，输入停止后能全部排空，没有累计丢步。

同一采集区间的十个力源输入只提交一个 worker 构建任务，返回各自的精确输入编号。最多四个任务在途。GPU 相同不可变数据可以复用仍在读取的上传银行，每次关闭用覆盖全部读者的新 fence 替换旧 fence；不同数据仍不能覆写未完成银行。最新采集保留用于接管，避免已消费后同一渲染帧重新捕获可变世界。

移动姿态银行随补算预算扩大，200 tick/s 每结构最多四十个银行，旧银行及其 fence 保留；不会因为四银行硬上限而永远无法补完低帧率输入。默认二十 tick/s 仍使用四银行。历史、资源、最终基线、心跳、重试及服务端步数预算延续前一轮按目标 rate 的换算。

## 环境接触与队列

日志拒绝的机器事件报告方块 `(-18,84,17)`，但某些包裹最终中心已被修正到世界 Y≈89.6。旧 shader 检查整段扫掠，却记录最终位置；接触后堆叠修正使最终位置远离接触方块，服务端按最终位置拒绝该有效扫掠。

shader 现在记录实际命中时刻的包裹中心，初始重叠时记录扫掠起点。服务端使用与 GPU 一致的接触边界误差检查接触点及真实方块，保留库存身份、租约、事件序号、步号及伤害资格校验；不再依靠四方块的最终位置容差。燃烧结束的无接触计时事件仍记录当前位置。机器接触事务继续由服务端消费当前库存。

接管控制队列与累计环境 ACK 分开有界存储，各最多 1024 条；新 OFFER 在控制队列达 512 条时单独拒绝，为已开始的握手保留空间。过载不会设置共享运行时失败并关闭所有自由包裹。ACK 按区域、epoch、revision、身份、lease、基线 revision、index 精确合并，只保留更大的累计确认号；ACK 队列满时可从 GPU 保留的未确认 journal 重发恢复。两类消息交替处理，避免大量握手饿死环境确认。

同一步号的延迟确认允许更新零位移状态，位移额度严格为零；更旧步号、同一步再次移动和重复网络序号仍拒绝。这修复了可能造成区域 `INVALID` 的独立时序问题；用户旧日志未含具体校验分支，不能断言那一次 `INVALID` 就来自该分支。真正输入过期日志现记录 next/available 输入、世界时间、rate、步号和等待资源，便于区分 worker、历史、几何版本与上传银行限制。
