## 当前 ABI 10 修复结果（2026-11-04）

本节替代下方旧实现的路径描述。下方 ABI 9 结果作为历史证据保留，其中“完整 GL Dome”实际运行了全池参考，不能用它证明真实生产 Dome 的表现。

五个客户端窗口均来自 PID 24060，相机、2560×1506 分辨率和 Complementary 光影配置一致，但攻击阶段不同。production 无 Dome 为 50.60 FPS；RT 含集结为 33.78 FPS；production 含集结为 49.39 FPS；GPU 验证 RT 无 Dome 为 44.67 FPS，卡顿窗为 1.91 FPS，57/58 帧超时。卡顿窗 Dome 间隔中位数约 540.76 ms、接触约 35.42 ms、continuation 约 524.53 ms。Dome 消失后的最后七帧仍持续长帧。它们用于定位回退连锁，不能充当三轮 FPS 验收。

异步三角探针原型通过 10／50／500 ms 延迟、三槽同时占用、退休、待完成关闭、容量、错代／错场景／未完成／非法坐标和静止跳过检查。局部修正通过 30,568,451 项字段／位移／地形约束检查：正常轻微重叠两步消除，密集溢出、低速预算和未知地形保留未解决状态。Dome 近似覆盖审核拒绝据此新增就绪或删减分母。

这些是组件检查，不是完整近似质量或性能准入。独立模型显示快照、一帧显示延迟、相同四探针算法的高效 GL 对照、交叉流／完整玩法质量、真实 RT／GL 重叠以及完整新链测量尚未完成。诊断客户端不开放近似候选，实验源码包明确标记未准入。生产 Dome 的原子网格顺序可能使参考 A/A 轨迹不同；规则矩阵原样保留这些差异，不能包装成逐位等价通过。

NVENC／NVDEC 不接入在线路径；继续沿用下方历史实际往返结果和停止接入结论。

## 历史 ABI 9 结果（2026-11-03，修复前）

结论：实现已通过本轮离屏正确性验证，但三个 RT 候选均未达到完整更新链收益门槛。保持 `production`；媒体路线停在离屏原型，客户端画面、玩法与 FPS 标记为**待验收**。没有将微基准换算为 FPS，也没有启用媒体与 RT 组合。

## 冻结与范围

冻结清单为 `build/benchmarks/hardware-r9-20261103/baseline/manifest.json`，保存原始源码、已有 DLL、索引指纹。最终测量每轮前后核对原生源码、DLL、硬件 Java、验证 Java、粒子着色器和验证任务文件的 SHA-256；三个独立进程均一致。生产粒子着色器、粒子记录布局、网络协议和玩法接口未改变。

设备为已有 RTX 4070 Laptop，使用原 GPU/驱动和固定 SDK 缓存。真实捕获来自 R7 Complementary 水平场景，普通分离查询 65,528 行。Dome 在本轮 RT 候选中始终使用完整 GL 路径；Dome 多帧规则由独立合成矩阵覆盖。

## 生命周期与时间线

修复消费者 fence 未提交导致槽位无法退休的问题；已完成但未消费的输出复用前归还所有权。原生超时继续隔离资源，只有实际完成后才能释放。首次失败和 `ring busy` 保留资源代次、任务、阶段、槽位、Fence 与退休状态。

详细采集使用策略 371（339 加时间线标志），位于 `admission/hardware.json`；正式测量不启用该标志。`lifetime_trace` 保留 R8 的 16 项格式：0 为时间线格式版本 8，1 为策略；2–9 为从提交到 worker 开始、输入封套可读、查询入队、结果就绪、发布、消费者提交、退休开始、退休完成的 CPU 时间戳；10 为外部信号量等待的 GPU 区间；11 为输出等待/读回区间；12 为输入封套复制区间；13–15 分别为排序区间、lookup 复制与输出封套写入区间、输出信号发布区间。没有执行的项为 -1。原生 ABI 单独为 9，时间线格式号不是 DLL ABI。

`native_ms` 的 0 是查询 GPU 总区间，1 是 worker 墙钟时间，2–6 分别是包围体/校验、BVH 维护、查询与力累加、扫描、第二遍查询/压平。融合策略后两项为空事件间隔。CPU 区间与 GPU 区间可能重叠，不能相加。消费者时间戳表示提交外部等待，退休 fence 证明消费者完成；它们不声称是第一条 GPU 指令的硬件时间戳。GL 输入就绪通过外部信号量依赖保证，信号量等待区间不能解释为全部互操作开销。

RT Core 加速遍历，自定义求交、距离判断、力累加和 BVH 维护仍占用普通计算资源。输出封套读回已可由 GPU 验证替代，输入 64 字节读回仍保留，没有把未知统计报告为零。

## NVENC / NVDEC

设备实际完成 HEVC 无损 NV12 字节往返。数据放在 Y 平面，UV 固定，未经过 RGB/YUV 色彩转换；关闭 B 帧和前瞻。独立帧与低延迟 P 帧都通过逐位校验。下表是 8 次正式样本中位数，单位 ms。

| 已准备输入 | 大小 | 独立帧 CPU 往返 | 重复 P 帧 CPU 往返 | 同字节 GL 复制 GPU 时间 |
|---|---:|---:|---:|---:|
| 真实粒子记录片段 | 4 MiB | 31.701 | 15.712 | 0.172–0.193 |
| 真实 continuation 片段 | 4 MiB | 35.018 | 11.739 | 0.177–0.184 |
| 按身份排序的量化坐标 | 1,048,448 B | 6.883 | 3.691 | 0.091–0.095 |
| 随机字节对照 | 64 KiB | 1.506 | 1.018 | 0.005 |

CPU 往返包括封装、上传、编码与码流 CPU 搬运、解码与 D2H、验证和同步；初始化另列。捕获提取、身份排序和坐标量化在计时外。GL 列是相同已准备数据的直接复制，不是 CPU 往返等价基准，也不代表整个粒子帧耗时。重复 P 帧只改变封套代次，是压缩最佳条件的成本下界；没有把它描述成运动序列性能。尚未实现在线 GPU 整理、粗筛消费者与完整媒体粒子链，当前结果不足以支持生产接入。

坐标使用明确的 1/64 格量化与无损编码。保守单元向外扩张，当前精确坐标负责最终规则；身份变化、未知状态及越界失效。纯 Java 覆盖测试检查 20,000 组随机粗筛无漏检。媒体输出没有参与权威玩法状态。截断、损坏、错代和后续复用失败会话均拒绝发布旧结果。

## 验证与交付

- 原生构建和普通 `test build` 通过，Java 共 1,034 项测试；R9 分析脚本 8 项测试通过。
- 真实完整链 FP64 力参考与受保护状态检查通过，共 18,369,448 次断言；覆盖 5 类 GPU 发布故障的完整回退。
- 三个候选分别通过 84 个场景组合、840 个状态步；包含出生死亡、Dome、伤害、尸体、恢复、工作组边界及缺失碰撞状态。
- 最终 DLL 的完整候选集合/重复检查通过，涵盖空集、重合、半径边界、远坐标与溢出；异步测试覆盖三槽交错、初始化失败、租约、超时隔离与安全退休。
- 最终测量三进程均完成且源码指纹一致；失败尝试的日志保留，其中一次追加异步任务因共用输出目录提前退出，已用独立目录重跑。

诊断包包含安装器、哈希清单、ABI 9 回执、依赖许可证、客户端命令、三进程清单示例及分析器。证据包包含冻结基线、最终改动源码、原始 CSV、JSON 和日志。安装、固定场景与回退步骤见 `docs/gpu-hardware-offload.md`。用户客户端每窗至少 30 秒且 1,000 帧；近似候选须三轮平均 FPS 均提升至少 20%、超过 A/A 噪声且 p95/p99 无稳定退化，并由用户确认画面和玩法后才考虑采用。
