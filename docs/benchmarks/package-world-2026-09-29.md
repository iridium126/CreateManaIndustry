# 包裹世界碰撞上传与查询测量（2026-09-29）

本阶段完成版本化 GPU 碰撞 atlas、预算化上传、世界 AABB 扫掠和刚性地面约束的内部接线。**真实 Create 接管仍关闭，密集堆叠未通过视觉质量标准。** 没有游戏内同屏帧率、服务端 tick、Iris、网络或 Create 原生同场景录像，不能认定 131072 活动包裹方案完成。

## 方法与可复现入口

RTX 4070 Laptop GPU，OpenGL 4.5，NVIDIA 581.15。隐藏 64×64 GLFW 验证上下文；通过生产 ResourceManager 路径/include 解析加载处理后的运行时 shader。计时采用 GPU `GL_TIME_ELAPSED`，每个负载预热 20 步，再从相同初始状态重复三组、每组 30 步；步长 0.05 秒，每步包含插值历史、预测、四轮网格构建与 Jacobi。

```powershell
.\gradlew.bat test --tests '*Package*Test' --tests '*CMIParticleCommandTreeTest' validatePackageGpu validateHexGpu jar --offline --no-configuration-cache -I scripts/particles/validation.init.gradle -PpackageWorldBenchmark
```

没有实时帧间等待或自动节流。样本结束后 GPU 结果等待/下载仅用于验证，生产 atlas 使用零超时 fence 轮询，没有 `glFinish`、阻塞 fence、等待 worker 或结果读回。初始 body 上传、CPU 形状打包、atlas 分配、view 建立和计时查询操作不包含在 substep CPU/GPU 时间中。CPU substep 提交分位数通常为微秒级，受系统/JIT/计时精度影响，不等于整个渲染线程成本。

原始 [45 组统计](package-world-kernels-2026-09-29.csv) 与 [1350 个逐步样本](package-world-kernel-samples-2026-09-29.csv) 全部保留。下面分别取三组 p50/p95 的中位数，并非把不同负载合成一个帧率。

## 空分区查询对照

每个 body 半尺寸为 0.5，初始非重叠 64×64×层数阵列、间距 1.5，速度 vx=0.25，重力 32 方块/秒²。三个路径输入完全相同：

- `legacy_air`：现有 solver，没有世界查询或世界碰撞体。
- `world_air_cells`：世界路径，用内部 `view(..., false)` 关闭已确认空 section 的粗查询，逐 cell 查询。
- `world_air`：世界路径，只有完整上传、无形状和无危险标记的 section 可以按 section 查询跳过 cell 遍历。

两条世界路径在同一 JVM/同一 shader 内执行，没有更改物理公式、调度数量或资源覆盖。完整 131072 body 的 16 个字段逐位一致；所有候选仍在运动，fallback=0。

## 上传、存储与预算限制

本验证配置为 343 个逻辑 section、两个物理版本槽/section、每 section 一个唯一 AABB，覆盖完整运动轨迹。atlas 数据加四个索引 bank 共 **45110720 字节，约 43.02MiB**；这不含 body/历史/链路、通用粒子池、模型、delta journal 和 CPU 缓存。生产初始配置是 256 section × 1024 唯一 AABB，数据 48MiB，索引另 64KiB。

完整空分区上传为 22478848 字节，平面为 22480416 字节。帧预算默认 256KiB/0.25ms，单次拷贝最大 16KiB，需 86–87 次 pump 完成。重复局部形状由 worker 去重：全实心 4096 cell section 的 GPU 几何只需一个 32 字节 AABB；cell 参数仍为 64KiB。

多数合成上传的 p95 为 0.010–0.060ms，但本次 65536 `world_air` 初次上传出现 **p95 0.5895ms、87 次 pump 中 10 次软预算超限**。这里包含冷页写入和系统调度，尚未隔离原因；不是每帧都能严格低于 0.25ms 的证明。单次拷贝/方块查询不可抢占，预算检查只能停止后续工作。应通过游戏内预热、方块更新和高速移动测量进一步处理，不能隐去超限样本。GPU 分配也不在这个上传统计内。

游戏诊断 `/cmi particle packagecollision capture` 开始采集/上传；`/cmi particle packagecollision` 分别给出 CPU 采集、已发布 worker 烘焙和 GPU 上传 p50/p95、超限/拒绝/等待状态，`clear` 失效并释放资源。这些真实世界采集数据尚未在本报告取得；合成上传时间不能冒充游戏主线程采集时间。驻留分区退订、优先级和高速预取尚未连接生产适配器。
