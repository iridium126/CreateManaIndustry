# 动态结构包裹物理测量（2026-09-29）

本轮实现 Create contraption 与可选 Sable sub level 的碰撞数据入口，以及显式实验 GPU 接触管线。**真实 Create 包裹接管门禁仍关闭；没有完成游戏整帧、实际 Sable ABI、视觉或多人验收。** 以下使用合成结构和真实 NVIDIA 驱动，不代表实际 Create/Sable 场景已达到目标。

## 方法

机器为 NVIDIA GeForce RTX 4070 Laptop GPU，OpenGL 4.5.0 NVIDIA 581.15。固定种子、64×64 错位堆叠、半径 0.5、20Hz、4 轮相对 Jacobi、支撑森林投影。每一步 GPU 驱动施加持续变化推力，禁止用休眠替代活动容量。测试 10000、65536、131072 个动态 body；静态体素地板、一个刚性平台、16 个相邻刚性平台分别测量。平台每步沿 X 平移 0.003 格，几何不改变。

每组预热 20 步，再进行三次独立重置，各 30 步。GPU timer 包含物理全部派发；CPU 提交包含获取世界/姿态视图、绑定、派发和 fence 发布。测试在 timer 结束后等待结果，以保持夹具姿态槽可用，等待耗时不进入 CPU 提交统计。生产路径只执行零超时轮询。持续运动容量检查额外执行 60 步，并每 10 步验证 GPU 全邻居对统计、有限状态、回退数、活动数与地面穿透。

静态地板使用真实静态 atlas 格式；移动平台使用一个合并局部 AABB/BVH。两者数据表示不同，不能从较低的单平台数字宣布整体引擎提速。比较一个与 16 个平台说明当前按结构派发的扩展成本。

## GPU 结果

下表是三次运行 p50/p95 的中位数，单位 ms。所有测量组均为零最终重叠、零地面穿透、零回退，移动结构组的活动数等于输入数；静态组活动数为输入数减 48，仍超过 99%。

| 包裹数 | 静态体素地板 p50/p95 | 单平台 p50/p95 | 16 平台 p50/p95 |
|---:|---:|---:|---:|
| 10000 | 1.059 / 1.079 | 0.575 / 0.588 | 1.666 / 1.833 |
| 65536 | 2.975 / 3.255 | 2.196 / 2.352 | 3.712 / 3.868 |
| 131072 | 5.371 / 5.605 | 4.632 / 4.875 | 6.620 / 6.853 |

131072 时，单平台 CPU 提交 p95 为 0.0230–0.0284ms，16 平台为 0.0808–0.1505ms。夹具姿态捕获 p95 为 0.0024–0.0035ms / 0.0076–0.0282ms；这仅是读取已构造的不可变姿态，并未测量 Minecraft 世界采集或 Sable 反射调用。

一次几何上传分别为 48B / 768B，运动过程中不重新烘焙。每个平台姿态 bank 为 256B、四槽；包裹承载 sidecar 为 16B/body，131072 个增加 2MiB，仍只占一个通用粒子槽位。姿态与附加缓冲不进入 shaderpack 的 64B 粒子读取协议。

## 正确性及修复

- 1/63/64/65 尾部工作组与全部三种索引路径；连续平移/升降承载、表面速度、正非均匀缩放、旋转承载。
- 150 个固定种子三轴旋转/缩放，与独立 double 精度 15 轴 SAT 对照。剩余穿透容差 0.0003 格，明显分离时不得产生水平位移。
- 0 / 0.6 / 0.98 / 1.2 材质摩擦与相邻平台接缝的滑动速度对照：每物理步仅施加一次摩擦，不因接触阶段或平台数量重复阻尼。
- 4/8 格单步墙体扫掠，以及只在中间旋转姿态相交的墙体。
- 65536 个方块精确合并成单平台；保留空洞、材料边界，超过容量明确拒绝。
- 四槽连续延迟、第五槽拒绝与恢复；已打开视图在失效、清空后拒绝使用旧几何；同一个 tick 姿态不能被同一个 solver 重复推进。
- 未上传几何、未知结构枚举、危险/回调碰撞体、移动平台与静态天花板挤压均请求交还。
- 后台仅访问 primitive 快照，主线程捕获软预算、四任务背压、陈旧任务丢弃、缺失区块暂停与恢复均有 Java 测试。

最终完整验证通过：包裹 GPU（含基准）12781598 项断言、Hex GPU 135498 项断言、Java 155 个测试，build 成功。Hex 重载故障测试产生的 ERROR 是预期注入，旧程序保留验证通过。

本轮测试发现并修复的问题：Jacobi 将底层压入平台后必须先重新约束根高度再传播支撑；相邻平台边缘须保留原接触进入面；固定朝向/缩放的切向扫掠应使用解析 SAT 区间，避免无必要地耗尽保守推进迭代。

## 限制与下一步

- 当前每个结构分别执行准备、承载和接触派发，包裹状态多次 ping-pong。16 平台比单平台增加约 1.98ms GPU p95；需要区域结构索引与合批，不能假设 64 结构成本仍满足整帧目标。
- 旋转/变缩放的保守推进最多 32 次，BVH 遍历最多 1024 节点；预算耗尽明确请求交还，未截断后继续接受结果。复杂旋转结构的大容量活动覆盖尚未通过。
- 运动结构按外部权威姿态视为运动学碰撞体，尚不反馈反作用力到 Sable/PhysX。自定义动态 collider、碰撞回调/脆弱块、流体/火和实体相关形状保守交还，不能声称完整 Sable 玩法语义已移植。
- Sable 可选入口按 .refs 中公开 API 缓存反射符号，ABI 异常撤销覆盖；没有安装的二进制/游戏会话来验证注入和实际 sub level。Create 6.0.10 实际 jar 已核对相关方法描述符，但本轮未运行游戏内 mixin 验收。
- 真实世界捕获/大规模编辑、资源重载、跨维度、Iris/阴影、网络增量和 131072 活动包裹整帧 p95≤16.7ms 尚待验收。不能把本报告的计算内核时间当成帧时间。

## 后续 API 迁移
