# 包裹堆叠支撑传播与接触对测量

日期：2026-09-29。RTX 4070 Laptop GPU，OpenGL 4.5，NVIDIA 581.15。**这是合成物理组件验证，尚未完成 Create 游戏内视觉、渲染、网络或整帧验收。实验路径默认关闭，真实接管门禁保持关闭。**

## 实现与正确性修正

保留 64 字节 body、通用粒子槽位和现有渲染/增量同步布局。实验路径在四轮接触后，GPU 建立垂直支撑关系，以严格 `(Y,index)` 顺序避免环；每个 body 选择一个支撑父节点。通过两组 16 字节记录进行指针跳跃，传播最低支撑高度和支撑速度，最多 `ceil(log2(count))` 次 dispatch，131072 输入为 17 次。最后仅写自己的 body，并重新验证世界形状和覆盖。

计数与间接命令在 GPU 生成；没有支撑边时，跳跃/应用生成零工作组。含工作组屏障的 kernel 让尾部线程参与全部屏障，不依赖 subgroup 或浮点原子。附加工作空间按需分配，在更新 body 前检查实际分配容量；失败会清理未完成的工作空间。工作空间只复用，不做每帧分配。

接触实验路径还作了两项修正：按各轴的正负约束极值修正位置，避免其他轴的接触数稀释约束；按两个 body 的相对速度累计修正，避免共同下落的堆叠被零世界速度冻结。旧的绝对速度清零在抽掉地面后曾使 1024 个 body 中只有 640 个保持运动；修正后全部共同下落。默认四轮 Jacobi 保留作对照。

世界接触的进入面修正作为正确性修复应用于世界 kernel：动态修正把 body 压过体素中心时，从上一步分离的面解出，不因单个体素的最短位移而误把连续地面接缝识别为两堵侧墙或从地面下方解出。65 个 body 的地面/天花板深穿透测试验证恢复正确面、保持横向坐标和裁剪进入速度。

## 方法与质量判定

- 输入数量 10000、65536、131072。64×64 个水平位置，间隔 1.03125 方块，初始中心 Y 为 `1.5 + layer*1.03125`，初始 vy=-1；半尺寸 0.5。完整实体形状是 AABB，无角动力学。
- `aligned_still` 为规则堆叠；`staggered_still` 的奇数层在 X/Z 各偏移 0.4；`staggered_driven` 在 GPU 对每层持续施加不同相位的水平推力。三者都每步执行重力及完整接触解算，没有启用休眠。
- 三个算法为旧四轮 Jacobi、旧十六轮 Jacobi、四轮实验接触加支撑传播。20Hz，dt=0.05。每组重新上传同一输入，预热 50 步，测量 40 步，独立重复三组。下表是三组各 p50/p95 的中位数。
- GPU timer 包括历史、积分、世界碰撞、网格重建、所有接触迭代、支撑准备/传播/应用及活动场景的 GPU 推力。CPU 提交时间不包括 timer 下载、输入生成、初始化、采集/上传、读回、绘制或网络。
- 最终位置重建空间哈希，检查全部 27 邻域中的所有真实候选；哈希冲突需要完整坐标匹配，碰撞对只按 `j>i` 计数，无邻居截断。另统计接触 body、最大最小轴穿透、平面穿透、非有限值、回退和运动数量。检查器对零输入及 1/63/64/65 数量与 CPU 全对穷举核对，深度容差 1e-6。
- 数值门槛为全部接触对最大穿透 <0.002 方块、平面穿透 <1e-4、非有限值和回退均为零。这个门槛只判断合成数值质量，不能代替视觉对照。`moving` 表示最终速度模长 >1e-4，不是活动调度计数。
- 131072 的持续运动回归另跑 120 步，每 20 步检查接触质量、完整输入计数、零回退以及超过 99% 的运动 body。规则/错位/16倍质量比的 1024 body 堆叠在移除地面后检查全部开始下落。

## 覆盖错误与保留的失败样本

首轮沿用了 343 section fixture，其 X/Z 只覆盖 0..6。持续推力使部分 body 的 X 从 2 向左移动，在中心 X<1.5 时碰撞 guard 进入 section -1。GPU 正确触发交还；缺少 Create 接管的合成场景把这些 body 留在旧状态，随后接触误差扩大。逐步诊断最早拒绝 body 位于 X≈1.51、Y=9.5，堆叠顶部始终为 16.5，并非支撑传播把堆叠推至高 Y。上一轮的 320/1057 等回退不能作完整覆盖下的算法失败证据。

最终 fixture 改为 448 section：X/Z=-1..6、Y=-3..3，覆盖完整轨迹及 guard。所有三算法、全部 81 组末尾回退为零，并显式断言。生产未知覆盖仍立即交还，未为通过测试把未知区域当空气。

最终原始数据为 [分组结果](package-stack-kernels-2026-09-29.csv)（81组）与 [逐次样本](package-stack-kernel-samples-2026-09-29.csv)（3240项）。覆盖不完整的探索数据依次保存在 `package-stack-first-*`、`package-stack-axis-first-*`、`package-stack-entry-first-*`；它们分别对应首次相对速度、各轴极值、世界进入面阶段，不参与最终表格或优化资格判断。此前 [世界碰撞报告](package-world-2026-09-29.md) 的失败样本保留原样。

## 存储、复现与剩余范围

支撑工作空间为 `32*capacity+32` 字节：131072 时 **4194336 字节，约4MiB**；分配后在 solver 内复用直到关闭。CSV 的 `support_extra_required_bytes` 表示该算法额外需要的空间，不是每组实际显存驻留差：一个 solver 会跨组复用已分配工作空间。

合成世界 atlas 为 448×2 个版本槽、每 section 一个唯一形状，数据与四个索引 bank 合计 **58880000字节，约56.15MiB**。不含 body/历史/链路、通用池、模型和 delta 缓冲，初始化上传也不包含在 timer 内。生产配置、采集预算、shape 上限和 residency 仍按世界碰撞组件管理，本次未扩大生产 atlas。
