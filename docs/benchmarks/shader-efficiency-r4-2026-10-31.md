# 实机记录驱动的 GPU 粒子着色器优化 R4

## 交付结论

**本轮没有替换生产着色器。** MODEL 只读缓存候选未通过完整链等价门槛；两种绘制复用候选均出现匹配 A/A 之外的稳定退化，已撤回。未降低风暴成员的数量、模拟频率、碰撞或画面精度，也未启用羽毛／金粒子的不可见降频。

保留的生产改动是采集正确性修复与可回放上下文导出。实验、验证类和冻结参考不进入分发包。相对本轮基线，分发包内全部 **222 个生产 shader 资源逐文件 SHA-256 不变**；原有 AST 优化未扩大。

## 候选与决策

### MODEL 只读攻击缓存

隔离候选只缓存一次调用内的只读 assignment 和攻击 kind，按成员／base 变化懒加载；slot/base 仍按原整数公式计算。保留 `cmiStarVec` 的 raw-vector 读取、精确时钟、所有浮点运算及动态状态读取，不缓存 `starStateWrite` 的阶段、接触、导航或完成字段。统一程序、普通域→MODEL 域调度和生产屏障未拆分。

固定输入哈希的内核诊断覆盖 46 组、184 对调用，含 1,000／65,536 成员、普通／MODEL／混合、星落、螺旋、穹顶聚集与攻击、尸体、拥挤、时钟边界、不规则步长及碰撞资源缺失；**4,595,818 项检查通过**。

完整链夹具执行准备、两域更新、穹顶接触、解穿透、导航、反馈与状态发布，另有真实列快照生成→恢复→普通更新场景。每次计时前恢复冻结输入池、输入哈希与状态银行；它是受控固定输入夹具，不是游戏世界回放。

完整链同样完成 46 组、184 对诊断，但穹顶聚集的 MODEL-only 场景在 1,000 和 65,536 数量下均发生 **A/A 自身差异**，随后 A/B 也有差异。例如 x 坐标 raw bits `4114c785` 与 `4114d2db`。按稳定身份匹配后仍不同，不能仅用压紧顺序解释；具体根因未证明。保留 `validation-failures.txt`，不生成通过标记，也不扩大容差。

新增列／恢复链的八组、32 对诊断通过，**799,676 项检查通过**；恢复数据来自实际 `column_snapshot.comp`，并断言包含有效状态，不以空恢复队列冒充覆盖。它不能解除穹顶聚集的完整链失败。

**决定：不接入生产。** 计算诊断仅每组四对，尚未开展三轮各 64 对的完整性能门槛；没有可宣称的 MODEL 更新加速百分比。初次引用错误的恢复工具日志与修正后的通过日志均保留。

### 穹顶邻居查询复用

仅在单个邻居处理内复用 `cmiDomeOwner(other.w)`，没有跨邻居／pass 缓存动态状态；保留原格子、链表顺序、768 访问预算、最危险接触选择和原子操作。四组完整链诊断中，聚集阶段再次出现基线自身差异，因而未通过替换门槛。未扩展到人口列表、索引布局或接触算法改写。

### 绘制攻击查询复用

第一候选同时复用 claim 与 carry；第二候选缩小到复用已经计算的 carry，保留原 claim 查询，减少局部变量存活。原生 `model.vsh` 与隔离的光影合并编译器同步修改，生产源码未替换。

每个候选均在 Complementary／Solas 上完成三轮独立进程 A/B 和三轮独立进程 A/A。每轮 12 组输入、每组 64 对，合计每候选 4,608 对。场景为 1080p、50,000 提交成员、动画＋持剑与混合攻击两种负载，以及稀疏／密集／遮挡三种布局。计时包括身体、持剑和透明层的完整三段，保留分段与 CPU 提交记录。

按匹配输入的 A/A，三轮均须超过相对 0.5% 和绝对 0.002 ms 下限；p95 退化另用匹配 A/A 判断。所有初始异常保留，没有用复测替换原始标记。

| 候选 | 稳定改善组 | 稳定退化组 | 关键结果 |
|---|---:|---:|---|
| claim＋carry | 7 | 2 | Complementary 混合负载三轮约 −2.37%～−2.58%；动画＋持剑的密集组 +0.64%～+0.77%，遮挡组 +0.75%～+1.01% |
| 仅 carry | 6 | 3 | Complementary 动画＋持剑的稀疏组 +0.68%～+0.82%，密集组 +1.13%～+1.24%，遮挡组 +1.27%～+1.32% |

**两种候选均撤回。** 局部收益不抵消其他有效负载的稳定退化。计时使用合成 RGBA32F MRT，并非原实机选项／附件带宽，不换算整帧 FPS。由于初筛已失败，没有继续展开八包、两分辨率的完整性能矩阵。

最终 carry 候选的八包严格差分仍独立完成：全部附件／深度、身体／持剑／透明层、关键帧、受伤／尸体、攻击、LOD 与现有选项变体合计 **1,639,182,442 项检查通过**。这证明所测输入的数值等价，不能推翻性能门槛失败。

## 保留的实现与验证工具

- Profile 的包名、源码、选项绑定到同一活动 pipeline／session／构建代次。关闭光影不显示旧选项；等待新 pipeline 时显示 pending。状态查询仍只读，不触发导出或编译。
- 仅在显式开启 profile 后，为活动会话导出 `run/logs/cmi-particle-profiles/session-*.json`：完整有效选项值、源码摘要、环境宏、维度、分辨率、MODEL draw-buffer 映射、颜色附件及深度格式。原窗口只有哈希，不能倒推出原选项值。
- 绘制工具可用 `-PdrawSnapshots=<目录>` 回放宏和选项。源码、包、维度、宏或有效选项哈希不匹配时拒绝原生格式计时；目前回放支持主世界。严格差分继续使用 FP32 MRT，性能目标可按匹配快照使用实际附件格式。
- 原生格式回放的独立合成 GPU 测试已验证选项／宏应用、不匹配拒绝、RGBA8／RGBA16F 与 D24S8。它是工具契约测试，不是客户端导出验收，也没有把合成快照作为实机证据。
- 计算工具保留 A/A、A/B 失败，缺组／缺样本／缺通过标记时，汇总器拒绝通过；内核计时不能作为完整链替换依据。计时门槛之外仍需编译、首次执行、程序数量、内存和客户端验收。
