实现了 GPU 射线命中归约、按完整身份读取小批量前后姿态，以及正常链包退休时的实际交还接线。CHAIN_READY 仍关闭：实际拾取输入和服务端精确身份事务、紧急关闭姿态、移动光照、观察客户端、Iris/阴影等未完成。这不是 131072 活动包裹整帧验收。

## 查询契约

每个结果 128 字节，保留 long ID/generation、generic candidate、fixed-offset body、track、当前摆动/每 tick 速度/目标/进度，以及上一步位置/偏航/目标。它不改 64 字节通用粒子 ABI，不占额外粒子槽位。身份同时核对 metadata 和已提交 admission；可见位来自成功提交。退休查询只能在显式请求允许退休、body 状态为 -3 且 admission 已移除时返回。

四个独立请求上传/输出 bank 和四槽 staging 不覆盖未完成 copy。最多 256 个请求，正常释放仅扫描退休转换队列，不遍历活动总体。零超时 fence 轮询后才读取已完成 staging；槽满保留请求，超过两 tick 预算触发回退。程序替换全量编译后提交，失败保留旧程序。131072 容量下固定 GPU 查询缓冲合计 320KiB，另有 40KiB CPU direct 暂存，不包含 Java 解码对象和驱动开销。

GPU 射线归约使用共享内存，尾部无效线程也参加所有 barrier。命中盒与 Create targetPos 选择一致；数值测试对照 Minecraft AABB.clip。查询使用当前物理目标而不是画面插值位置，遵循 Create 原输入语义。

正常退休同时等待 admission 移除和完整姿态确认，再恢复 Create 成员、stock 交互缓存以及前后摆动状态。其他包裹继续更新不会覆盖退休 history；初始化路径仍写入完整 history。GL 异常、断线或立即关闭没有保证最后姿态完成，仍是未完成项。保存两帧姿态的数值检查不替代游戏中的时钟交接及视觉对照。

## 基准方法

RTX 4070 Laptop GPU，OpenGL 4.5，NVIDIA 581.15。每数量/模式预热至少 30 次且持续至少 1 秒，三组各 120 次。固定格点、完整有效身份和可见 admission；测试命中、未命中，以及分散读取 256 个候选。姿态固定，仅测查询组件，不测运动/堆叠，不允许用该场景替代活动物理验收。

GPU timer 覆盖 kernel、barrier、有效结果 copy 和 fence 提交；CPU submit 计时不包含 GPU 等待。timer 结果等待发生于验证程序；之后单独测量已完成 staging 的下载和 Java 解码。实际生产保持异步四槽轮询，没有该等待。decode 样本不含基准断言、native 世界修改或网络。没有旧 Create 整场景基线，不能把此表认定为整体提速比例。
