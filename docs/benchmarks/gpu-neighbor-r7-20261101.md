## 2. 已实现的路径

### 查询与 continuation

默认生产更新着色器保持原样。实验从当前发布的展开源码生成一个完整统一程序，仍由同一程序执行普通/MODEL 调度，增加前段和继续阶段；没有两域编译、羽毛独立程序或全量姿态缓存。普通分离在真实局部恢复后的原点和半径暂停；Dome 使用 MODEL 更新完成后的不可变候选位置，覆盖 solve/apply 的相对运动和速度预算。精确距离、接触、速度、伤害和生命周期继续由原规则处理。

结果带帧、阶段、资源代次、nonce、完整性与容量状态。消费前检查 CSR 边界、全部索引及对应关系。错误、迟到、超容或输入不合法时，整阶段使用无截断的完整参考查询，不消费部分结果。危险接触相等时以稳定身份裁决。诊断版本在 GPU 上按原池索引排序归约，排序成本包含在测量中。

| 后端 | 实际工作 | 判定 |
|---|---|---|
| `production` | 现有 OpenGL 生产链 | 默认保留 |
| `cuda-control` | CUDA 网格、完整候选及 FP32 复核 | 常规计算对照，不记作专用单元收益 |
| `rt-aabb` | OptiX CUSTOM AABB、自定义 intersection、精确复核 | 正确性准入；含 SM 工作，不能把全部时间归给 RT Core |
| `rt-triangle` | 静态三角形 BLAS＋动态实例 IAS，固定方向射线、FP32 复核 | 正确性准入；明确使用 TRIANGLE primitive |
| `tensor` | 保守分块 INT8 WMMA 距离广阶段＋FP32 复核 | 正确性准入；包含打包、量化、补齐、掩码与消费成本 |
| `tensor-control` | 与 Tensor 同分块、量化和输出的标量 CUDA 对照 | 区分 Tensor 指令与算法收益 |
| `copy` | 实际状态范围经共享缓冲、D3D12 COPY 队列传输后消费 | 字节复制正确性准入；完整链成本很高 |

三角形候选对原计划的单位盒表示作了具体化：每个保守盒使用一张足够大的出口面三角形，固定 +X 射线枚举；使用 `REQUIRE_SINGLE_ANYHIT_CALL`，避开盒面两三角形对角线带来的重复。独立参考覆盖面、边、角、重合、负坐标和远坐标，最终仍进行原 FP32 精确判定。没有把任意三角形命中直接当成物理接触。

`hardware-evidence.json` 保存 PTX 摘要和 `wmma.mma.sync.aligned.row.col.m16n16k16.s32.s8.s8.s32` 指令、RT primitive 及 COPY 队列证据。当前没有可用 Nsight 时间线或硬件利用率计数器，**不声称释放了多少 SM，也不声称已证明 GPU 并发**。

### 异步交接、所有权与默认成本

OpenGL、CUDA 和 D3D12 按同一 LUID 校验；D3D12 只分配共享资源、运行 COPY 队列和 Fence，不替换 OpenGL 渲染器。三槽环只读输入、临时结果，工作线程处理 CUDA 等待与完成通知。渲染线程不执行阻塞式 CUDA 同步；到当前帧消费者时仍可能有最多 50 ms 的主机等待，再转完整参考查询。等待本身计入成本，不能因此称为无等待异步。

Iris 前阴影入口只提交可提前的普通查询前段；第一个粒子/阴影/视觉消费者再继续。修复了前阴影入口立即 join、导致合法重叠窗口消失的问题。Dome 依赖 post-MODEL 位置，目前仍在其正确消费边界串行完成。不能使用上一帧粒子或阴影换取重叠。

挂起/继续保存 SSBO、uniform、image、sampler 等状态；实验路径保护 8 个 image 单元，默认路径维持原 4 个，不额外查询实验状态。所有反馈与发布完成后才提交代次。退出、切后端、重载和换世界会取消或退休任务；未退休资源隔离，不能凭超时释放。清理异常不应反复中断健康 GL 生产链；GL reset 检查失败时中止发布。

受控原生缓冲及 AS 总预算 512 MiB，单槽结果不超过 64 MiB。客户端查询共享环为 96 MiB，COPY 环为 192 MiB；查询 continuation 另占 GL 约 152 MiB＋16 字节。驱动/模块内部不可见分配不在可精确核算项内。查询实验增加 7 个 GL 程序；COPY 不建立这些程序。普通构建没有准入回执，不加载原生模块或编译实验变体。

### 光流与编解码器

在同一 CUDA 设备实际创建光流 API/设备、NVENC 会话，并读取光流、编码与解码能力，不仅检查 DLL 是否存在。光流输入为图像对，视频单元为固定媒体数据流；本项目的三维候选、碰撞及权威状态没有满足现有接口且保持语义的替代工作。本轮未把二维运动估计、诊断录像或物理记录视频化作为粒子加速，未注册这些后端。NVDEC 探针覆盖 H.264/HEVC/VP9，不据此推断其他格式不受支持。

Tensor 位于 SM 内并共享其资源，RT 的 ray generation/候选处理和 BVH 维护也有普通计算成本；COPY 路径需与原 GL 复制对照，不能假定原 GL 复制没有使用 DMA。这些限制与官方 [Ada 指南](https://docs.nvidia.com/cuda/ada-tuning-guide/)、[OptiX 说明](https://developer.nvidia.com/blog/how-to-get-started-with-optix-7/)、[光流接口](https://docs.nvidia.com/video-technologies/optical-flow-sdk/nvofa-programming-guide/index.html) 和 [NVENC 接口](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/nvenc-video-encoder-api-prog-guide/index.html) 的职责边界一致。

## 3. 正确性与绘制证据

- 完整几何参考：4,570,887 项检查通过，覆盖空池、工作组边界、1千/1万/5万/65,535/65,536/131,072、全部非空查询、拥挤、重合、负/远坐标、边角、溢出及 refit。
- 五条查询路线分别完成 14 场景×96 帧，共 6,720 帧；检查速度、伤害只消费一次、死亡不重现、恢复、阶段、尸体倒计时、反馈及发布代次。固定输入对完整参考进行匹配，不要求复现旧截断轨迹。
- 每条路线另有 234 个小规模数量/场景/池组合、20 个大规模组合和容量回退测试。CUDA/AABB 首轮有 5 个“普通池恢复也必须含 MODEL”夹具错误；保留原失败，修正为按实际 MODEL 数判断，并保存对应复查，不能把原失败记录删除或冒充全部首轮通过。
- `consumer-proof` 每条路线验证 3,163 个 Dome 原生行被实际消费；普通 continuation 状态也核对未静默拒绝原生 CSR。generation/overflow/incomplete/offset/id 五类坏结果均触发整阶段参考路径。
- 四份真实快照×五条路线共 20 次更新边界回放通过，查询数量分别为 54,983、65,527、65,525、65,526。检查稳定身份粒子多重集、状态、计数、成员映射、分配器和动画槽配对；范围不含历史完整主链。
- 异步安全测试 3,366 项通过：初始化失败、15 个三槽任务、代次拒绝、500 ms 延迟/50 ms 超时隔离、非阻塞关闭及最终退休；受控原生存量归零。COPY 对实际 25,234,080 字节状态银行、三个生产复制范围进行逐字节验证，另测超容、迟到及间隙不被修改。
- 完整命令记录对四种合成物理链进行独立资源重建与五路线回放，共 20 项通过。最终状态挂起/恢复及命令往返回归 59 项通过；命令行回放入口另做烟雾测试。
- 绘制使用相同粒子输入，原生及现有八包、1920×1080/2560×1506，核对覆盖、身体/持剑/透明、关键帧、受伤、尸体、六剑、混合与全部附件/深度。八包共 4,956,340,332 次断言/字比较；这不是独立场景数量。Complementary 另恢复 402 项实际选项/宏/附件上下文，其他包为测试默认选项。原生实际 RGBA8/RGBA16F＋D24S8 格式回归通过。没有扩大片元 AST 裁剪规则。
- 最终 `test build` 通过，1,012 个 Java 测试；Python 工具回归结果见 `python-final.log`。

原生产 Dome A/A 和 COPY 完整物理回放中仍存在原子顺序导致的 FP32 末位差异，分别保留在原始记录中；Dome 查询插桩出现的已知差异与生产 A/A 同位置。它们不算新算法逐位等价通过，也不抹去独立候选完备性、状态复制和物理规则验证。

## 4. 完整成本与失败结果

查询路线进行了 15 个独立进程：五路线×三轮；每轮每个负载预热后分别采集生产 A/A、候选 A/A、生产/候选 A/B，各 64 对交错样本。数量为 1千、1万、65,536、131,072，场景为普通与 Dome 攻击，使用成对岛状分布。全部准备、状态处理、原生维护/查询/排序、同步等待、参考回退、继续、反馈与发布成本计入。

汇总为 40 个 GPU 指标负载单元和 40 个 CPU 指标单元，**GPU 单元没有一个在三轮均通过净收益门槛**。以下仅为 65,536 普通 MODEL 成对岛状场景的“三轮各自 p50 的中位数”，单位 ms；每路线使用自己的匹配生产样本：

| 路线 | 生产完整链 | 实验完整链 |
|---|---:|---:|
| CUDA 网格 | 0.4946 | 12.5588 |
| RT AABB | 0.5192 | 10.3148 |
| RT triangle | 0.5064 | 13.3504 |
| Tensor | 0.4296 | 24.4936 |
| Tensor scalar 对照 | 0.4332 | 26.6138 |

这些例子的回退次数为零，不能把变慢全部归因于回退。GPU elapsed 覆盖交接和空等，不是纯 SM 忙碌时间。Tensor 比其标量对照快的局部事实，不能抵消其相对生产完整链的额外成本。不能把这些合成约 0.5 ms 的生产样本和原日志约 2 ms 的更新样本直接比较，或换算为实机 FPS。

另保留初筛密集分布中约 291 ms 的 AABB 完整链失败：受容量限制而走无截断参考，并非 RT 查询本身耗时。旧约 9 ms refit 退化和旧几何序列中的局部收益继续保留，未用它们替代本轮完整链结果。

COPY 完整链三轮、两场景、同样 64 对 A/A 与 A/B：星落生产 p50 约 0.832–0.905 ms、COPY 26.448–28.081 ms；Dome 攻击生产约 1.045–1.101 ms、COPY 26.358–26.973 ms。均没有稳定净收益。原始 CSV 保留很大的候选 A/A 噪声，结果不可宣称低成本异步传输。字节正确不等于整个浮点模拟逐位一致。

因此没有组合这些已明显增加离屏关键路径成本的路线来宣称组合收益，也没有更改默认生产路径。按本轮新准入规则，离屏稍慢本身不禁止正确的客户端实验；交付的显式选项让真实地形竞争裁决实际帧时，但不能预设专用硬件一定减轻客户端压力。

## 5. 捕获、归因与后续输入

`profile frames` 保持兼容，增加同帧实际后端、准入/引擎摘要、相机/FOV、自动节流、资源代次、提交/阴影数量、CPU 攻击阶段与硬件任务侧表。未知数量不借用旧代。准备/恢复/普通/MODEL/接触/解穿透/导航/发布、绘制父范围和 Iris 实际阶段身份分开记录；父子区间不求和，`sky.pack-stage.*` 不再解释成云层独占时间。

`profile capture` 新 schema 3 记录 CPU 上传、实际 SSBO/纹理别名、raw uniform、程序二进制/展开源码、复制、清空、调度、屏障与发布；有界 512 MiB 异步冻结，缺资源、未知 uniform/UBO 或不支持的纹理状态直接标无效。`validate_chain_capture.py` 与 `replayR7ChainGpu` 拒绝旧快照冒充完整记录，程序二进制绑定实际 GPU/驱动。

`profile querysequence` 新 schema 3 补齐普通实际局部原点/半径，以及 post-MODEL Dome 候选与 solve/apply 边界。`prepare_r7_actual_sequence.py` 只导出连续、稳定拓扑和共同有效身份的输入，保留实际半径；GPU 适配器已使用明确标注的 16 帧合成输入验证全部九种重建/refit 路径。此短适配器测试不是三轮性能成绩。已有两条客户端序列为 schema 1，只覆盖读取池，不能用于实际局部半径或扫掠周期判断。用户采到新序列后才能裁决每帧/4帧/8帧周期；目前没有据此开放客户端周期切换。

`compare_client_frames.py` 要求三轮独立进程、生产与候选两侧 A/A、匹配相机/选项/源码/回执/数量/攻击阶段。每窗至少 30 秒且 1,000 帧；整帧 p50 收益须同时超过匹配噪声、1% 和 0.1 ms，p95/p99 不稳定退化。正确性双跑、插桩和能力探针不进入 FPS 成绩。

## 6. 交付与用户验收

交付脚本 `scripts/particles/package_r7_delivery.py` 在正确性、绘制、构建及索引/源码校验后向诊断分发 JAR 的内部模组注入准入回执；普通构建不含回执。回执绑定 GL 4.6 设备上下文、编译类、当前展开源码、变体、DLL 和 SDK。安装器在隔离假游戏目录验证重复安装，开发资源覆盖只做准备测试，不启动客户端，不改真实 `run/config/mods`。发布文件不覆盖旧包。

- `build/distributions/createmanaindustry-0.2.7-hardware-diagnostics-r7-20261101.jar`
- `build/distributions/cmi-r7-client-20261101.zip`：诊断 JAR、可选运行时、锁定头文件/许可和安装器。
- `build/distributions/neighbor-r7-results-20261101.zip`：源码、初始冻结、实际历史输入、新原始成功/失败记录与回归结果。
- `build/distributions/neighbor-r7-provenance-20261101.json`：源码/证据/包 SHA-256、回执和不替换生产的结论。

工具链沿用 OptiX 9.0、CUDA 12.8 Update 1/NVRTC 12.8.93；媒体头文件另以固定提交和 SHA 锁定。不升级驱动，不成为普通构建必需依赖。能力探针设备为 RTX 4070 Laptop、CC 8.9、581.15 驱动、一个异步引擎。

操作步骤与完整命令见 `gpu-neighbor-r7-client-20261101.md`。先做 Complementary 水平地形重负载的匹配 A/A、A/B，再分别做向上、向下；随后 Photon、iterationT 与其余包。相机朝向之间的成本不相减。实验需关闭 `autoThrottle` 保持数量/装饰与合法提前提交窗口；每次切换都使当前窗口失效。

用户负责执行新轨迹画面、真实多帧玩法、全部包实机画面、切包、F3+T、换维度、初始化失败和释放验收，并返回新日志/帧时/完整捕获/连续输入。其余六包离屏默认选项回归不代替它们实际选项的客户端验收。只有正确性、画质与实机整帧收益全部通过后，才有依据考虑生产替换。
