# 包裹总网络带宽验收约束（2026-10-01）

**范围变更：用户随后将网络带宽优化从本次目标排除，采用现有方案，进一步优化留待后续版本。以下 1.5 倍约束及样本保留为后续工作的历史基线，不再作为本次验收或运行时门禁。** `PackageNetworkComparison` 继续如实区分证据不足和超支，未测完整连接不会改成通过；`PackageNetworkBudget` 现仅显示延期状态。双端 opt-in、资源覆盖、可见提交、身份和回退检查独立保留。

用户最新要求：GPU 包裹的总网络带宽必须不大于同场景 Create 原生包裹的 **1.5 倍**，替换此前的一倍限制。比较同一时间窗口、包裹数量、运动负载、实体/风机力源、客户端及订阅区域，合计服务端与所有相关客户端双方向的实测字节。字节上限为 `native + floor(native/2)`；超过上限一个字节也不以计时噪声解释。判定采用不会溢出的整数比较，报告比例只是显示值。不得用关闭接管、静止替代活动负载或大量回退降低验收分子。

必须包含位置、速度、姿态、ground/lifecycle、物品内容与地址、生成/销毁、初始和迁移基线、ACK、能力与心跳、交互与交接、恢复、观察者成员信息及锁链 BE 消息。实体推挤与鼓风机的力源同步也需覆盖；当前实现复用既有原生实体/BE 数据，不新增专用力源包，但不能因此漏记既有流或后续新增流。保留的原生流同样计入；不能只统计新增协议，也不能重复计算同一原生消息。完整连接验收还需包含实际打包、压缩、加密和传输开销，不能以未压缩 payload 或预估停发量代替。

内部 `PackageNetworkComparison` 将比较结果分为 `PASS`、`OVER_BUDGET`、`INCOMPLETE`、`WORKLOAD_MISMATCH`。其输入区分协议帧与实际连接流量，并要求每个流量类别有完整覆盖证据，包括确实没有事件而测得的零值。活动包裹时间必须达到固定场景要求；GPU 一侧只计实际 GPU 模拟时间，Create 回退不计入该指标。输入检查拒绝负数、溢出和不匹配场景。它是报告判定工具，不是网络抓取实现，也不会打开生产门禁。

`benchmarkPackageBatchNetwork -PpackageNetworkFraming` 现在另生成 `build/package-network-acceptance.csv`。旧 framing CSV 的数字保持不变；新增报告明确标记保留流和假设停发两个案例，未采集的流量与实际 GPU 活动时间继续缺失。因此假设停发后比例小于一也只能得到 `INCOMPLETE`，不能认定达标。

按 1.5 倍新上限重跑 384 个组件案例：15 项组件字节超支，369 项证据不完整，零项通过。原相对帧 CSV 与归档逐行一致，编码及字节数未因上限调整而改变。判定测试加入 1.5 倍相等、一字节超支、奇数基线、最大整数及力源类别遗漏。原始判定见[CSV](package-network-acceptance-2026-10-01.csv)。这些判定不等同于完整连接流量采集。

此前 131072 包裹、异速 XYZ、单客户端、三秒、阈值 256 的位置组件结果：原生位置帧 33748520B；实验 predicted 上行 9647704B，ACK 4319B。保留原生位置流后合计 43400543B，为原生的 1.286 倍，低于新上限，但完整消息与连接证据未覆盖，属于 `INCOMPLETE`。当时假设取消权威原生位置下行后的 9652023B / 0.286 未计入新的可见确认，也不能作为当前版本总流量。默认 relative 的原保留流比例为 2.157。不能把实验 predicted 切成默认或把组件案例标成完整验收通过。
