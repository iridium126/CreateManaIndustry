服务端另外检查有效名单必须等于完整名单减已确认死亡／退出；客户端同一反馈先发退出确认，再发就绪。协议由 17 升为 18，两端须升级重启。Dome v4 与 Helix v1 模板的 Git blob 与基线完全相同，存档格式未改。

## GPU 场景与计时方法

使用 RTX 4070 Laptop GPU 的隐藏 GLFW 上下文运行生产内核。Helix 矩阵覆盖横移、绕圈、折返，10／20／60／144／240Hz，0／50／100／200ms 延迟及不规则步长／抖动。检查固定 START 预算、完整分母、三帧实际就绪、反馈版本／时间及 LOCK 连续性。本轮60组实际发动为7.5875–9.5833秒，固定预算29.2秒，每组分母均为4096。独立检查恢复收包、重复快照和双 bank 回滚。

完整Dome生产场景在11.05秒发动，11859名参战，最终12288名完成退出；记录的最小中心距0.3791格、2帧小于0.4格，仍高于既有0.34格接触阈值。该数值不代表剑翼动画无交叠，观感仍需实机。

排队回退检查安全绕行、原请求保留、方向滞回和封闭地形下 18 格／秒²制动；路径检查移动后安全接入、跳过前部转折点、目标漂移和旧窗口失效。混合搜索使用四个 Dome 的 400 个请求和 128 个归队请求，验证 96／32 保留额度、128 在途上限及 8192 节点上限。

混合搜索组件采用相同初始 GPU 状态做三轮、每轮 40 次预热和 120 次计时。GPU 内复制固定输入发生在计时区间外；GPU 时间仅包含调度和搜索，CPU 时间仅包含对应提交。该固定输入组件不代表完整游戏帧时间。回退探测单独计时。完整风暴基准使用 131072 名成员、四个 Dome、64 根星柱及 100 名玩家，coherent／pressure 各执行三轮，与基线比较相同二进制输入。
