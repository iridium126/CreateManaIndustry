## 实验实现

实验源码由 `prepare_neighbor_r6.py` 从冻结基线生成到独立目录，生产 GLSL 没有替换。

1. 无截断完整枚举、保守球—格裁剪、哈希桶去重。Dome 保留速度预算和扫掠计算，外层范围向外扩展；危险接触平局按稳定身份裁决。
2. 计数、分块前缀和、散射的连续桶；比较 2.5、扩大哈希、1.25、1.0。32 字节条目保存位置、成员身份、完整格键和池索引。格键过滤哈希冲突；索引带阶段、代次和有效标记。溢出走完整、无截断的旧存储参考查询，整次阶段不消费部分索引。
3. 空间排序、阶段排序、Dome 邻居内 owner 纯查询复用，以及组合版本。排序保留池索引与动画槽的完整配对，不改变透明绘制排序。owner 局部复用不缓存导航、接触或完成状态。

当前连续序列格式只记录恢复后读池的位置、速度、稳定身份和池索引。它是广阶段几何输入，尚不包含实际局部恢复后的全部查询参数和物理 continuation 状态。

## 三轮性能筛选

真实更新调度为 3 进程 × 3 快照 × 9 组（含 A/A），共 5,184 对样本。合成完整链为 3 进程 × 6 场景／数量组合 × 13 组，共 14,976 对。每组预热后交错 64 对。原始 CPU 提交及 GPU 时间均保留。

噪声采用匹配 A/A 成对绝对差的 p95，属于保守初筛；同时检查 0.5%、0.002 ms 和尾部。部分完整链 A/A 噪声很大，不能把未超过噪声的差值当作收益或稳定退化。

编译时间保存在日志中，原生初始化、内存及首次执行记录在 metadata 中。更新变体的冷首次执行和寄存器／内存详测尚未补齐，不能把这些初筛记录称为完整发布验证。

|候选|真实更新调度观察|完整链／决定|
|---|---|---|
|完整链表、裁剪链表|三快照约慢 29%–48%|部分小场景有利，其他场景退化；撤回|
|连续 2.5、扩大哈希|约慢 50%–69%|没有整体收益；撤回|
|连续 1.25|一份约慢 9%–10%，另外两份接近噪声|不合格|
|连续 1.0|约快 6%–15%；一份尾部未过门槛|65,536 普通成员完整链约 0.63→0.94 ms，明显退化；撤回|
|空间排序|约快 36%–42%|65,536 普通成员约 0.63→0.52 ms，但小负载约 0.10→0.14 ms；三轮整体门槛不通过|
|阶段排序|约快 5%–21%，部分窗口未超过噪声|没有整体合格收益|
|Dome owner 复用|更新调度源码不变|接触完整链收益不稳定；撤回|
|1.0＋排序／局部复用|另做正确性插桩|普通完整链约 0.63→1.00 ms，Dome gather 约 1.38→1.73 ms；不组合发布|

这些数值的场景、输入和范围不同，不能相互相加，也不能换算客户端 FPS。不能以较慢的新参考路径作为最终比较基准。

五个第二轮进程曾因新原生回放工具漏接 Java 编译源而未启动。依赖已修正，原失败日志保留，以新的 `.retry.log` 补跑；不存在用失败进程填补样本的问题。

## 正确性证据和限制

- 三份真实快照中，完整裁剪、1.0 网格、排序组合及容量不足回退完成了实际局部查询原点下的分离力检查；每种覆盖 171,847 个有效查询。以独立完整邻居枚举、FP64 累加和 FP32 误差界判断，最大力差约 `1e-5`。
- 重合处理沿用原 GLSL helper。大角度 sin/cos 的 CPU/GPU 差异曾造成错误 oracle 失败，原记录保留；修正后独立执行原 GPU helper 校准该项贡献，不修改运动公式。
- 额外直接核对候选身份集合和原始入选次数，避免漏选被力抵消掩盖。1.0、1.0＋空间排序、容量不足回退，各在三份快照中覆盖 1,340 个抽样真实查询及 23,844 对相关成员，未发现缺失、额外成员或重复。
- 合成完整链初筛覆盖空池、65、1,000、65,536 MODEL 的 ordinary、Dome gather、Dome attack，检查身份、有限值、单帧 HP／死亡、材质归属和普通速度约束。生产 A/A 的状态、位置及浮点差异独立保存，未当作新算法通过证明。
- 连续采集内核通过 1,620,776 项真实 GPU 检查，覆盖 0、1、63/64/65、255/256/257、1千、1万、5万、65,535/65,536、131,072 和失效代次、非法池索引。

上述检查不是完整多帧物理验收。伤害、重复事件、穿透、恢复、发布代次、新轨迹质量、完整极端分布矩阵及八包两分辨率绘制门槛尚未通过。候选已因成本门槛撤回，未继续宣称其具备生产正确性或画质资格。

## Clock、CUDA 与 RT

`clock-captures/clock-summary.json` 按真实输入成员分为 ordinary、未分配 return、Dome、Column。Dome 的分离访问数为零，仍可能有较长 invocation clock，说明混合分支、warp 等待及插桩扰动不可忽略。嵌套 terrain 与 whole-update 时钟不得相减、相加或转换成毫秒。此次没有据此改写地形物理。

使用缓存中的 OptiX 9.0、NVRTC 12.8 依赖重新跑了三轮真实读池几何查询。每份快照查询 1,024 个成员，独立核对完整候选集；记录 GL、CUDA 网格、RT build 和静态 refit 的 GPU 时间及含互操作／同步的完成墙钟时间。

第一轮静态 refit GPU p50 约 0.49–0.53 ms，对照几何 GL 为 0.62–0.86 ms；RT build 为 0.92–0.96 ms。CUDA 在不同快照间有得有失。这里只查询 1,024 个成员，不能外推 65,535 个更新成员，更不能推导整帧收益。R5 移动几何约 9 ms 的 refit 失败证据继续保留。

每帧／每 4 帧／每 8 帧重建的适配器已实现并用明确标记的 16 帧合成移动序列验证。没有真实连续序列，因此未给出真实重建周期成绩；离散快照没有拼接为连续运动。尚无查询＋维护＋互操作的生产完整链净收益，未实现生产 continuation，也未开放实验 backend 命令。未引入 Tensor Core、编解码器、插帧或 Vulkan。

## 新诊断接口

保持现有用法：

```text
/cmi particle profile frames 30
/cmi particle profile capture complementary_low_A
/cmi particle profile querysequence complementary_motion_A 64
```

`querysequence` 支持 16–128 帧，3 个 GPU 读回槽、单写线程、有界队列；溢出、缺帧、上下文变化或失败使整段无效。它与 FPS 窗口及单次冻结互斥，默认不编译诊断内核。没有 GPU 等待式采集或降模拟频率。

帧窗口现在额外输出 `-stages.csv`、`-submissions.csv`：同 scene-frame 标签的输入准备、恢复、两次更新、接触、解穿透、导航、反馈、发布准备、绘制及项目天空效果；附带源代次、CPU／GPU 样本数。范围可嵌套，不能求和。未知值为 `NaN`／`-1`，不借用旧计数；金粒子没有独立同代 census，明确标记 unavailable。原生 MODEL 仅在诊断窗口内拆分三个子提交以归因。

元数据绑定实际生效的引擎源码摘要、后端、维度、资源代次与光影选项快照。关闭光影时保留 source=none、options=unavailable。GPU 时钟插桩不进入 FPS 数据。

单次捕获升级为 schema 2，新增覆盖范围、源码／选项关联和 TBO 范围。**它仍是更新边界捕获，不是完整真实链捕获**；preparation、recovery、contacts 等缺少的覆盖明确为 false。完整真实链资源／阶段配置采集与回放仍是未完成项，不能把本轮合成完整链或旧快照替代它。
