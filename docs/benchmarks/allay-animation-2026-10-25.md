# GPU 悦灵姿态与玩家快照

以`.refs/neoforge-21.1.227`中的`AllayModel`、`ModelPart`、`LookControl`、`BodyRotationControl`及悦灵持物／跳舞计数为依据。修正部件和跳舞根节点为`T · Rz · Ry · Rx`，保留几何、枢轴与持物显示变换。普通MODEL和风暴成员共用独立动画状态；燃烧室内原版实体不经过此路径。

## 状态与距离

动画以20Hz记录身体偏航、头部相对偏航／俯仰、水平移动强度／累计相位、持物进度及独立舞蹈计数，渲染只插值已提交端点。跨tick用指数衰减和几何级数闭式累计，不逐tick追赶。高帧率的运动采样折算到最后一个完整动画tick，插值以已存tick为起点，避免GPU浮点融合在整数边界造成相位跳变。停留不再按粒子年龄持续自转，死亡清零移动动画并保留动画年龄。

普通观察每30–60tick寻找6格内最近有效玩家，持续45–90tick，按稳定实体ID保留目标，越界、消失或遮挡时结束。攻击成员看所属攻击目标的眼位。头部每tick最多转10°，移动时头身差最多75°，俯仰使用眼睛连线并遵循原版负值朝上规则。持物以实际显示条件触发，举起和放下均为5tick。跳舞进入独立计时，退出重置，包含55tick周期及旋转进度衰减。

玩家表保存眼睛坐标、稳定ID、脚点及身体中心高度偏移；每帧仅CPU更新玩家与至多68个攻击目标，不逐成员更新。观察和Dome／Helix持剑使用实体脚点之间的三维距离，包含6格边界；持剑仍受原攻击阶段约束。排斥力、反馈继续使用身体中心及原作用半径。脚点空间索引对身体中心查询扩大垂直邻格，覆盖游泳、蹲伏、缩放及超过16名玩家。普通MODEL活跃时也上传该表。

Dome、Helix和星雨保留专用编队／飞行覆盖。公共归队身体缓存仍仅由实际GPU局部寻路触发；重新远离队形不单独启用，新攻击结束旧覆盖，头部观察独立控制。

## 独立存储与提交

通用粒子 ABI 保持64字节。首次需要 MODEL 时，一次性创建262144个64字节动画槽的两个 bank，动画本体固定 **33,554,432字节（32 MiB）**，不随主池容量扩张。之后保留到粒子池销毁；世界／池重置清空状态。没有 MODEL 时不分配动画或分配器，MODEL 列表仍有固定成本。

密集 MODEL 列表保存 `(主池槽位, 稳定动画槽号)`，包含视锥外成员和尸体。每帧仅压紧运动与列表；现存成员的动画槽号不变。双缓冲列表在默认200万主池下从2 MiB增至4 MiB，**增量2 MiB**，不包含原有 STORM 子列表。分层空闲位图及退休位图双缓冲合计 **135,376字节（约132.2 KiB）**；每个候选帧只复制、合并这部分元数据，不扫描主池建立反向索引。

MODEL 最多262144个；生成同时预留动画槽和主池槽，失败立即释放本次临时预留并丢弃请求。尸体实际移除后才释放容量。退休槽随成功运动提交进入下一帧的可分配集合，候选撤销不会释放已提交成员的槽。风暴重建按成员退出回收，保留其他 MODEL。包裹粒子覆盖普通池尾部时，通过候选列表过滤回收被覆盖成员；临时列表复用排序缓冲。

动画具有独立 bank、采样 tick 和提交版本，以成功提交的模拟时间累计20 Hz时钟。运动、接触修正和生成后，从候选 MODEL 列表读取最终输入；跨多个 tick 只执行一次闭式更新。未跨动画 tick 时，已有成员动画记录零写入、零复制、零 bank 切换。新生仅在安全空闲槽初始化两个副本，立即可见；撤销的新生没有已提交引用，重试前重新初始化。暂停和候选撤销不推进已提交时钟。

排序键低9位保持原含义，高位携带18位动画槽号；原 payload 保留主池槽。原生模型、持物、阴影和 Iris 直接解码槽号，共用动画 bank 和插值系数，不增加顶点阶段列表查询或状态积分。计算边界保存／恢复四个 image 单元，资源重载原子替换程序。不改服务端配置、网络协议、运动、碰撞或攻击判定。

风暴 GPU p95 约下降4.3%；满 MODEL 约增加45.1%，混合约增加30.7%。独立20 Hz采样把现存成员的动画写入集中在采样帧，额外列表派发和独立内核也有成本。因此本实现节省显存及记录写入，不能称为普遍降低尾部耗时。无 MODEL 仍有约0.005 ms GPU p95增量；CPU提交各组也略增，包含工具绑定与检查开销。

180个120 Hz采样帧内，风暴／混合的动画记录写入从720 MiB降为120 MiB，满 MODEL 从2880 MiB降为480 MiB，均为原来的1/6。该字节数由实际提交动画 tick 数与记录大小计算，不含位图、列表或运动写入，也不是GPU硬件带宽计数；GPU写入计数专项独立验证非采样帧现存成员零写入、新生双副本初始化与采样帧更新。

## MODEL 不可见修复

真实客户端反馈所有 MODEL 不可见。沿生成、列表发布和下一帧运动链检查，发现 `ParticleRuntime` 在发行命令／外部计算程序仍为 current 时，调用基于 `glUniform` 的 setter 设置 `prepare_dispatch` 的 `uModelMembersPublish`。uniform location 属于目标程序，却被用于当前程序；测试设备上没有 GL 错误，但目标发布开关仍为0。新生可短暂写入物理池，但列表计数未发布，绘制实例为0；下一帧通用更新跳过 MODEL，MODEL 更新又拿不到列表，成员随即丢失。

将发布开关和 phase 1 派发集中到 `ParticleDispatch.prepareModelPublication`，通过 `glProgramUniform1i` 直接设置目标程序。普通发布、包裹前发布及包裹后的只刷新分支都使用该边界。没有改变槽容量、动画时钟、运动或着色器算法。

此前隐藏窗口工具直接设置了目标程序的 uniform，因此存储／数学回归通过仍未覆盖真实调用顺序。新增回归保持发射程序、方块发射程序或 program 0 为 current，再调用生产发布方法；覆盖普通 MODEL、方块 MODEL、实际 style 3风暴解析生成、混合普通粒子及包裹刷新，检查列表、主池、绘制计数和下一帧存活。旧顺序的失败日志保留在 `build/model-publication-repro.log`，修复后存储与发布502,017项、成员列表1,015项、原版姿态11,719项、原生／Iris阴影4,133,608项及程序生命周期575项 GPU 断言通过，记录在 `build/model-visibility-final.log`。该修复涉及 Java 调度，需更新构建并重启客户端；资源重载不能替换此逻辑。
