## 需要优先收紧的验证问题

1. `summarize_feather_merge.py:77` 用
   `m.get('repeat_regressed', m['regressed'])` 生成最终退化列表。只要提供复测，
   初次判定就由复测布尔值替代；源码相同、输入一致、样本完整和异常是否真正
   得到解释，不是这一步的必要条件。已交付 Photon 异常有“同一 GL 程序＋独立
   A/A＋未重现”的具体证据，但这个通用规则不能推广到源码改变的包。
   建议分成“初始异常／复测结果／已解释／未解决”，保留所有标记，未解决项
   阻止自动替换；只有同源码控制或独立且充分的校准才能显式解除。
2. 同一工具 `:51` 在缺少 `production.csv` 时直接使用空列表，缺少完整 MODEL
   数据也可能得到 PASS；也未检查所有预期 MODEL 输入组。建议区分“羽毛局部
   收益”和“整体替换门槛”，后者强制要求两分辨率完整 MODEL 数据、完整 A/A、
   编译／首次执行／程序数量，失败时返回非零退出码。当前已交付有 48 组完整
   三段 MODEL 辅助记录，但不是完整两分辨率负载矩阵。
3. `ParticleDiagnostics.java:85` 的包名取当前 Iris 状态，源码／选项却取缓存的
   ShaderPackSession。日志已出现 `pack=off` 仍带旧 Solas 源码和选项；工具提取
   已明确非活动，但运行时显示尚未消除歧义。建议绑定同一活动 pipeline／会话
   快照，关闭包时显示 source=none、options=unavailable；查询保持只读。
4. 本地默认选项与七个实机哈希均不匹配。正式扩大材质分支裁剪前，应从实际
   生效的选项值导出可重放快照，记录源码、维度、宏与选项哈希；不能只凭哈希
   反推出值。现有 FP32 MRT 合成夹具适合严格数值比较，但其附件带宽、世界光照
   和混合条件不同于客户端，需另用原生附件格式测性能。

R3 一些收益仅略超过 0.002 ms 的绝对门槛，小结果容易受计时粒度、温度与频率
漂移影响。建议针对这些组加长单次计时工作量并交错独立进程轮次，保留原始
记录；不能通过扩大噪声包络或选择单次复测自动消除不利结果。

## 下一步优化顺序

### 1. 优先定位并减少 MODEL 更新的只读重复工作

最新实机记录的 MODEL 更新 p50 约 1.68–2.08 ms；普通更新示例仅约 0.07 ms。
羽毛绘制仅 0.030–0.081 ms，继续在其片元上争取 1% 的整帧上限很低。
身体与透明层在 Complementary／Solas 仍重，但计算热点不依赖可见绘制数量，
应单独研究，不能通过画面裁剪跳过模拟。

首个低范围候选是 **一次 MODEL 调用内复用只读攻击上下文**。
`update.comp:330` 之后多个块和 `chunks/storm_motion.glsl` 反复读取
`cmiStarAssignment(p0.w)`、成员、slot/base、攻击类型；
`starfall_identity.glsl:7` 中 assignment 实际会读取 StarfallData，类型查询又会
读取对应记录。成员／assignment／slot/base／kind 和不变时钟可以在确定有效后
懒加载复用，保留当前精确时钟与向量读取方法。

这是候选，不是已证明的加速：驱动可能已经消除部分重复读取，扩大局部结构也
可能增加寄存器压力。不得缓存本次调用中被修改的 starStateWrite 阶段／接触／
完成状态，不能把中途状态改变前后的读取合并。先比较寄存器、溢出、访存与
完整 MODEL 更新 GPU 时间，再决定是否保留。

同时在诊断夹具中区分普通风暴、星落、螺旋、穹顶、尸体、碰撞缺资源和攻击
阶段边界，不在生产运行时关闭任何规则来制造收益。

### 2. 根据实际事件分布选择结构优化

`chunks/model_damage.glsl:15` 对每个 MODEL 扫描伤害队列；若队列长期非空，
可研究按稳定身份建立事件范围，保持原队列顺序、重复伤害、死亡裁决和非风暴
身份代次。需要先记录队列长度分布；空队列下没有理由增加索引构建成本。

`chunks/storm_motion.glsl:160` 的 27 格链表遍历在拥挤分布存在访存风险。
先统计访问数、有效邻居和预算触顶比例；穹顶成员已跳过此处，不应把穹顶热点
归因于这段循环。若确为瓶颈，再研究等价布局／读取局部性。不能减少 256 访问
预算、改变邻居选择或调整分离力来换性能，这些会改变模拟。

普通域在材料拒绝前读取四个粒子 vec4，可试验延迟非必要读取及复用材料行，
但驱动可能已做调度消除；这只能作为测量驱动的小候选，优先级低于 MODEL 热段。

### 3. 绘制继续聚焦身体与透明层，羽毛保持当前保守路径

先复现实机选项和附件带宽，再对相同数量分别改变分辨率与覆盖面积，对相同
覆盖面积改变实例数，判断顶点、片元或带宽成本。随后只扩展可证明恒定的上下文
裁剪，不改 native 采样、导数、alpha test、逐附件混合及输出编码。

本轮没有理由重推羽毛独立程序、索引四角、提前 alpha discard、深度预通道或
全量姿态缓存；已有失败与兼容性风险应作为下一轮的边界，而不是每轮重复尝试。

### 4. 每项候选独立通过门槛

冻结新一轮当前交付基线，逐项 A/B 与完整 A/A 后再组合。计算必须测生产两域
调度、切换、屏障、接触、导航和发布的完整 update，并按稳定身份比较粒子、
离散事件、伤害与反馈；绘制必须测完整三段和全部附件。三轮方向一致且超过
匹配输入噪声，其他包与负载无稳定退化，才替换。同步检查编译、首次执行、
程序数量与内存；客户端画面和整帧仍由用户验收。
