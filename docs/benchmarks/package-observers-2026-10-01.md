# 自由包裹观察者下行微基准（2026-10-01）

## 结论与验收范围

自由包裹服务端的提交日志、预算化订阅协议和原子参考消费端已有实现及测试。优化降低了实际日志、packet 编解码和参考状态提交中的 CPU 耗时、分配量；静止成员不产生批次。不过 131072 个成员全部改变位置时，当前 CPU 参考链路仍需约 **38.9–45.4ms p95、56.5MB/波**，不适合直接作为目标规模的观察者生产路径。

当前游戏客户端没有自动订阅，未接入观察者 GPU 姿态、可见槽位确认和原生同步抑制，Create 自己的观察者渲染及同步继续工作。锁链观察者、Sable 父结构轨道、实际多人网络及 131072 活动包裹整帧/服务端 tick 验收未完成。这里的 CPU 数值不能称为游戏帧时间或 server tick 时间。

## 方法与原始数据

本报告 CSV 测量的是 v1、无服务端确认时间的协议。之后 v2 加入公共 tick/共享或逐记录 age，并修改离线入口保留单调确认时间；下列历史性能和字节不代表 v2。v2 与原生包格式的单独对照见[网络 payload 报告](package-network-payloads-2026-10-01.md)。

同机 JDK 21.0.8，通过 `benchmarkPackageObservers` 在单 JVM 顺序执行服务端日志更新、实际 `ClientboundPackageObserverPacket` 编解码和 `PackageObserverReplica`。每组初始化精确成员数，先导入完整基线；预热至少 0.5 秒/七波，测量 0/1% 变化 256 次、100% 变化 32 次，重复三次。位置按固定索引分布，速度固定 1 block/s，模型/尺寸相同。最终版预热后重置到 wave=1000，测量值从 wave=1001 开始，不因预热吞吐改变实际编码值。没有 CPU 物理、回退、GPU、socket、服务端 entity.apply、Minecraft tick、渲染或自动节流。

所有变化由日志逐条接受，包通过真实 codec 往返，每批最多 128 条；参考消费端排空整个波次并核对最终数量与状态。这是测量全波成本，**没有用生产的 0.25ms 预算分割结果来降低报告耗时**。生产预算可能造成积压重建，尚未进行实时网络负载验收。

- [最终汇总](package-observers-2026-10-01.csv)、[最终逐样本数据](package-observers-samples-2026-10-01.csv)。
- [首版汇总](package-observers-before-2026-10-01.csv)、[首版逐样本数据](package-observers-before-samples-2026-10-01.csv)。

首版采用通用树合并、boxed 索引以及逐批身份覆盖表。最终版使用整数索引、可变内部 cell/不可变提交记录、复用 scratch、单调日志直接输出，以及只改姿态时的独立原子快速路径。基线/退休/重复索引仍走完整身份验证。两版数量、字段、量化、模型及批次上限相同；**首版未在预热后重置 wave，前后测量姿态值并非逐字节相同**，编码字节差约 0.2% 以下。因此这些数据证明该微基准中开销明显降低，不作为严格的游戏场景前后提速比例或网络压缩率承诺。最终源码现在固定测量序列，后续版本可以做严格复现。

## 已验证与后续工作

精确测试覆盖满规模分批基线、乱序完成接管、持续运动中的快照推进和 serial 区间过滤、字段独立性、合并/退休、快慢观察者并存、日志溢出重建、序号缺口、完整 long 身份及有界解码。服务端原提交组件验证失败回滚不把有效前缀发送给观察者。

最终 `test build --offline --no-configuration-cache -I scripts/particles/validation.init.gradle` 通过：57 个测试套件、281 项测试、0 失败/错误，Sable/companion 缺席门禁验证通过。三次最终基准全部核对最终成员数和 pose，构建成功；本轮未修改 shader 或 GPU 物理，未把 JVM 结果作为新增 GPU 验证。

服务端仅在真正 GPU_OWNED 后引入成员，lease 超时或释放会退休；额外 observer opt-in 不成为权威候选。默认日志惰性分配，大小有限且最后观察者离开后释放。调度按区域公平轮转，并在批次边界检查软预算。日志可容纳两波满规模变化，不能据此保证持续全变化流能在该预算下实时排空。

下一阶段需用该协议接入 GPU 基线合并/预测/插值，减少参考状态器与逐记录 Java packet 解码的热路径成本；补齐可见 admission 与原生同步抑制的就绪确认；完成轨道/时间基准的锁链观察同步及父结构坐标。最终仍需按原计划测量全部活动包裹、实际网络和多人交接。不能用静止结果、分批隐藏延迟或大量 Create 回退代替目标规模验收。

2026-10-01 后续：GPU 合并、预测/校正、紧凑变化上传、共享池导入及独立异步反馈组件已通过真实驱动验证，见 [GPU 微基准报告](package-observer-gpu-2026-10-01.md)。网络 controller 尚未接通，本文的 CPU packet 解码、日志和参考消费端成本仍存在，不能把 GPU 时间当成本文全链路的替代结果。
