# GPU 包裹物理与服务端校验优化

## 服务端校验

服务端每次处理位置批次都要复制网络 payload、解码数百条记录，并为验证与观察者发布创建临时列表和数组。位置、速度校验还会对同一候选位置重复计算三维距离；相对位置批次会为观察者再创建一份包装记录。

本次改动为每个世界复用解码列表和批次暂存数组。服务端解码直接读取网络包的只读 `ByteBuffer` 视图；防御式复制的 `changes()` API 保持不变。校验时缓存已确认速度和候选距离，提交阶段复用相同距离。观察者直接接收已合并的量化状态，内部成员以可变 cell 保存当前状态，从而移除每记录的 `Member` 替换对象与相对位置包装记录。校验仍在整批应用前完成，适配器失败仍按原逻辑回滚并撤销受影响租约。

`benchmarkPackageServerValidation` 测试 512 条相对位置记录，包含网络视图读取、解码、服务端校验、应用和观察者状态更新。每行是一次 1200 包测量轮次：

| 指标 | 优化前 3 轮中位数 | 优化后 6 轮中位数 | 变化 |
|---|---:|---:|---:|
| 每包分配 | 195,189 B | 118,246 B | -39.4% |
| CPU p95 | 203.0 μs | 173.1 μs | -14.7% |
| CPU p50 | 60.3 μs | 111.1 μs | 样本波动较大，方向不确定 |

CPU 单包计时受 Windows 调度和 JVM 预热影响明显：优化后 p50 单轮范围为 35–138 μs，优化前为 57–160 μs。分配量下降稳定；现有样本不足以确认平均 CPU 时间下降，p95 中位数改善也应视为初步结果。需要在游戏服上用固定包裹数量和 tick 时长继续验证主线程占用。

## GPU 物理与着色器

保留已验证的两轮支撑指针跳跃融合：将 17 次全量 dispatch 降为 9 次，并减少对应 SSBO 写入和全局 barrier；还保留 compute program 包裹数量 uniform 缓存。完整 RTX 4070 Laptop GPU 校验再次通过，12,299,275 项断言通过。131,072 包裹的 `support4` 重复基准 p95 中位数为 `aligned_still` 9.808 ms、`staggered_driven` 10.118 ms；跨运行差异较大，性能对比以 [物理基准记录](package-physics-optimization-2026-10-04.md) 为准。

尝试把融合扩展到三轮后，`movingCapacity` 穿透断言连续两次失败，因此已撤销。支撑传播会影响移动碰撞质量，不能仅凭 dispatch 数下降保留该改法。

## 验证

- `gradlew test`：480 项测试通过。
- `validatePackageGpu -PpackageStackBenchmark`：12,299,275 项断言通过，含完整 131,072 包裹栈基准。
- `benchmarkPackageServerValidation`：优化前后分别测 3 轮和 6 轮；每轮均成功提交 512 条记录。
