# 包裹空间索引与密集工作预算对照

2026-09-29，RTX 4070 Laptop GPU，OpenGL 4.5，NVIDIA 581.15。合成物理组件，**不含 Minecraft、绘制、网络、世界采集或服务端 tick**。真实接管门禁和所有新实验的默认选择仍关闭；本轮不能用于 131072 实际包裹整帧验收。

## 本轮实现

`IndexMode.EXACT_RANGES` 构建精确整数单元的连续 body 索引区间。以原 body index+1 为代表，GPU CAS 线性探测最多32槽，比较完整有符号单元坐标；插入失败表示未知，不表示空气。表容量为旧链式表的两倍，活跃单元负载最多0.5。计数后使用128元素、64线程的分层 Blelloch 排他扫描和偏移传播，再 scatter 到连续区间。不排序或搬动64字节 body、不改变身份或通用池映射，也不增加粒子槽位。

每个已占用精确单元只检查一次27邻域的总候选数，上限512。探测失败或总量超限，在 scatter 完成后的游标字段写 `GRID_OVERFLOW`。独立 guard 发布所有动态 body 的负 `previousSleep.w`，保留坐标和速度；静态占位保留。各 query 后续只遍历已证明预算内的完整区间。高速静态扫掠另检查整个扫掠查询范围，不能用仅27邻域的资格代替扫掠预算。哈希冲突不混合不同单元。

`IndexMode.BOUNDED_LINKED` 保留原链式索引，在扩展 heads 缓冲的后半部分保存桶计数。预算包括完整链表候选和哈希冲突；同一桶被查询多次也多次计入，保守限制实际访问量。每轮接触将预算检查合入原 kernel，超限 body 不开始邻居遍历；静态积分前及支撑建图前用独立 guard 发布回退。它可能因哈希冲突保守拒绝对象，不能当成精确单元分区。

两种回退均是 GPU 请求标记，等待真实接管适配器交还 Create；它们不自行调用实体或库存回调。邻居不静默截断，也不删除槽位/物品。131072 全部集中于一单元的测试验证请求回退，**不是通过物理/性能验收的活动场景**。原 `LINKED` 保留作对照，其密集输入仍可能平方级遍历，实际接管前不能忽略这个限制。

索引及 guard 仅读写 GPU 缓冲，不增加每帧 Java body 扫描或生产读回。工作空间首次使用时分配，完成验证后才触碰提交状态；分配失败清理候选。复用 SSBO 0–3、6–8，保持世界4/5及原 ABI。清空使用 buffer-update 屏障，GPU producer/consumer 间使用 SSBO 屏障；层次扫描的尾部线程参加所有工作组屏障。通过 include 编译独立范围/计数变体，默认 kernel 的实验分支可在编译时消除。

## 方法

- 三条索引都使用相同的四轮相对接触加支撑传播，20Hz、dt=0.05；几何、推力、材质、世界覆盖与前一份[支撑报告](package-stack-2026-09-29.md)一致。
- 10000、65536、131072；规则静止、错位静止、GPU 持续推力三种场景。448个已完整上传的 section，包括整个轨迹与负坐标 guard。
- 每组重置相同输入，预热50步、40个 GPU timer 样本，重复三次。每次轮换三种索引的执行顺序。下表取三组分位数的中位数，不能混用其他批次的旧结果作为本轮基线。
- timer 包含历史、积分、世界接触、所有网格重建/预算/扫描、四轮接触、支撑传播和活动推力。输入生成、初次分配/上传、检查器、timer读取、绘制、读回和网络在计时外。CPU 数据只代表异步 GL 提交，微秒分位数易受调度噪声影响。
- 独立 GPU 检查器重建原链式索引，完整检查27邻域所有真实接触对，最大穿透 <0.002、平面穿透 <1e-4、回退/非有限值为0。检查器不使用被测索引，因此不能因错误的范围划分漏掉同一碰撞对。

## 结论与实验记录

连续单元的正确性通过，但活动131072的 GPU p95 比同轮原链式高约39.3%，不能进入默认路径。计数方案以约4.1%的该场景 GPU p95额外成本约束最坏遍历量；它解决超预算请求，未证明普通负载提速。两者都保留为内部实验显式选择，不替代默认路径，也没有开启真实接管。

先前连续方案使用 uniform 分支与逐 body 的预算 guard，之后改为编译期变体/逐单元预算并扩大表，再增加计数方案，最后融合计数接触预算。全部原始结果保留：

- 最终：[81组摘要](package-range-kernels-2026-09-29.csv)、[3240个逐次样本](package-range-kernel-samples-2026-09-29.csv.gz)。
- uniform/逐body版本：[摘要](package-range-uniform-kernels-2026-09-29.csv)、[样本](package-range-uniform-kernel-samples-2026-09-29.csv.gz)，54组/2160样本；较小索引表，不能与最终版本做内存等价比较。
- 编译期/逐单元版本：[摘要](package-range-cell-budget-kernels-2026-09-29.csv)、[样本](package-range-cell-budget-kernel-samples-2026-09-29.csv.gz)，54组/2160样本。
- 计数独立guard版本：[摘要](package-range-guard-pass-kernels-2026-09-29.csv)、[样本](package-range-guard-pass-kernel-samples-2026-09-29.csv.gz)，81组/3240样本。

不同批次原链式131072活动 p95 中位数约5.78–6.27ms，存在明显机器状态/测量波动。不能把跨批次绝对耗时变化归因为某一次小改动；最终决策使用同轮交错对照，未把融合guard描述为已确认的跨版本提速。

## 验证与剩余工作

GPU 验证包含零/1/63/64/65/127/128/129/4097/131072计数、负坐标、完整范围前缀、scatter计数、唯一原 body身份、未写尾部哨兵及全16字段不改变；35个刻意同 hash 的不同精确单元触发32探测上限。两种预算路径覆盖511/512/513临界、131072集中单元与隔离对象、相邻单元合计600、513个静态占位，以及扫描范围扩大的高速静态扫掠。

两种新索引与原算法对照规则边界/错位/16倍质量比，姿态与运动全字段误差 <0.003；移除支撑后全部下落且最大接触穿透 <0.002。三种索引均通过131072持续 GPU 推力120步的全量计数、零回退和接触质量检查。物理数值检查不代替 Create 视觉录像。

最终带基准真实 GPU 验证 **12773247** 项断言通过；最终非基准回归 **12773161** 项通过。完整 Java **149** 项测试、Hex **135498** 项断言及构建通过。复现：`gradlew.bat validatePackageGpu --offline --no-configuration-cache -I scripts/particles/validation.init.gradle -PpackageRangeBenchmark`。

仍需不规则多接触堆叠、动态CCD、活动/休眠调度、预算反馈和真实幂等交还适配器。索引应在满足视觉和完整场景测量后再选择默认；不能用集中单元的大量回退代替131072活动包裹验收。真实Create生命周期、渲染/Iris/阴影、观察客户端和跨区域唯一所有者、实际网络与库存回归仍未完成。
