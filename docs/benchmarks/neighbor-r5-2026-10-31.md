## 已实现接口与正确性工具

- `/cmi particle profile frames <1..300>`：主帧 HEAD 间隔、交换前 CPU 墙钟提交时间、主帧 GPU 异步时间戳，平均 FPS 和 p50/p95/p99；记录尺寸、维度、限帧、VSync、光影会话、独立进程身份、输入时钟、CPU 攻击契约阶段、资源代次以及带原帧标签的延迟数量。GPU 成员阶段仍须从冻结状态读取，不能由 CPU 契约阶段代替。
- 菜单、失焦、换世界、改变窗口/光影/限帧、F3+T、资源关闭或重叠输入冻结使整个窗口无效。GPU 结果缺失保留为 NaN，数量缺失为 -1；不会拿上一帧“最新值”冒充当前帧。采样不计入粒子预算账本，不调用 glFinish 或等待未完成查询。GPU 范围覆盖交换前所有渲染提交，帧间隔包含交换与限帧等待。
- `/cmi particle profile capture <name>`：在 GENERIC 更新之前、准备/恢复完成之后复制绑定输入；随后回放必须先执行 GENERIC 再执行 MODEL。记录 SSBO、TBO、image buffer、3D 纹理、uniform 原始位、代次、程序二进制和上下文。异步 fence 完成后读取私有副本，后台写出 SHA-256 与最终 manifest。超过 512 MiB、GL/fence/映射失败则整份拒绝；不会发布可消费的部分快照。此操作及重叠窗口不进入 FPS 成绩。
- `neighbor_reference.py`：独立全量/相对线性扫掠候选、无截断分批消费、稳定身份危险接触平局裁决、FP64 求和及 FP32 加法误差界。普通分离保留尸体，接触查询可显式排除。真实物理必须提供实际提议运动与原接触规则；工具不会把当前速度外推当作完整物理回放。
- `replay_neighbor_capture.py`：验证已提交快照和每份数据摘要，导出 MODEL 点输入与有界候选流。它是查询回放工具，尚非完整攻击/事件回放器。
- `compare_client_frames.py`：核对三轮独立进程、每窗 ≥30 秒且 ≥1,000 帧、上下文一致、生产 A 基线、候选 B 后端身份、1% 和 0.1 ms 以及匹配噪声门槛、p95/p99。只有生产 OpenGL 的两窗不能伪装成 A/B；工具不授予物理/视觉替换资格。

CPU 提交是该范围的墙钟时间，不是 CPU 利用率；主帧 GPU 时间不含交换与限帧。捕获工具本身有开销，实机 A/A 需包含同样的采集方式。

## 独立查询原型

原生模块位于 `native/neighbor`，通过 `build-neighbor-rt.ps1` 独立 MSVC/CMake 构建，普通 Gradle 不下载或链接 CUDA/OptiX。锁定 OptiX 9.0 commit `a1280c1863ff19d87f8e827468a4cc906ba9032a`，CUDA 12.8 Update 1 的 NVRTC 12.8.93、runtime/driver headers 12.8.90，以及匹配 CRT 支持头。归档与 redistrib manifest 均校验 SHA-256。依赖在 `.gradle/neighbor-rt`，未升级驱动。

OpenGL 网格、CUDA 网格、OptiX 每次重建及 OptiX 持续 refit 共享相同点输入和半径语义：完整计数、64 位前缀、容量检查、写入 CSR 候选；自身/哈希冲突重复过滤。OptiX 使用向外舍入 AABB，遍历所有保守候选并在自定义 intersection 中精确复核距离，不在首个命中停止。溢出显式标为无效，不消费部分结果；CPU 参考可继续分批处理，未把该后备路径接入生产物理。

CUDA 使用 `cuGLGetDevices` 匹配当前 OpenGL 物理 GPU。资源每个隔离 fixture 注册一次，输入只读、输出为临时缓冲，显式 map/unmap；析构同步并释放上下文、注册资源、BVH 和模块。该原型在调用结束同步，尚未实现生产所需的异步 continuation、事件发布与资源代次接入。

RTX 可以承担 BVH 遍历，但本原型的 ray generation、精确距离复核、候选写入、力与物理仍使用常规计算资源。自定义 intersection 会回到 SM；因此不能将查询总时间都解释成 RT Core 时间。[NVIDIA 对自定义 primitive 的说明](https://forums.developer.nvidia.com/t/a-few-questions-about-bvh-traversal-engine-and-triangle-intersection-engine/233412)。CUDA/GL 互操作本身具有所有权与同步要求，不能假定与光影渲染免费重叠。[CUDA 互操作文档](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/graphics-interop.html)。

正确性验证通过 12,967,885 项检查，包含空池、1/63/64/65/255/256/257 边界、1千/1万/5万/65,535/65,536/131,072、稀疏、均匀、跨格/浮点边界、重合和运动输入，以及显式溢出。大规模全重合使用 32 个查询覆盖所有候选成员，避免生成平方规模结果；不能称为全体成员多帧物理验证。

三轮独立进程，每种负载先预热，再进行匹配 A/A 和 A/B，各 64 对交错样本。保留了静态和动态两组共六个进程的原始数据。以下为 65,536 成员动态组各轮 GPU p50 范围，单位 ms：

| 查询负载 | 完整 GL 网格 | CUDA 网格 | OptiX 重建 | OptiX 持续 refit |
|---|---:|---:|---:|---:|
| 小幅形变 | 0.842–0.846 | 0.683–0.686 | 0.852–0.859 | 0.561–0.563 |
| 大幅相对形变 | 1.268–1.276 | 1.146–1.154 | 0.872–0.876 | 9.030–9.104 |

不同 A/B 组合各自匹配采样，因此表中为近似范围，正式裁决读取原始配对记录。小幅运动中 GL/refit 的完成墙钟约为 0.934/0.657–0.663 ms；大幅形变 refit 约 9.1–9.25 ms。持续 refit 的 BVH 质量退化使其不合格；始终重建在小幅/静态负载也有稳定成本劣势。CUDA 在部分负载优于新 GL，但没有通过所有负载的稳定收益/尾部要求。

原生 GPU 事件范围包含 bounds、BVH build/update、计数、扫描和写入；完成墙钟另外覆盖 map/unmap、提交及等待。输入生成/上传、注册、编译和持久分配在 fixture 初始化阶段单独记录，故这些仍是隔离查询成绩，不是完整客户端成本。初始化原始日志及最终验证 JSON 另外记录首次执行、程序数量与内存。65,536 的稀疏 fixture 约有 BVH scratch 4.50 MiB、BVH output 3.06 MiB、其他自有 CUDA 2.50 MiB、GL 缓冲 14.50 MiB；不含驱动/OptiX 隐式内存。`cuMemGetInfo` 是整设备快照，不能全归因于本模块。

## 与现有生产更新链直接比较

额外生成 inline streaming 完整 GL 参考：去除旧 256/768 截断、按实际格子过滤哈希冲突重复、稳定身份裁决接触平局。无新增生产记录布局，也无需中间候选容量。它只是完整语义参考，未被当作最终优化。

`complete-grid-*` 是正式成本初筛范围：初始网格清空/构建、staged 准备、恢复、普通与 MODEL 更新、穹顶接触/应用/审计、解穿透、导航与反馈发布。固定输入的人工状态倒带位于计时外。此前未计入初始网格的 `complete-*` 与 pilot 也保留，不能与新范围混合。

三轮 A/A 与三轮 A/B 共六个独立进程，每格 64 对；覆盖 1千、1万、5万、65,536、131,072 的普通风暴、星落、螺旋、穹顶 gather/attack、尸体及真实恢复 fixture。验证稳定人口身份、有限数值、首帧 HP/死亡与材质归属、普通速度预算。新轨迹不要求重现旧前缀；完整伤害/事件、多帧接触与视觉质量仍未获资格。

65,536 成员完整链的三轮生产/参考 p50 范围：普通约 0.492–0.496 / 1.921–1.935 ms；穹顶 gather 约 1.341–1.366 / 2.183–2.212 ms；穹顶 attack 约 1.277–1.290 / 2.099–2.122 ms。该参考在主要负载稳定变慢，成本初筛不通过。尸体的微小变化也不能支持整体替换。合成生产链约 0.5 ms 与实机约 2 ms 的差别再次表明：离屏数值不能换算实机 FPS。

既有生产穹顶 gather 的 A/A 状态差异仍能复现，逐轮保存于 `production-aa-differences.txt`；它们没有被解释成新算法合法轨迹变化，也没有作为完整正确性通过的证据。

## Shader clock 定位

`clock-localization` 使用独立冻结源码副本，对分离、地形 body/page 查询、穹顶接触 main 与 update main 插桩。生产 compute 已达到 storage-block 限制，新增 SSBO 会链接失败，最终改用空闲 image unit 7。失败编译日志与各版源码均保留。

普通风暴的分离 work/call 平均接近 257，表明旧访问截断频繁触发。原始地形 fixture 没开启 emitter collision，因此最初 body/page 计数为零；在 `clock-terrain-v4` 显式开启后记录到 2,077,224 次地形调用，避免把“未执行”误判为“地形零成本”。clock tick 仅供局部定位，不转换 ms，不相加为 GPU 时间，也不参与 FPS 成绩。插桩引入 image 写入、嵌套计时及寄存器变化，不能据此声明某函数占整帧百分比。

## 验证状态与后续实机采集

最终普通构建、1,000 项 Java 测试、查询实驱回归、异步冻结/状态恢复实驱回归与 GPU 帧发布回归通过；另有 Python 邻居/验收工具测试。构建中既有 ThreadDeath 等警告未引入本轮变更。曾因并发 Gradle 进程共享输出导致无关类加载失败，随后单进程顺序构建与全部测试通过；该失败日志保留，不当作功能通过。

目前合格的生产路径只有原 OpenGL。新完整 GL 参考未过成本初筛，原生路径仅是查询原型；未实现生产 continuation、后端热切换、完整多帧攻击/接触事件双跑、光影竞争下的 native 更新/绘制链验收，也未将 CPU 参考后备接入生产。因此没有暴露实验后端开关，没有把任何候选标记为可替换。

Photon 与 iterationT 的实机基线和实际冻结输入仍需用户在固定场景采集。安装新诊断 JAR，先预热，在高可见量、零可见量、密集攻击各运行 `profile frames 30`；不足 1,000 帧时延长到 60–300 秒。另开一轮 `profile capture <name>`，等待导出完成再预热采集 FPS，不能重叠。保持两种分辨率分别独立窗口、固定包选项/限帧/VSync，三轮独立进程保存结果。

将来若有候选通过离屏完整正确性与收益门槛，才提供显式切换，进行受控客户端 A/A、A/B。还需核对其余六包、全部附件与深度、材质/姿态/六剑、聚散与平滑度、切包、F3+T、换维度及失败释放。当前没有候选能参加实机 B 组，不能把本轮诊断包的采集本身称为 FPS 优化。

Tensor Core、视频编解码器、插帧、Vulkan 重写和不可见降频均未引入。RT 重建策略、生产 continuation 与真实输入适配仍是后续研究空间，本轮结果不能证明所有 RT 算法都不可能获益。
