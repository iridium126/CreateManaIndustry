# 包裹与 MODEL 是否拆池：实测决策（2026-10-10）

结论：以降低渲染线程 CPU 负载为优先，当前不建议把包裹和 MODEL 各自复制成一套完整普通粒子池。包裹保留独立物理域，独立渲染提交域作为大规模或包裹-only 场景的候选；MODEL 保留共池模拟，优先考虑同代活动索引及其多查询复用，并保留密集扫描回退。

这次没有修改生产模拟或绘制路径。新增 MODEL 索引查询对照仅存在于验证程序，尚未部署活动索引。Hex 实例已经迁出通用池，参考回答中“Hex 实例仍经过通用池”的描述已过时。

## 当前版本重测

RTX 4070 Laptop GPU，NVIDIA 581.15，OpenGL 4.5 隐藏 GLFW context。每种模式三轮、每轮 120 样本；MODEL 每轮至少 30 次且 1 秒预热，包裹每种模式预热后连续测三轮。表格为三轮 P95 的中位数，单位 ms。CPU 是提交区间 wall time，不是 thread CPU，也不是 Minecraft 整帧；显式等待只在验证外壳中。

包裹夹具一半自由、一半带 rig 的链包裹，全部可见；Iris 模式包括 `select/reserve/import-only` 和 GBUFFER 分组准备。不是仅 `pool_import.comp` 单个 kernel，也不含真实光影绘制、光照采样、物理、传送带 CPU 掩码及状态边界。

| 包裹数 | 无光影融合路径 CPU / GPU | Iris 导入与主绘制准备 CPU / GPU |
| ---: | ---: | ---: |
| 10,000 | 0.0087 / 0.032768 | 0.0044 / 0.049152 |
| 65,536 | 0.0065 / 0.065536 | 0.0045 / 0.151552 |
| 131,072 | 0.0043 / 0.285696 | 0.0050 / 0.447488 |

MODEL 下面的原路径数据为全部 MODEL 可见、全部非 storm carrier 候选，包含完整当前 `ParticleComputeState` capture/restore。测试范围是阴影列表准备，不含最终模型顶点/片元、模拟、游戏世界或 Iris ShaderInstance.apply。

| 总存活数（全部 MODEL） | 含状态边界 CPU P95 | GPU P95 |
| ---: | ---: | ---: |
| 10,000 | 0.0279 | 0.028672 |
| 65,536 | 0.0233 | 0.028672 |

重测 CPU 高于部分 10 月 9 日历史结果；状态边界和系统调度均会影响数字，不能用旧版本值直接代表现状。CPU 随粒子数并不线性增加，主要为固定提交与边界工作；这些数据没有证明增加独立域会降低 CPU。

## MODEL 混合比例查询对照

增加 `-PmodelIndexProbe`：在同一份提交池中均匀分布 MODEL，其余为 ADDITIVE；当前数据位置、emitter、counter 和阴影规则相同。`full_pool` 使用生产 kernel；`prebuilt_index` 仅在验证工具里让 prepare/collect 读取预建同代 MODEL slot 索引。没有复制模拟记录，没有改变粒子身份或可见集合；全部输出 count、唯一性和 slot 身份逐项验证。

两种模式都包含相同 compute 状态边界，均使用非 carrier MODEL，waves/targets scratch 复用。查询结束后读回验证，在计时之外进行。索引构建、随压缩/新生更新、发布及溢出处理的成本**没有包含**；不能把此表当作完整活动索引实现或独立模拟池的净收益。

| 总存活 / MODEL 数 | 全池 GPU P95 | 索引 GPU P95 | 全池 CPU P95 | 索引 CPU P95 |
| ---: | ---: | ---: | ---: | ---: |
| 100,000 / 100 | 0.025600 | 0.020480 | 0.0336 | 0.0306 |
| 100,000 / 10,000 | 0.024576 | 0.020480 | 0.0268 | 0.0260 |
| 2,000,000 / 100 | 0.530432 | 0.020480 | 0.0278 | 0.0269 |
| 2,000,000 / 10,000 | 0.532480 | 0.020480 | 0.0273 | 0.0271 |
| 2,000,000 / 2,000,000 | 0.607232 | 0.638976 | 0.0277 | 0.0294 |

200 万存活记录、100 MODEL 时，查询端 GPU 时间少约 0.510 ms（96.1%），CPU 只少约 0.0009 ms。这不是渲染线程直接节省半毫秒；GPU 队列压力下降是否改善 CPU 尾延迟仍需实机证据。10 万档只节省约 0.004–0.005 ms，索引维护很容易抵消收益。全为 MODEL 时 GPU 慢约 5.2%，不应强制所有场景走索引；具体密度切换阈值未测定。

索引夹具存储为 `16 + 4 × MODEL数` 字节：100 个为 416 B，10,000 个为 40,016 B，200 万个为 8,000,016 B。生产需要考虑同代双 bank 或其他安全交接，不应把夹具字节数当成最终显存预算。

## 包裹的决定

### 保留独立物理域

当前物理本来就独立，不需要再造模拟池。10 月 9 日完整世界/支撑 solver 夹具中，65,536 个持续驱动 body 的 GPU P95 为约 7.96 ms，静止场景因睡眠降为约 0.256 ms；该优化的 CPU submit 大致 0.01–0.04 ms，未证明稳定 CPU 提交下降。搬动渲染记录不会减少 CCD、接触、支撑、移动结构、采集、网络或读回工作。不同夹具数据不能相加或当作同一实际场景的百分比。

### 暂不以 CPU 性能为由拆出完整渲染池

131,072 包裹的 Iris 导入与主绘制准备 CPU P95 只有 0.005 ms；GPU 0.447 ms 包含整个流水线，仍不是独立渲染域可以完全省下的时间。独立域依旧需要姿态转换、选取、主/阴影剔除、材质分组和间接命令。直接在每个顶点读取物理 body/history/chain/frame 也可能放大访问成本，未测得比一次转换更快。

更实际的候选是独立的紧凑渲染快照：复用现有 64 B 渲染 ABI、几何、材质列表、阴影及统一帧调度，只移除对普通 pool/counter/capacity 的依赖；不复制普通粒子的积分、死亡链、排序和大容量辅助 buffer。优先级为中等，需要包裹-only 与混合场景的完整 A/B 后再默认启用。

固定槽位的独立快照还可能按 free/chain/observer 版本复用未变化的记录，而当前普通池压缩/追加会改变包裹导入的 base；这比把格式转换搬到每个顶点更值得试验。但具体可跳过次数及净收益尚未测量，不能由已有物理发布去重的数据代替。

### 先消除可绕开的扫描

- 当帧 `keygen` 已使用 `pool_reserve` 保存的普通前缀，包裹不参与普通剔除/排序，不应再把它当作拆池的收益。
- 下一帧 update 使用上一代总 live count，仍到达包裹槽后按 PACKAGE material 返回；MODEL 阴影、hit、stormpos 等查询也仍扫描混合池。减少这些访问可先增加同代普通边界或 MODEL/storm 活动索引，不必移动模拟数据。
- 活动包裹容量优先级已有保护；独立渲染域可以解除容量耦合，但这是容量/可预测性收益，不能自动换算成 CPU 提速。

包裹 131,072 条 64 B 记录的双 bank 为 16 MiB。迁出通用池但仍保留原普通池容量，再分配自己的双 bank，不能宣称净省 16 MiB；必须减少旧容量/辅助数组或复用现有资源才能释放显存。

## MODEL 的决定

不完全拆模拟池。阴影、命中和 storm 查询的无关扫描已经在对照中暴露；共享活动索引足以绕开其他类型，不需要同步迁移稳定身份、HP/伤害、死亡动画、压缩、storm 网络和死亡后普通粒子生成。主绘制材质/透明分区与独立阴影列表也已存在，拆模拟池不会自动少 draw call 或免掉 MODEL 自身排序/着色。

若实施活动索引，应遵守：

1. 尽量在已有 update/emit/keygen 的适当提交阶段生成，避免另加一轮全池扫描只服务一个查询；keygen 索引必须在主视锥判定之前收集。
2. 按所消费的 pool generation 发布，不使用旧 slot；gridbuild 等前置消费者需要上一提交代索引，阴影/hit/stormpos 使用当前提交代。
3. 让多个 MODEL 查询共用，并为 storm 子集保留正确成员身份。主视锥列表不能代替完整活动索引。
4. 密集时回退连续扫描；溢出时保留安全扫描/回退。阈值和维护成本必须补测。
5. 独立列表按 MODEL 的安全峰值需求增长，而非机械跟随普通池预留容量；GPU 新出生与读回延迟不能导致漏实例。当前 200 万容量的 MODEL 阴影列表约 15.38 MiB，即使 MODEL 很少也分配；这可独立优化，无需拆模拟池。

## 实施优先级与决策门槛

| 项目 | 当前建议 | 数据所支持的收益 |
| --- | --- | --- |
| 包裹独立物理 | 维持 | 已有专用 kernel、稳定 ID、活动集与睡眠 |
| 包裹独立紧凑渲染提交 | 中等，先做完整 A/B | 减少导入耦合/包裹-only 通用流程；净 CPU 收益尚未测得 |
| MODEL 同代活动索引 | 大混合池下优先验证 | GPU 查询收益已测得；CPU 提交收益不明显；维护成本未计 |
| MODEL 完全独立模拟池 | 低，暂缓 | 现有实测没有证明必须通过拆池才能获得收益 |

后续 A/B 应覆盖包裹-only、MODEL-only、普通粒子-only 与混合比例，固定世界/相机/有效存活/可见集合，不拿预留 200 万容量冒充存活扫描量。记录整个准备/绘制阶段的 CPU wall/thread CPU P50/P95/P99、分配、上传、dispatch/draw、GPU 各 pass 与实际显存，包含索引维护和资源增长。只有净成本下降且 current-frame、容量/回退和视觉行为不退化才切换默认路径。实机验收继续由用户负责。
