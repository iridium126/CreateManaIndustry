# 风暴区域发射与金色上升粒子

`allay_gold` 为 additive GPU 粒子，约 80% 细光尘、20% 四角星芒。浅金亮心随寿命过渡到琥珀金，在方块顶面上方 0.02 格出生，缓慢上升并小幅盘旋。粒子无碰撞、子粒子或 shadow-map 投影，继续使用现有 additive 自绘、深度遮挡及后处理路径。后续风暴美术路线保持冻结，本轮不新增尾迹、光环或模型特效。

## 配置与空间密度

`config/createmanaindustry-client.toml`：

```toml
[allayStorm]
stormLodDistance = 4096
allayFeatherMaxSpawnPerSecond = 1000
allayGoldMaxSpawnPerSecond = 2000
```

羽毛配置范围为 0–2000，金色配置范围为 0–4000，表示 **R=32 时的基准总发射速率**，0 只停止相应类型的自动新增。共用发射函数只限制负值，最大值由各自配置校验。实际目标速率均为 `配置值 × (R/32)²`，大半径时不封顶于基准值，仍受共享池、类型容量与现有限流约束。金色默认配置在 R=16、32、最大半径约 45.25 时分别为 500、2000、4000 个/秒；配置为 4000 时分别为 1000、4000、8000 个/秒。已有配置不迁移或覆盖。

有效风暴的中心和半径来自已有完整模拟或远景中心时间线。不检查玩家距离、高度、天空或相机视锥，不主动加载区块。按出生点到中心的水平距离 d 设权重：

| 水平距离 | 权重 |
| --- | --- |
| d≤R | 1 |
| R<d<2R | (2R−d)/R |
| d≥2R | 0 |

2R 圆盘内均匀采样，按权重接受；圆盘平均权重 7/12，因此候选速率是目标速率的 12/7。完整有效区域下目标总量与 R² 成正比，单位面积密度不随 R 改变。羽毛的 Y 在 `[中心 Y−8, 中心 Y]` 均匀采样；金色粒子用候选 XZ 查最高有效上表面。未知覆盖、实心出生位置、缺少表面或容量不足时直接丢弃该候选，不重试、不将名额集中到剩余有效区域、不补发欠额。失败候选帧不提交额度和小数余量。

客户端 `allayStorm.stormLodDistance` 和服务端 `[allay_storm] stormLodMaxDistance` 新默认值均为 4096，可配置上限仍为 8192。客户端分组为 allayStorm；旧键不迁移。

## 上表面缓存与成本边界

`StormSurfaceGpu` 保留唯一一张 **256×256、每列 4 字节、256 KiB** 的 GPU 高度缓存。一个无符号整数区分未知、确认无表面、体素来源及补采来源；高度偏移编码覆盖 ±3000 万格。体素来源优先，同一来源保留风暴高度以下最高有效顶面。

原点按 16 格对齐，索引用世界坐标低位构成环形窗口。按 16×16 地块维护坐标、版本和脏标记：移动时保留重叠区域，只初始化新进入区域；高度上限变化重验活动区域。碰撞页表发布时携带变更 section，只有相关活动地块重新提取；无关页发布不触发重建。程序更换使缓存失效。

提取使用 `当前格占用 && 上方格已知为空气`，跨 section 顶面必须有已知上方页。AIR 和压缩 SOLID 页走快速路径；非活动、非脏地块跳过。只有空中空气页、不能确认顶面的列仍为未知。顶面上方 0.02 格须低于风暴高度。

缺失列在 GPU 生成位图，最多每 8 个成功提交帧附带到现有异步快照，复用 fence。稳定且无变化时不生成或读回位图。CPU 用有界位图去重，保存逐列扫描进度；世界 epoch、地块坐标、版本及高度上限不匹配的旧反馈丢弃，已完成列不会被延迟位图再次排队。体素接管后取消补采，未加载列等待现有区块或三维 cube 变化通知；确认无表面的列缓存空结果，直到相关变化才重试。

补采只在客户端世界所属线程读取已加载数据，不强制加载区块，不交给后台线程。优先复用未过期的 CPU 体素快照并跳过已知空气段；原版 WORLD_SURFACE 高度图只提供扫描起点，最终仍以与体素一致的 `getCollisionShape(...).isEmpty()` 判定。悦灵维度从高度上限按三维 cube 加载状态扫描，不用原版高度图替代 cube 覆盖。未知当前格或上方格不能确认表面。

原有碰撞采集优先，共享原有 **1 ms** 预算；金色每帧最多占剩余预算中的 **0.2 ms、256 列、4096 次格探测**，任一达到便保留进度让出。时间上限为软上限，单次世界查询可能超时。高度补丁带地块版本，按脏地块合批，与失效命令共用一个 16 KiB 暂存区，每帧合计不超过 **16 KiB**，并计入原有 128 KiB 上传预算。GPU 批量应用时再次校验版本且不能覆盖体素结果。

这里保留整格占用精度：半砖、台阶等取碰撞格顶面，液体及无碰撞装饰不另作表面。**不要求露天**，保留屋顶、洞穴、夹层及负高度行为。金色不增加完整体素的需求、驻留页或上传；缺少表面时只补采紧凑高度。出生仍是一次直接高度查询，没有逐粒子扫描或额外纹理采样。

两类自动发射合为一次 compute 调度。金色数量复用已有元数据空位与异步计数快照，不增加 fence 或逐粒子 CPU 更新。64 字节共享记录保存出生尺寸、盘旋方向、半径、角速度、上升速度和相位；普通更新负责运动及寿命，使用有界小角度旋转近似，跳过碰撞和羽毛地面 pass。只有金色粒子时不准备羽毛脚步、扰动、地面列表或主体绘制。

金色自动速率为 0 或风暴结束时，停止补采、反馈和高度上传。清空、换维度与退出世界统一撤销任务、计数、发射余量和缓存有效状态；缓冲可复用至引擎释放。旧零快照不能关闭新生成的金色粒子。光影重载失败保留旧程序集，成功发布后缓存按构建程序失效。不改变 64 字节粒子记录，不增加网络协议。

## 美术与生命周期

- 细光尘初始完整边长 0.025–0.06 格；四角星芒 0.08–0.16 格。
- 寿命 8–12 秒，上升速度 0.5–1.1 格/秒，盘旋半径 0.08–0.22 格。出生相位交错，产生柔和明暗变化；淡入后逐渐缩小、变暗。
- 金色关键帧为浅金 `(1,0.94,0.67)`、金黄 `(1,0.72,0.25)`、琥珀 `(0.9,0.38,0.06)`，形状在片元程序中生成，不扩展图集或增加纹理采样。
- 类型上限 65536，同时服从共享粒子池容量。风暴结束只停止新增，已有金色粒子自然寿终；羽毛的 60 秒寿命、三色比例、两档尺寸、运动、落地与光影路径保持。

## 用户实机验收清单

1. `/cmi particle emit allay_gold 300`：检查少量四角星芒混合细光尘，金色缓慢上升、盘旋、淡入淡出；手动命令不要求表面缓存。等待 12 秒确认全部消失，没有子粒子。
2. `/execute positioned ~ ~24 ~ run cmi particle allaystorm 65536`：在平地上观察羽毛与金色层次；比较 R 内平台、R 到 2R 的衰减，以及不同成长阶段。玩家进入房屋、改变高度和朝向不应关闭自动发射。
3. 使用屋顶、洞穴、夹层、半砖、台阶、负高度及区块边界场景；检查首次预热逐渐补齐最高有效地表，未加载列留空、不强制加载。破坏/放置顶面、卸载重载区块、移动风暴、改变高度，确认旧高度失效；悦灵维度额外检查垂直 cube 边界。
4. 羽毛基准速率设为 0，金色分别设为 0、2000、4000，确认无需羽毛预热也能补齐已加载地面，完整体素驻留不增加。恢复羽毛，检查两种来源交接；停止风暴后，金色应在各自 8–12 秒寿命内消失，已有羽毛仍按原寿命结束。
5. 无光影及 Photon v1.4 等八包分别检查颜色、Bloom、深度遮挡；切换/重载包、清空粒子、换维度和退出重进。金色保持 additive 自绘，无投影、重复绘制或纹理依赖。
6. 在羽毛 0、6 万、12 万及不同落地比例下，记录整帧、渲染线程和 GPU 分项耗时；对比关闭/开启金色。复杂地形、多人及光影观感由用户验收。
