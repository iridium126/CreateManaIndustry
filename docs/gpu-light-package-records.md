# GPU 自由包裹与轻量记录

2026-10-02。本说明取代旧版本的自由包裹交还、轻量 CPU 后备运动和接管后才移除实体的设计。自由包裹允许与 Create 原生运动存在轻微差异，库存和事务正确性优先。

## 创建、暂停和保存

玩家丢出、机器输出、锁链脱落和旧存档的 `PackageEntity` 在加入服务端世界时统一捕获。先执行 Create 的初始物品合法性检查，再保存物品、附加 NBT、稳定身份、UUID、尺寸、生命值、火焰及初始姿态；取消实体加入并删除临时对象。自由包裹从创建起就是 `PackageLightStore` 记录，不进入原生实体运动生命周期。GPU 配置关闭时也采用同一创建入口。

存档仍使用各维度 `data/cmi_light_packages.dat` 和全局 `cmi_gpu_packages.dat`。箱内物品及地址保留原 ItemStack/NBT 格式；环境步编号是可选字段，缺失状态字段时默认无燃烧、生命值 5、环境步 0。旧实体与现有记录身份和 UUID 相同时，记录优先，取消重复实体；复制身份的不同 UUID 重新分配身份。

没有就绪 GPU 时，记录保留最后确认状态并暂停。掉线、关闭 GPU、资源重建和历史缺失都撤销旧权威，优先尝试其他就绪客户端；没有候选则继续暂停。区块卸载移除活动目标及显示，保留存档记录，加载后重新登记。服务端不恢复自由实体、不计算轻量运动、不逐 tick 查询自由包裹碰撞。区域关闭和区块登记按最多 64 项的批次推进，并受 tick 工作预算约束；状态冻结立即生效，退役和重新接管逐批完成。

模拟暂停、权威迁移、消费库存和 GPU 槽位退役是不同操作。暂停不消费物品；消费必须命中当前精确记录且只能成功一次。

## GPU 运动、环境与确认

成对 CCD 使用双方预测状态和相对运动，任一方高速时双方都参与扫掠及质量加权修正。空间索引候选预算为每次查询 8192；耗尽、未知几何和不可用历史版本保留最后有效姿态，局部暂停并在后续步重试。GPU 暂停不会删除服务端记录。

水、火和熔岩是环境数据，不是交还条件。环境 pass 检查实际运动扫掠与流体高度，机器和传送门接触另有很小的边界容差。环境状态与计时随成功 GPU 步进推进：水中破包，首次着火点燃 100 tick，持续接触及每 20 tick 的燃烧损伤均为 0.15，熔岩保持至少 300 tick；生命值不高于 0.5 时终止，服务端以当前物品的抗伤害资格为准。

每个 GPU body 保存精确身份、lease、服务端索引及 revision、火焰和生命值，并保存最多 20 个未确认环境样本。每次有界捕获最多 16 个事件，每个事件携带最多 20 个样本；输出溢出保留原 journal，轮询重试。未确认样本满或预计销毁时保留终止状态，等待服务端确认。不能用覆盖队列来丢弃旧接触。

服务端每客户端每 tick 最多处理 256 个环境样本，校验当前记录、精确生命周期、单调步编号、服务器时间界限、世界坐标下的相关方块和伤害资格。重复样本跳过；消费记录后不再发送幸存 ACK，只发送退役控制，库存内容、生成蛋、销毁效果及音效只执行一次。幸存 ACK 使用服务器确认的生命值、火焰及资格，GPU 以该状态重放尚未确认的后缀，避免延迟 ACK 覆盖新接触或资格变化。

## 历史追赶

物理固定步长为 50ms。保留 20 tick / 1 秒不可变输入，每帧最多提交四步；输入和覆盖完整时，5–60 FPS 的时钟回归无累计丢步。只有对应 GPU 步进成功提交后才消费时间。

力源按 tick 捕获并登记后台结果，延迟结果不会覆盖其他历史输入。移动结构姿态按 tick 保存，几何 revision 必须匹配且姿态对只能使用一次。静态几何历史按版本过滤上传表；缺少版本的区域局部暂停，其他覆盖完整的包裹继续推进。超过历史窗口则撤销旧模拟，从服务端最新确认基线重新接管，不能伪造完成的历史步骤。

增量提交携带单调模拟步编号，服务端按实际有界步数计算位移预算，四步补算不再被单 tick 位移上限误拒绝。客户端步编号不延长服务器 lease。

## 机器事务与其他玩法

自由包裹通过环境接触上报进入现有漏斗过滤及 `tryInsert`、`DirectBeltInputBehaviour` 和传送带库存接口，移除了依赖实体运动的居中流程。拒绝或阻塞保留记录；部分接收先写回实际剩余 ItemStack；全部接收才原子消费记录并通知 GPU 退役。移动漏斗也直接处理记录与剩余量。

拾取、攻击、箭矢、爆炸、水火销毁和传送门直接操作记录。服务端重新检查当前身份、手持物、距离及视线；消费后另一个竞争操作无法再次获得同一物品。传送门迁移库存、身份及状态，不生成自由包裹实体。机器以后吐出的新包裹通过统一创建入口创建新记录。

兼容入口为 `PackageAuthorityManager.queryLight(ServerLevel, AABB)`、`consumeLight(ServerLevel, Entry)`。不向实体列表塞入代理对象。依赖 `PackageEntity` 对象的其他模组需要适配记录接口。

## 槽位、显示及锁链

body、pool、delta、journal 和观察槽位均可回收，内部跟踪精确生命周期。退役 admission、旧 flight、编码任务、读回引用以及 GPU fence 全部结束后才允许复用。重写身份及映射，清除姿态历史、承载、光照、残差、环境状态与检查点资格；缩减末尾空闲范围，不移动其他活动索引。旧 ACK、环境事件、检查点和旧提交代的交互结果均被拒绝。

记录显示仍由 `PackageLightClient` 和 GPU 观察流提供。GPU 暂停时显示最后确认状态；库存不进入显示下行。协议升级为 `gpu-packages-9`，旧自由权威客户端不能取得新版本权威，观察协议仍为 `gpu-package-observers-4`。

锁链没有 GPU 权威时继续由服务器 tick 推进进度和端口、连接及库存事务。服务端跳过 Create 的逐包裹 `updateBoxWorldPositions`；只在查询、端口交接、保存和脱落需要时计算逻辑位置，不计算摆动、渲染前后姿态、光照或剔除。GPU/CPU 迁移使用确认进度及事务序号，旧交接结果不重复执行。锁链脱落后生成的自由包裹立即转换为轻量记录。

当前验证、复现命令和真实游戏待验项目见 [GPU 包裹修复验收记录](gpu-package-repair-validation.md)。空间索引五轮质量合格比较选择 `linked`；生产只保留这一实现。两种落选实现仅存于独立 benchmark 参考目录，不参与 mod 构建。[索引原始数据及比较报告](benchmarks/package-index-2026-10-02/comparison.md)。
