# GPU 自由包裹与轻量记录

2026-10-06。本说明取代旧版本的自由包裹交还、轻量 CPU 后备运动和接管后才移除实体的设计。自由包裹允许与 Create 原生运动存在轻微差异，库存和事务正确性优先。

## 创建、暂停和保存

玩家丢出、机器输出、锁链脱落和旧存档的 `PackageEntity` 在加入服务端世界时统一捕获。先执行 Create 的初始物品合法性检查，再保存物品、附加 NBT、稳定身份、UUID、尺寸、生命值、火焰及初始姿态；取消实体加入并删除临时对象。服务端接管启用时，自由包裹从创建起就是 `PackageLightStore` 记录，不进入原生实体运动生命周期；服务端 `gpuPackages.authorityEnabled=false` 时，普通新包裹保留 Create 原生生命周期。

存档仍使用各维度 `data/cmi_light_packages.dat` 和全局 `cmi_gpu_packages.dat`。箱内物品及地址保留原 ItemStack/NBT 格式；环境步编号是可选字段，缺失状态字段时默认无燃烧、生命值 5、环境步 0。旧实体与现有记录身份和 UUID 相同时，记录优先，取消重复实体；复制身份的不同 UUID 重新分配身份。

没有就绪 GPU 时，记录保留最后确认状态并暂停。掉线、关闭客户端 GPU、资源重建和历史缺失都撤销旧权威，优先尝试其他就绪客户端；没有候选则继续暂停。区块卸载移除活动目标及显示，保留存档记录，加载后重新登记。接管启用期间，服务端不恢复自由实体、不计算轻量运动、不逐 tick 查询自由包裹碰撞。区域关闭和区块登记按最多 64 项的批次推进，并受 tick 工作预算约束；状态冻结立即生效，退役和重新接管逐批完成。

服务端关闭接管是唯一将轻量自由记录恢复为 `PackageEntity` 的路径。先撤销权威，再以最后确认的物品、姿态、速度、朝向、着地、生命值、火焰、插入延迟、传送门冷却、投掷者 UUID 及原附加数据恢复；实体成功登记后才删除记录和轻量显示。失败或 UUID 冲突保留记录并重试。只恢复已加载区块；其余记录保持存档，区块自然加载时恢复，不强制加载。启动关闭和在线关闭使用相同恢复入口。

在线重新启用接管时，已加载原生自由包裹分批转回轻量记录，成功保存后才删除实体，使用新的生命周期代次。锁链恢复确认进度和原生容器，不生成自由实体；重新启用后重新登记已有结构。自由与锁链迁移共享每维度每 tick 最多 64 项额度，并分别受现有时间预算约束。

客户端 `particles.packageCollisionMaxSections` 默认 256，范围 1–1024，各玩家独立设置，仅控制静态碰撞 atlas。重新进入世界时分配，修改配置不重建当前缓存；双份数据槽同时受显卡单个 SSBO 容量限制，诊断报告配置值与实际值。光照缓存上限保持独立。

模拟暂停、权威迁移、消费库存和 GPU 槽位退役是不同操作。暂停不消费物品；消费必须命中当前精确记录且只能成功一次。

创建/重新登记和已确认姿态更新会把脚部低于 `minBuildHeight-64` 的记录加入生命周期队列。服务端按最多 64 项及工作时间预算回收，不依赖水火或机器接触，也不扫描全量包裹或模拟运动。

## GPU 运动、环境与确认

成对 CCD 使用双方预测状态和相对运动，任一方高速时双方都参与扫掠及质量加权修正。高速轨迹在涉及的散列 cell 上记录实际正负方向位移，查询按局部位移扩展端点候选范围，覆盖交叉扫掠；散列别名只增加候选。空间索引候选预算为每次查询 8192；耗尽、未知几何和不可用历史版本保留最后有效姿态，局部暂停并在后续步重试。GPU 暂停不会删除服务端记录。

水、火和熔岩是环境数据，不是交还条件。环境 pass 检查实际运动扫掠与流体高度，机器和传送门接触另有很小的边界容差。环境状态与计时随成功 GPU 步进推进：水中破包，首次着火点燃 100 tick，持续接触及每 20 tick 的燃烧损伤均为 0.15，熔岩保持至少 300 tick；生命值不高于 0.5 时终止，服务端以当前物品的抗伤害资格为准。

每个 GPU body 保存精确身份、lease、服务端索引及 revision、火焰和生命值，并保存最多 20 个未确认环境记录。每次有界捕获最多 512 个事件，每个事件携带最多 20 个记录；输出溢出保留原 journal，轮询重试。未捕获的连续同种接触、相同接触点可合并，保存结束步号与持续步数，最多合并一个历史窗口；已经捕获的记录在 ACK 前保持不可变。燃烧中的机器/传送门接触不合并，避免改变库存与伤害顺序。未确认记录满或预计销毁时保留终止状态，等待服务端确认。

服务端环境消息独立于接管控制额度：每客户端每 tick 最多接收 4096 条、处理 32768 个记录，并受累计实际工作时间预算约束。预算耗尽确认已完成前缀，未完成后缀由 GPU journal 重试；重复记录不占样本额度。服务端校验精确生命周期、不重叠的单调步区间、服务器时间界限、历史步数与每轴 CCD 位移可达性、实际接触方块及伤害资格，移除了相对最新姿态固定 36 格的限制。消费记录只发送退役控制；库存及销毁效果只能执行一次。客户端每帧单独处理最多 512 个累计环境 ACK；幸存 ACK 使用服务器生命值、火焰及资格，并按持续步数逐步重放未确认后缀。

## 历史追赶

物理每个游戏步积分 50ms。历史按目标 tick rate 保留至少一秒；20 tick/s 时每帧最多补算四步，200 tick/s 时最多四十步。Minecraft 客户端以 20Hz 采集时，200 tick/s 将每个采集区间拆为十个有独立单调编号的游戏步。只有对应 GPU 步进成功提交后才消费输入；完整输入条件下的 5–60 FPS 回归无累计丢步。

力源按采集区间捕获并登记后台结果，延迟结果不会覆盖其他历史输入。移动结构姿态按区间保存，几何 revision 必须匹配且每对姿态只能使用一次；200 tick/s 将 20Hz 客户端观察插值为十个步进区间。静态几何历史按版本过滤上传表；缺少版本的区域局部暂停，其他覆盖完整的包裹继续推进。超过历史窗口则撤销旧模拟，从服务端最新确认基线重新接管，不能伪造完成的历史步骤。

增量提交携带单调模拟步编号，服务端按实际有界步数计算位移预算；补算不会被单步位移上限误拒绝。客户端步编号不延长服务器 lease。

自由与锁链各自提交时钟并使用各自插值。自由场景缺少力输入、静态历史或移动姿态 bank 时，只保留自由域的待处理时间；锁链进度及普通/Iris 绘制继续使用锁链时钟。

## 机器事务与其他玩法

自由包裹通过环境接触上报进入现有漏斗过滤及 `tryInsert`、`DirectBeltInputBehaviour` 和传送带库存接口，移除了依赖实体运动的居中流程。拒绝或阻塞保留记录；部分接收先写回实际剩余 ItemStack；全部接收才原子消费记录并通知 GPU 退役。移动漏斗也直接处理记录与剩余量。

拾取、攻击、箭矢、爆炸、水火销毁和传送门直接操作记录。服务端重新检查当前身份、手持物、距离及视线；消费后另一个竞争操作无法再次获得同一物品。传送门迁移库存、身份及状态，不生成自由包裹实体。机器以后吐出的新包裹通过统一创建入口创建新记录。

兼容入口为 `PackageAuthorityManager.queryLight(ServerLevel, AABB)`、`consumeLight(ServerLevel, Entry)`。不向实体列表塞入代理对象。依赖 `PackageEntity` 对象的其他模组需要适配记录接口。

## 槽位、显示及锁链

body、pool、delta、journal 和观察槽位均可回收，内部跟踪精确生命周期。退役 admission、旧 flight、编码任务、读回引用以及 GPU fence 全部结束后才允许复用。重写身份及映射，清除姿态历史、承载、光照、残差、环境状态与检查点资格；缩减末尾空闲范围，不移动其他活动索引。旧 ACK、环境事件、检查点和旧提交代的交互结果均被拒绝。

记录显示仍由 `PackageLightClient` 和 GPU 观察流提供。GPU 暂停时显示最后确认状态；库存不进入显示下行。当前权威协议为 `gpu-packages-13`，观察协议为 `gpu-package-observers-5`；新增环境持续步数字段要求服务端和权威客户端同时升级，旧自由权威客户端不能取得新版本权威。

锁链没有 GPU 权威时继续由服务器 tick 推进进度和端口、连接及库存事务。服务端跳过 Create 的逐包裹 `updateBoxWorldPositions`；只在查询、端口交接、保存和脱落需要时计算逻辑位置，不计算摆动、渲染前后姿态、光照或剔除。GPU/CPU 迁移使用确认进度及事务序号，旧交接结果不重复执行。锁链脱落后生成的自由包裹立即转换为轻量记录。

## 验证与边界

当前验证、原始证据索引和真实游戏待验项目见 [GPU 包裹测试与证据](gpu-package-repair-validation.md)。空间索引五轮质量合格比较选择 `linked`；生产只保留这一实现。两种落选实现仅存于独立 benchmark 参考目录，不参与 mod 构建。[索引原始数据及比较报告](benchmarks/package-index-2026-10-02/comparison.md)。

独立 OpenGL 回归、单元测试和权威微基准不代替真实游戏的 Mixin 启动、机器库存、多人网络、跨维度和完整 tick/帧性能验收。
