# GPU 自由包裹的轻量记录

2026-10-01：自由包裹完成可见接管后，不再保留服务端或客户端的 `PackageEntity`。以下描述取代旧文档中的 retained entity、native observer 和实体恢复路径；锁链上的原生数据成员不属于自由包裹实体。

## 接管与存档

服务端收到精确 `VISIBLE_READY` 后，先把物品及附加 NBT、稳定身份、UUID、尺寸和最近确认姿态写入 `PackageLightStore`，再 `discard()` 原实体。删除的原生跟踪通知继续正常发送；转移过程中的离开/取消配对回调不会撤销已确认 lease。记录不持有原实体，原实体的碰撞、阴影、LivingEntity tick 和原生运动跟踪随之退出。

存档文件为各维度 `data/cmi_light_packages.dat`；全局身份分配仍使用 `cmi_gpu_packages.dat`。最新姿态、生命值、火焰、插入等待和传送冷却独立保存，箱内物品及地址继续使用原生 ItemStack/NBT 格式。重载只注册记录，不生成实体。如果旧实体区块数据还包含同一身份和 UUID，记录优先，旧实体加入世界被取消，避免重复包裹。

记录有区域和区块索引。移动更新所在桶；区块卸载撤销 lease 和显示，保留存档记录，并移出活动列表。只有已加载区块的记录参与生命周期处理，休眠记录不执行碰撞或机器扫描。活动列表采用交换删除，不在每 tick 复制全世界实体映射。

## 玩法入口

| 入口 | 处理 |
| --- | --- |
| 右键拾取 | GPU 精确选择或轻量显示射线选择，服务端校验身份、距离、视线和当前手持物；消费记录并执行原生 `setItemInHand` 和拾取音效 |
| 漏斗收集 | 原生过滤及 `AbstractFunnelBlock.tryInsert`，插入成功消费记录 |
| 漏斗输出阻塞 | 原生 extractor 保持原流程，溢出范围查询补充轻量记录 |
| 移动漏斗 | 原生 contraption 过滤及 `ItemHandlerHelper.insertItemStacked` |
| 溜槽、置物台、传送带、弹射置物台 | 直接复用 `DirectBeltInputBehaviour` 或 belt 原生库存入口，轻量记录执行原生居中与插入等待；溜槽投掷成就保留 |
| 未接管的原生包裹接触 | 原生碰撞查询补入最新记录 AABB；轻量后备物理也查询原生包裹，不留下旧位置碰撞体 |
| 攻击、箭矢、爆炸、水、火、虚空 | 消费/更新记录；复用 PackageItem 内容解析、物品抗伤害判断、生成蛋、Create 销毁效果和声音 |
| 下界/末地传送门、末地折跃门 | 复用原生 portal forcer、相对位置/尺寸和无碰撞位置查询、平台及 gateway 出口计算，迁移或移动记录，设置 portal ticket；不调用实体生成 |

轻量兼容入口为 `PackageAuthorityManager.queryLight(ServerLevel, AABB)` 和 `consumeLight(ServerLevel, Entry)`。查询返回记录，不向 `List<Entity>` 塞入代理对象，也不把记录强转成 `PackageEntity`。任何额外模组若直接要求实体对象，需要使用记录接口适配；不会为兼容回调恢复实体。

居中或机器接收时撤销 GPU lease，并在记录上完成等待和库存交接。机器以后重新吐出的新包裹仍使用 Create 原生物品生成流程；这不恢复已经消费的记录。

## 显示、恢复与超时

接管客户端继续使用 GPU 自由物理和精确提交。观察客户端使用 `PackageLightObserverClient` 的既有自定义姿态流及 GPU 插值，经过隐藏/可见 admission 后才接管显示。批量上传 metadata，退役确认后释放身份预留；候选、物理索引仍不复用，旧确认不能操作新 lease。

`PackageLightClient` 的原生 Create 模型缓冲提供资源重建或未被 GPU 接管时的记录显示和输入。GPU 正常工作时，权威客户端备用姿态每 20 tick 更新，已建立观察流的客户端每 5 tick 更新；其余客户端按变化同步。延迟发送的最新姿态会保留到发送周期，停止运动也不会丢失最后一次更新。切换维度重新发送记录显示，避免重返维度时遗漏静止包裹。库存不进入显示或物理下行协议。

客户端协议升级为 `gpu-packages-8`，观察协议为 `gpu-package-observers-4`。双方必须使用支持轻量记录的版本；只有具备记录显示和输入通道的客户端才可成为权威。

100ms/两 tick 的物理积压和提交新鲜度检查保留。它约束的是输入和确认时效，不表示 GPU 内核执行了 100ms。逐帧一对移动结构姿态不能重复用来补算任意多步。光影 pipeline 更换先撤销旧资源，避免把光影编译停顿计入旧物理时钟。力源后台结果非阻塞轮询，未准备好时不消费时间或位姿。

超时、禁用、掉线或重载均撤销 GPU 所有权；已经转移的包裹留在记录中，由加载区块中的轻量 CPU 后备运动继续运行，等待重新接管。不会走 `restoreLight`、临时实体拾取或实体重新加入世界的路径。

## 验证范围

333 项包裹单元测试通过，覆盖持久化、区域/区块索引、巨大查询边界、持续火焰接触、身份退役/重接管、物理时钟与力源等待；字节码契约检查确认轻量存储/玩法/恢复不构造 PackageEntity、Flywheel shadow 不覆盖原实例，以及实际 Create/Minecraft 机器、碰撞和传送门方法签名。

真实 RTX 4070 Laptop/OpenGL 4.5 验证：`validatePackageGpu` 通过 21,488,659 项断言，`validatePackageObserverGpu` 通过 3,547,962 项断言。它们验证 GPU 状态、接管、退役和观察协议，不代替真实世界的 Mixin 启动和玩法验收，也不证明整帧性能提升比例。

游戏验收需检查：F3+B 与旧位置碰撞/阴影消失；双手拾取、攻击与物品守恒；各机器过滤、阻塞及库存接收；区块卸载/重进、保存重载、多人与跨维度；切换光影、暂停、低帧率、关闭 GPU 与掉线后的记录显示、后备运动及重新接管。
