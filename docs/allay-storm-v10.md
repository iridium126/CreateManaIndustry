# AllayStorm 协议10：对数星锥、独立调度与短回流

日期：2026-10-19。客户端与服务端必须同时替换核心协议10的JAR，拒绝协议9混连。真实客户端测试交给用户。

## 行为与配置迁移

Helix、Dome各自按风暴计时，首次机会在激活30秒后。每次机会独立抽签；失败、没有目标、成员或容量不足均消耗机会，不积压、不补发、不降级。两者可同时发动，并能同时针对同一玩家；同类型仍限制一个目标对应一个活动大招。目标分别轮换，三种攻击共用一次资格采集；大招机会到期时才轮换资源竞争顺序，避免600 tick间隔与逐tick轮换周期重合造成固定优先级。

| 配置 | 默认 | 范围 |
| --- | ---: | --- |
| `stormHelixInterval` | 30秒 | 5–600秒 |
| `stormHelixChance` | 0.5 | 0–1 |
| `stormDomeInterval` | 30秒 | 5–600秒 |
| `stormDomeChance` | 0.5 | 0–1 |

已有有效概率配置保留；旧配置中的0.2不会被强改为0.5。概率0可关闭对应攻击。`stormWaveInterval`、`stormHelixMemberFraction`、`stormHelixMaxMembers`退出配置规范且不再读取，请迁移至新的独立间隔。Helix固定4096名；16384存活门槛、对向两臂各2048名为固定规则。Dome原人数份额、768最低人数及人数上限保留。Starfall原0.5秒／50%／每玩家、64名／柱、64柱配置保留。大招仍共享4槽，所有攻击共享成员预留。

总人数门槛扣除死亡，不扣除预留；选员必须扣除死亡和预留。对向配对轮换，每臂精确2048名，不跨其他臂补员，不缩减阵容。发动后死亡不补员，总存活人数跌破16384不取消已发动攻击。

## Helix 几何与运动

长度64格，头尾参数u在0–1，轴向坐标32−64u；两条对数螺线各两圈、相差π。外包络E(u)=0.6×(32/0.6)^u，螺线中心半径0.4E；法平面二维高斯σ=0.2E，径向截断3σ，尾部外包络32格。

4096点模板离线生成，双股各2048点，使用确定性高斯候选及空间哈希拒绝相邻点。最终最小中心间距提高到1.4格（高于原计划1.2格）；无缩小模型或减少人数。模板49,160字节，装载时验证版本、有限值、包络、人数和间距；资源错误明确记录并拒绝发动。生成器：`python scripts/allaystorm/generate_helix_template.py`。生成过程不在游戏帧或服务端调度执行。

真实身体及翅膀姿态采样的保守包围半径约0.688格，双倍小于1.4格。Helix抬持剑手臂，取消旧Starfall通用的整身持剑倾斜，保持该姿态包络；不包括武器本身。运行时继续采用有界局部分离和碰撞，Helix分离半径同步为1.4格。模板保证参考队形间距；复杂障碍导致的压缩和视觉遮挡仍需用户实机观察。

星锥中点相对主体固定：生成时冻结玩家水平方向及主体半径，偏移为该半径＋50格，同主体高度，随主体平移而不跟随玩家平移或半径增长。集结朝向每5 tick更新，最大8度／秒，方向作为独立单位向量同步（不从远坐标控制点相减推导），客户端插值并连续维护侧向基；集结上限12格／秒，时长计入主体移动和外包络转动需求。

集结截止立即沿当前平滑朝向发射，不等待精确对准。冻结三维轴线和终止平面（冻结目标沿轴线向前12格），玩家后续移动不改变路线。起始0.15秒速度衔接；突刺速度仍用`stormHelixThrustSpeed`。成员参考进度越过终止平面即结束攻击，头先结束、尾后结束，不等待受阻成员恢复参考位置。继承实际位置与速度交给普通归队，较高的突刺速度经有限减速接入普通6格／秒上限，删除原分流、逆向和专用长回流。

仅攻击飞行阶段，成员模型中心距任意存活、非旁观玩家身体中心严格小于6格时持钻石剑并允许接触；达到6格即收剑。采用动态玩家容量和6格空间哈希，超过16人不会截断；小玩家数保持直接查询。提交后的标记统一驱动原生MODEL、阴影、Iris及接触读取。

## Starfall 0.5秒短回流与生命周期

逐成员触地、独立方向、h=0.0625r²、最大半径4格和不平整地形语义保留。每名成员展开完成立即收剑、关闭伤害，执行0.5秒短回流，约3格无碰撞路程；从末端位置、速度与切线逐渐转向当前主体。短回流期间继续占用成员，到时直接自动归队，不等待指定位置。最后一名成员完成短回流后释放柱槽。跨阶段剩余时间同帧传递，无触地确认者经无伤害短过渡退出。

新增双向`storm_attack_completed`：dimension、epoch、攻击ID和至多4096位的成员rank完成集合。指定反馈客户端通过现有异步GPU快照合并，每game tick至多发送一次每攻击完成集合，无成员位置上传。服务器验证活动身份、反馈权限和名单范围，幂等释放；已完成成员不再被旧波次退场逻辑清理，避免误释放新预留。开始快照后补发完成集合，支持观察者加入；无反馈则以同步的最晚攻击截止时间回收。

本地完成不等待网络；完成集合全部到齐立即回收客户端槽，旧攻击完成事件不能清理新槽。归队碰撞覆盖独立于攻击槽与预留，至抵达普通归队区域、死亡或新攻击接管时释放。GPU抵达确认由现有异步快照返回，确认后停止重复上报。新观察者未模拟的完成成员不创建离场覆盖；死亡成员也不创建该记录。身份清理移除离场记录。

GPU沿用SSBO 26–28／Iris TBO 14；模板替换原高斯缓存并压缩其空间，增加完成位图与归队确认位。双bank风暴域为7,484,800字节，协议9为8,037,760字节。普通MODEL和通用碰撞域语义保留。

## 自动验证与性能边界

执行完整test／check、服务端GameTest、Starfall／单柱／Dome／Helix、专用碰撞、MODEL群体／阴影／Iris与自由包裹回归。最终统计及JAR校验见文末交付记录。覆盖独立机会、16383／16384与每臂2047／2048边界、成员互斥、三维轴线、主体相对锚点、冻结路线、6格边界／第100名玩家、高槽位完成位图、不同帧率短回流与旧事件隔离。

压力工具`validateStormV10Load`是固定输入的131072成员、4个Helix、64柱、100名玩家；包含邻居网格构建和运动更新，不包含Minecraft世界采集、完整绘制、联网或真实游戏帧率。RTX4070 Laptop／NVIDIA581.15的一轮结果：模板首次装载CPU约30.59ms；工具全部设置约714.98ms（含着色器编译／驱动初始化等，不是游戏冷启动）；首次状态发布CPU约17.98ms；首轮网格＋运动GPU3.496ms、CPU提交约8.46ms；稳态120样本GPU P50／P95为2.683／3.438ms，CPU提交P95约0.142ms，玩家哈希构建CPU P95约0.0562ms。专用域约7.48MB，初始化上载1,644,424字节，静态输入稳态风暴上载0；实际攻击更新、完成反馈和移动玩家仍有上载。

64柱单独运动的本轮GPU P95约0.031ms；协议9历史约0.047–0.048ms。但主机负载及GPU时钟未固定，不能将差值精确归因为代码，亦无完整相同场景的旧版4大招基线。服务端规划冷样本及原始CSV／元数据保存在build日志和`build/benchmarks/storm-v10/`。初轮同工具P95约3.022ms、设置约6403.83ms，显示驱动缓存及主机负载差异，不宣称真实FPS提升。

## 用户实机验收

- 双端升级协议10；两种大招各自30秒／50%，可同时发动，人数不足不出现缩水Helix。
- 观察32格尾部的远景规模、头尖尾散、旋臂取员、集结随主体、三维追踪及截止立即发射；发射后绕行不改变路线。
- 验证任意玩家6格附近出剑、远离收剑；逐成员飞行结束后自动归队，无逆向回程或原点漂移。
- Starfall触地后逐成员展开，收剑后短转弯0.5秒，再自动归队；坡地、台阶、墙体和未知碰撞下不悬停、不伪造触地伤害。
- 最大主体＋4个大招＋64柱，检查动态地形、离场碰撞覆盖、自由包裹并行、真实Iris／Sable及多人帧率。
