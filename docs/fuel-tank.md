# FuelTank

熔盐燃料罐按面连接成任意形状，控制器选择顺序为 Y、X、Z。注册标识、容量配置、覆盖材料和窗口交互不变。当前存档与同步格式直接使用整数盆液量，不读取旧液面格式。

## 状态与职责

- `FuelTankGeometry` 保存不可变的成员、分盆、每层容量前缀及真实包围盒。序列化原点独立于包围盒最小角；解码直接使用已计算的分盆编号，不重新运行分水岭算法。
- `FuelTankFluidState` 保存 `long` 盆液量及总量。求解使用相对高度，整数余数确定分配；显示液面不能回写库存。存储/同步使用已受配置上限约束的整数数组。
- `FuelTankConnectivity` 在已加载区块内扫描，先快照所有源控制器，再提交合并或拆分。区块不完整时保留完整分布，控制器被删除时将剩余分布交给已加载成员，等待延迟拆分。
- `FuelTankBlockEntity` 统一库存与分布提交后的灯光、比较器和网络副作用。结构更新发送完整几何；常规液量更新合并为 8 tick 一次，少数盆变化使用稀疏更新。初始同步和存盘不消费增量标记。
- `FuelTankVisualState` 仅保存客户端动画和渲染缓存。服务端几何与液量不包含这些字段。
- `FuelTankContraptionBridge` 在装配体落地前快照当前移动库存，放置结束后恢复一次。纯平移保留各方块整数份额，旋转后重新沉降；失败方块只损失其份额。Create 适配不交换整块 NBT，也不以空的包围盒角点作为控制器。

合并/提交后的约束是：所有盆液量之和等于控制器库存；非控制器库存为空；每盆液量不超过自身容量。结构变化之外不重建几何。普通注排液不扫描全组方块；灯光按跨越的盆层刷新，比较器只在输出等级或成员变化时通知。

## 自动化验证

```powershell
.\gradlew.bat test --tests '*fueltank*' --offline --console=plain
.\gradlew.bat check --offline --console=plain
```

回归覆盖整数精度、随机注排与序列化、源控制器合并、拆除份额、异种/组件变体隔离、禁止未加载读取、控制器跨区块交接、初始/增量同步、客户端旧几何清除、平移/三轴旋转、移动中液量变化、失败放置及连接已有罐组。Create 合约测试核对实际依赖二进制中的 Mixin 注入位置与注册。

世界协调测试使用无图形的 Level 夹具，未加载的方块或方块实体读取会直接失败。它不替代真实 Create 启动和客户端画面验收。

## 局部基准

Java 21，同机独立 JVM，5 次构建预热，9 次测量取中位数。基线由修改前源码临时编译；注入负载为每次测量 1000 次 1 mB 调用。数值仅描述这次局部基准，不代表多人帧率。旧算法存在液量精度错误，相同调用负载不代表正确性等价。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 256 格平罐几何构建 | 1.05 ms / 485,056 B | 0.28 ms / 29,904 B |
| 4096 格平罐几何构建 | 6.94 ms / 7,857,976 B | 2.78 ms / 412,848 B |
| 4096 格平罐单次注入 | 327 ns / 24 B | 29 ns / 0 B |
| 4096 格平罐完整分布 NBT | 65,653 B | 49,256 B |
| 384 格、129 盆梳状结构构建 | 集合并发修改异常 | 1.34 ms / 1,002,304 B |

多盆邻接仅按实际边存储；另有 4095 格、超过 1000 个盆的规模回归。普通注排保持几何对象身份，稳定延迟 tick 不调用全组灯光扫描。

## 实机验收

仍需在真实游戏中验收：新玩家加入和区块重载后的液体显示；阶梯/倒 U 形罐组平移、旋转和接口转运；每格覆盖材料和窗口归属；部分落地失败；跨区块卸载与恢复；控制器区块不可见时的大罐渲染、灯光与比较器响应。自动化测试和局部基准不代签这些结果。
