# 天穹合围开发与离屏验收记录（2026-10-11）

状态：实现完成；Java、真实 OpenGL 与 Iris 回归和固定输入基准见下方记录。实机美术、地形、多人战斗和完整游戏帧性能由用户验收。

本文记录加入 HELIX 前的天穹交付快照；当前三种攻击调度和协议 4 见 [双螺旋贯击](gpu-helix-2026-10-11.md)。

## 攻击规则与配置

每次通过原有攻击资格检查后独立抽签，默认 20% 天穹、80% 星冠，允许连续选择同一种。两种攻击共用四个波次槽、每目标一个波次、攻击冷却和精确成员预留；途中死亡不补员。普通天穹没有终结版本，没有地面圆环、图案或新增粒子。

服务端 `allay_storm` 配置：

| 键 | 默认 | 范围 | 行为 |
| --- | ---: | ---: | --- |
| `stormDomeChance` | 0.20 | 0–1 | 每次机会选择天穹的概率 |
| `stormDomeMemberFraction` | 0.20 | 0–1 | 请求 `floor(alive × fraction)` 名成员 |
| `stormDomeMaxMembers` | 16384 | 768–24576 | 请求人数上限；只选择未预留的存活身份 |

可用名单少于 768 人或地形检查失败，本次改用星冠。顶冠占 `floor(actual / 10)` 人，其余均分六瓣，余量依次分配。半径为 `clamp(sqrt(actual) / 6, 8, 20)`。列表七组使用显式排他末尾索引，不能按星柱人数推导。

1. 从风暴集结，沿同一个最多六点 corridor 接近。集结时长根据风暴自身半径计算，给远侧成员飞行时间。中心每 0.5 秒同步，水平跟随最多 2 格/秒；中心高度出现不可行的大台阶时中止。
2. 六条 18° 宽经线弧带按 60° 分布，顶冠独立，半球内部空旷。经线使用余弦端点和自适应周期流动，扰动固定。朝向与顺逆时针顺序在服务端冻结。
3. 阵形成形后冻结中心。每瓣先预警 1.5 秒，收紧、持剑、轻微下沉；流动在该瓣预警起点冻结，预警没有伤害。
4. 单瓣收拢 `2 + 1.25 × radius / 6` 秒，围绕冠缘支点折向中心近地处，仅这个阶段允许真实成员接触伤害。其他瓣和顶冠无伤害。
5. 完成的瓣解除伤害，分散到半径至少 2 格的中央上升区域，再归队。中央上升目标不超过基底上方 28 格。最后一瓣预警前一秒，顶冠向上打开。

服务端在发射及锁定时逐格检查开放天空、覆盖区域的流体支持/深坑与出口；每瓣预警开始复查出口。六个瓣间候选出口逐段检查 0.6×1.8 玩家箱、实心地面支持、一步高度差和总高度差；不加载未知区块，拒绝流体支持、深坑和障碍。全部出口失效则中止，不读取 GPU 碰撞结果。客户端复用原有单个 48×32×48 碰撞 slice，锁定后固定在穹顶基底；动态障碍继续走碰撞/避障，超时退出伤害阶段。

锁定前原目标死亡、离线、换维度或失去资格会中止；锁定后固定区域继续运行，其他玩家进入也可被接触。现有客户端激活扫描还检查锁定天穹的固定圆柱区域及 120 格可视余量，避免风暴中心移走后旁观者失去阵形；继续使用原滞回和同一监听器。服务端按受击玩家、波次、成员分别去重，同一成员能分别命中 A/B。校验代、精确名单、当前收拢瓣、采样时间、冻结扇区/运动范围和服务器玩家位置历史；接受最多两秒延迟。伤害继续经原版 `player.hurt` 和带接触位置的来源执行，保留盾牌、护甲、吸收、图腾与无敌帧。

## 共享 GPU 域与协议

- 核心协议为 **3**，客户端和服务端同时升级。事件仍为 START / UPDATE / LOCK / ABORT，增加 STARFALL/DOME、显式阶段、组边界、中心、朝向/顺序和回退原因。开始/观察者补同步携带名单；目标/锁定更新不重发名单。补同步不再从 `landings[3]` 猜测是否锁定。
- `AllayStarfall.selectExact` 是共同名单入口；`AllayDome` 保存七组、逐瓣时序、出口检查和按玩家的接触去重规则。
- 保留 `StarfallGpuBuffers` 名称作为兼容代码入口，它现在承载两种攻击。复用 SSBO 26–28、Iris TBO 14、同代 MODEL/STORM 活动索引和已有模拟池。七组参数写入原来空闲的槽位，固定域双 bank 仍为 **3,158,912 B**；天穹没有增加 sampler 或固定 GPU buffer。
- 只有名单/事件变化时上传；每个 bank 的 roster 前缀为 524,352 B，参数区 4,992 B。两个 bank 暖后，静态天穹不上传归属/几何。中心增量最多每 0.5 秒刷新参数区；没有逐成员每帧几何上传。
- 持剑、姿态、主画面、阴影和接触共用阶段函数。主排序与独立阴影列表保持原路径。天穹完全绕开星冠 128 粒子 census 条件，圆环 GPU 入口也拒绝 DOME 类型。
- 成员身份阶段随模拟 bank 提交，失败准备不发布。无攻击时不分配首次活动域，也不读取攻击表。世界/资源/光影切换沿用现有域失效和清理入口。
- MODEL 的普通运动和风暴运动都保留 HP、回血、受击、尸体及永久生命周期。网络位置纠正在 servo 后执行，现在也遵守同一个速度上限。
- `/cmi particle stats` 分别显示星冠/天穹波次、人数、天穹当前预警/收拢瓣或归队阶段、回退原因及域占用/累计上传。

## 验证与基准

证据目录：[benchmarks/dome-2026-10-11](benchmarks/dome-2026-10-11)。测试摘要、完整压缩日志、汇总及逐次样本都保存在该目录。

GPU 几何 framebuffer 仅绘制生产运动函数产生的成员位置点，验证穹顶轮廓和空隙；不代表完整悦灵模型的实机画面：

历史图像：离屏成员位置几何（本地运行结果）

基准设备：RTX 4070 Laptop / NVIDIA 581.15 / OpenGL 4.5。覆盖 768、4096、8192、16384、24576 人，独立名单场景与 200 万普通粒子混合池；每档两种攻击，各三轮，每轮至少 40 次且一秒预热后 120 个样本。

这是固定输入离屏微基准。更新计入生产 gridbuild/update；主列表项计入 reset/keygen/prepare（不含完整 radix 排序）；阴影项计入独立 MODEL 阴影准备。各项读取固定输入，未串接成完整游戏帧。CPU 项为这些 GL 提交的 wall/thread CPU 和分配，不包括服务端选员、A*、出口检查、网络、完整 RenderSystem 边界及实际模型/光影包片元过绘。

汇总数值和复现命令见 [基准摘要](benchmarks/dome-2026-10-11/summary.md)、`validation-summary.txt` 与 CSV。Windows ThreadMXBean 单次分辨率不足，很多 thread CPU 样本显示零；这些零不能解释为实际无 CPU 工作。分配项也属于 harness 提交路径，不能直接作为整个游戏渲染线程的分配量。域累计上传含两个 bank 的预热与切换，不是每帧上传。

实机验收重点：第三/第一人称冠环及六瓣辨识度、宽度与模型密度、出口可见性、预警窗口、复杂地形/动态封路、旁观玩家进入、原目标离开、多人接触、无光影/Iris、持剑阴影、暂停/快速转向/重载。建议临时把 `stormDomeChance` 设为 1，结束验收恢复默认 0.20。
