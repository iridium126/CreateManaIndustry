# 悦灵羽毛 GPU 粒子

`allay_feather` 是有限寿命的 OPAQUE 粒子：空中使用项目 cherry_leaves 的重力、flutter 和离散旋转公式；落地后视觉铺叠，玩家脚步和实际模拟悦灵的向下碰撞可将其扬起。主体走悦灵实体的光影包合并路径，寿终白色光尘保持 additive 自绘。

## 生成与配置

`config/createmanaindustry-client.toml`：

```toml
[particles]
allayFeatherMaxSpawnPerSecond = 1000
```

范围 0–2000；0 只停止自动新增，已有羽毛仍会寿终。生成还服从 GPU 总容量和现有自动限流。

自动生成同时要求：有效风暴、本地玩家到中心的 XZ 距离 `d < 2R`、脚部 `Y < 中心 Y - 8`、眼部位置通过 Minecraft 的 `canSeeSky` 判定。生成速度为 `配置值 × clamp((2R-d)/R, 0, 1)`。

出生候选位于玩家水平 6–24 格、脚部上方 4–16 格的环带，最高为风暴中心下方 1 格。完整包围球须在主相机视锥外，每个名额最多尝试 8 次；不合适的位置直接跳过，不补发。此限制仅针对自动出生，已生成的羽毛可以正常飘入视野；手动预设命令便于单独验收。

羽毛寿命为 60 秒引擎模拟时间，落地和扬起不重置。风暴结束后停止新增，已存在的羽毛继续运动、铺叠及寿终。羽毛/白色光尘内部上限分别为 131072/65536，仍受共享池容量限制；同时大量寿终时光尘可因预算不足被减少。

## 美术与交互

- 使用 cherry_0..11 原始 3×3 图案，保留 alpha，仅将粉色色阶替换为悦灵蓝青色色阶。资源加载时直接复制原始像素，四周加一像素填充后按 5×5 区域打包；不放大、不裁剪。模型、剑、羽毛和 LOD2 统一使用紧凑图集对应的 UV。
- 两档完整边长为 0.10/0.15 格，等概率选择，与项目 cherry_leaves 一致。纹理像素放大不影响世界尺寸。
- 地面采用水平铺放、不同方位和毫米级高度差形成羽毛毯，不做羽毛之间的物理碰撞或实际堆高。
- 所有附近已同步、存活且非旁观模式的玩家，着地移动时产生半径 2 格的扰动；静止、离地和传送不产生脚步扰动。实际模拟 MODEL 粒子的向下碰撞同样产生半径 2 格的扰动。
- 每片扬起有 0.5 秒冷却；赋予向上、向外的初速度，下一帧恢复普通空中更新。寿命不重置。
- 寿终在原位置生成至多 12 个纯白 additive 光粒，寿命 0.8–1.6 秒，向上散开并逐渐缩小、变暗；不查询碰撞。

现有粒子使用两张独立图集，均由资源加载阶段合成：

| 图集 | 实际尺寸与排列 | 内容及过滤 |
| --- | --- | --- |
| `SPRITE` | 32×27，混合矩形 | 帧 0–11 为原始 3×3 樱花叶，12–14 为 8×8 暴击/魔法暴击/伤害图案，15–22 为 8×8 消散；最近邻，无 mipmap。 |
| `ALLAY` | 64×48，混合矩形 | 原始 32×32 悦灵、6 张 16×16 剑、12 张 3×3 羽毛；放大最近邻，缩小使用 mipmap，最高第 4 级。 |

`SPRITE` 的 11 张战斗图案先按 4 列放在左上 32×24 范围，最后一个 8×8 空位放入樱花叶 0–3，其余 8 张樱花叶沿 `y=24` 排列。帧编号与动画顺序保持原样。

`ALLAY` 的悦灵原点为 `(0,0)`；木、石、金、铁、钻石、下界合金剑原点依次为 `(32,0)`、`(48,0)`、`(32,16)`、`(48,16)`、`(0,32)`、`(16,32)`。羽毛使用右下区域，按 6 列×2 行排列；第 `n` 张的 3×3 内容原点为 `(33 + 5×(n%6), 33 + 5×floor(n/6))`，每张四周重复最边缘像素作为填充。所有可见内容均保留原始分辨率。

布局只在 `ParticleAtlasLayout` 定义一次，用于资源拷贝、模型及剑的静态 UV，以及编译期生成的 GLSL 矩形常量；不增加逐帧 UV 上传或纹理采样。羽毛与悦灵、剑和 LOD2 共用原有 albedo/gtexture 绑定。悦灵和剑按 16 像素边界排列，mipmap 保留 0–4 级，避免更高级别把不同材质混在一起；羽毛图案之间在高 mip 仍可能混合。

基础 RGBA8 像素存储：`SPRITE` 从 6144 B 降为 3456 B（减少 43.75%），`ALLAY` 从 32768 B 降为 12288 B（减少 62.5%）。包含 mip 链的逻辑像素总量从 49836 B 降为 19824 B，约减少 60.22%；这是纹理数据大小，不代表驱动按页分配后的实际显存释放量。樱花叶/羽毛的世界边长、剑的模型尺寸和碰撞行为均不随图集变化。

## 更新、资源及光影边界

普通更新负责空中运动和所有羽毛的寿命、压缩、寿终。地面羽毛走早期快路径，跳过重力、flutter、运动积分及扫掠碰撞。keygen 在视锥剔除前建立地面索引与计数；专用 pass 在 keygen 后只处理这些输出槽位，不重复计龄或移动。出生时缓存固定 flutter 方向和旋转系数。

羽毛候选元数据的两个 bank 放在既有空间网格 SSBO 的扩展区域。普通更新复用该绑定，其他 pass 使用对齐的区间视图，避免超过已有计算阶段 SSBO 数量限制。保持共享粒子 64 B、header 320 B；元数据 bank、列表和间接命令随同一 generation 提交。清空、换维度时撤销状态及羽毛地形租约，GPU 缓冲区域保留复用直到引擎释放。

碰撞复用风暴的 section-bit 图集、页表、采集预算和变更通知。出生区域提前请求；GPU 每 8 个提交帧按 section 去重提交有界需求，最多保留 4096 条。请求与计数使用原读回 fence，零超时轮询，不读回逐粒子位置。未知覆盖保持位置、继续计龄；地面支撑确认消失后恢复下落。

地面精确计数为零时，间接调度启动零个工作组。CPU 收到覆盖最近可能生成的零快照后停止相关专用提交；旧零快照不得关闭新生成的羽毛。只剩光尘时不再准备脚步、地面处理或主体绘制。扰动使用有界 GPU 空间场，不逐片遍历大量悦灵。

羽毛地面间接命令位于网格缓冲的候选区域，专用 pass 完成后（含失败退出）必须恢复引擎的 `GL_DISPATCH_INDIRECT_BUFFER`；即使地面工作组为零，也要恢复绑定。后续风暴波次接触检测在间接提交前显式绑定自己的命令缓冲，不能把网格头中的粒子索引当作工作组数量。运行时不为此新增 CPU 读回或逐粒子检查。

主体复用悦灵/LOD2 的实体材质上下文、TBO 输入及光影包片元程序；无光影或合并不可用时不透明自绘，绘制标记避免重复。羽毛不加入 shadow-map 投影列表；这与 `.refs/Iris` 的原版粒子提交行为一致。主绘制仍可接受场景阴影，并自然参与光影包自己的屏幕空间效果。

光影主绘制和投影入口均须等待 `ALLAY` 图集就绪，未加载的内部 ID `-1` 不得提交给 OpenGL 或 Iris 的 `RenderSystem` 纹理表。只存在远景 LOD 时，由 LOD 的首次可见准备加载图集。keygen 必须先 `glUseProgram` 再上传羽毛 uniform，避免把目标程序的 location 用于先前的程序。

## 自动验证与性能

```powershell
.\gradlew.bat --offline --no-configuration-cache -I scripts/particles/validation.init.gradle test --tests '*AllayFeather*'
.\gradlew.bat --offline --no-configuration-cache -I scripts/particles/validation.init.gradle validateAllayFeatherGpu -PallayFeatherBenchmark=true
.\gradlew.bat --offline --no-configuration-cache -I scripts/particles/validation.init.gradle validateParticleProgramsGpu validateModelMaterialGpu validateModelShadowIrisGpu validateStormLodGpu validateModelPopulationGpu
```

行为验证使用生产 update/keygen/ground/emit 着色器、真实碰撞页表和 GPU 顶点读回，涵盖尺寸、旋转、图集外区域、地面状态、实际悦灵触地、玩家半径边界、冷却、支撑移除、未知覆盖、单次消散、容量及请求上限；另覆盖手动命令到寿终的完整生命周期、6 万 MODEL 同时触地和生产所有者的首次分配/发布/绘制。交接探针给网格头放入安全的 `2×3×4` 哨兵，并确认羽毛 pass 之后的风暴式调度仍只执行引擎的 `1×1×1` 命令。CPU 测试覆盖速率、高度严格边界、旧零快照、光尘尾期门控、玩家快照前缀兼容以及不进入模型投影入口。八包合并验证还通过真实变换后的顶点程序、双 bank TBO 和间接绘制读回 CMI 的顶点输出，检查羽毛未误读 MODEL 哨兵；不等同于实机观感验收。

基准输出为 `build/benchmarks/allay-feather/kernels.csv`。RTX 4070 Laptop GPU 的离屏探针中，6 万片的普通更新 + keygen + 地面处理约 0.38–0.51 ms，12 万片约 0.60–0.85 ms，随落地比例变化。这里不包含羽毛光栅绘制、完整风暴、光影包、世界采集及实际客户端帧率；CSV 的 CPU 时间仅为探针提交时间。零数量基准为验证零工作组而强制提交准备阶段，实际引擎可靠空闲后直接跳过这些提交。

## 用户客户端验收

在单独的测试场景中执行：

1. 开阔地面先运行 `/cmi particle emit allay_feather 300`，检查蓝青色樱花叶图案、两档大小、落地不消失和水平铺放。来回走过观察 2 格范围扬起，静止与跳跃时检查脚步条件。
2. 羽毛已铺地时运行 `/cmi particle emit allay_fly 32`，观察其中向下运动、实际触地的模型是否扬起周围羽毛；对比远于 2 格的羽毛。
3. 运行 `/execute positioned ~ ~24 ~ run cmi particle allaystorm 2048`，在低于中心 8 格的露天位置观察周围羽毛雨；移动到 R、1.5R、2R 附近对比密度，进入不透光屋顶下检查停止新增。R 使用该风暴当前状态值。
4. 运行 `/cmi particle allaystorm stop`，检查已有羽毛继续存在；等待各自满 60 秒，观察原地白色上升光尘，确认穿过方块时不碰撞。
5. 分别测试无光影、光影包合并、切换/重载光影包，检查材质、遮挡、地面图案与无重复绘制；羽毛不会向 shadow map 投影。密集铺地与多人经过时由用户观察闪烁和帧率。
6. 将客户端最大速率改为 0、1000、2000，检查停止新增及强度变化。最后使用 `/cmi particle clear` 检查即时清理，再次生成确认无旧状态；该命令会清理当前 GPU 粒子测试内容。

客户端实机验收由用户执行；自动探针不代替上述视觉、复杂地形和多人帧率验收。
